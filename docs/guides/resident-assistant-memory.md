# 助手的权限、记忆与知识来源

本文对应个人内置助手。实施与本机验证状态见[实施记录](../process/resident-assistant-native-rollout-2026-11-05.md)，设计依据见[最终计划](../architecture/resident-assistant-permissions-memory-final-plan-2026-11-05.md)。

## 自主工作的范围

主助手可以直接读取文件、列目录、查找名称和搜索正文。它可以在当前会话接通已经启用、认证完成的 Source，并调用 Host 配置允许的只读能力。连接成功不意味着取得写权限；MCP 服务声称 `readOnlyHint` 或工具名称看似只读，都不能替代 Host 的权限配置。

执行、编辑工作文件与外部写入交给普通任务会话。任务沿用实际模型、权限上限和所选资料，不因一条记忆扩大授权。未启用或未认证的来源仍走原有配置流程。主助手的读取能力不包括直接读取助手数据库、其他会话原始控制文件或凭证库。

任务有明确的原始输入和回执。已经提交但没有送到模型的工作，可在核实后继续使用原输入；已保存且可核验的材料续接包可在重启后自动继续。来源撤回会阻止旧推理结果进入交付。存在未知写入效果、配置变化或新的用户工作时，恢复保留原证据并报告原因，不自动重复执行。

## 两个独立开关

工作区设置中的记忆学习与记忆使用分开保存：

| 设置 | 行为 |
| --- | --- |
| 自动学习 | 根据直接用户来源或经 Runtime 核验的观察保存有依据的低风险长期信息；常规准入不逐条要求确认 |
| 仅显式请求 | 新增与修订由当前直接用户的明确请求触发 |
| 暂停学习 | 保留已保存资料和待处理来源，停止后台学习调用 |
| 关闭记忆使用 | 停止长期记忆与协作摘要的自动使用；学习设置独立，不等于删除资料 |

置信度不足的观察保留为候选，不能作为已确认的用户事实。助手可在取得新证据后修订评估。长期信息有版本、来源、范围、条件与生命周期；纠正或退出后，旧依赖停止进入后续模型请求。永久遗忘要求当前用户明确提出；切换话题只退出当前工作上下文。

后台提炼使用同一个主助手 Session 和 Runtime，每次只处理一个有界来源片段。当前限制为每片最多 6000 字符、每次最多 6 次模型准备、16 次工具准备、30 秒；按 UTC 日最多 8 次维护运行、48 次模型准备和 128 次工具准备。计数和检查点持久保存，失败有退避，前台消息和工作集切换优先。这里统计准入次数，不代表模型账单次数。

## 资料分别由谁保存

```text
<workspace>/
  assistant/
    session-location.json
    sessions/<assistant-id>/       # 主助手会话、附件与 SDK 日志
    memory/memory.db               # 原子记忆、检索投影、情节引用、维护和项目请求回执
    context.db                    # 当前工作上下文、主题与恢复引用
    delegations.db                # 委派回执、通知与成果用途
    migrations/layout-v1/         # 可恢复的旧布局迁移证据
  sessions/<worker-id>/            # 普通任务会话
  projects/<project-slug>/
    MEMORY.md                     # 项目事实的可写权威
```

L0 是本地原始对话；L1 是有来源的原子信息；L2 是值得复用的目标、条件、决策与原子引用；L3 是有效协作偏好的有界摘要。L3 不复制 `preferences.json` 或另造人格权威，L2 不接管任务状态。修订、遗忘与来源失效会影响派生召回。

项目决定、约定和经验留在项目自己的 `MEMORY.md`。`project_memory_append` 校验来源原文、项目归属、学习策略、请求身份及当前文件 hash，然后追加；重试可恢复原回执。请求回执只保存身份和指纹，不把项目正文复制进全局数据库。`project_memory_search` 和 `project_memory_read` 返回原文件 URI、读取时间、位置和版本，可回查提示词摘要省略的中段。普通原生 Write/Edit 不能覆盖这个产品文件；外部人工编辑后，活动推理会检查其快照是否仍有效。

不对每个项目文件全量做全局记忆。项目工作依靠现有 Project 入口、实际相关文件和按需回查。旧数据迁移保留同一助手身份，源副本只作恢复材料，不同时作为第二份可写记忆。

## 使用个人知识库

继续使用已有 MCP、API 或本地 Source，无须引入第二套凭证、连接器或团队权限系统。可在原 Source 配置中添加用途与项目关联：

```json
{
  "knowledge": {
    "purpose": "knowledge",
    "projectIds": ["已有项目 ID"]
  }
}
```

这段元数据说明相关性，不授予权限。助手通过来源发现取得连接状态，按实际工具 schema 使用搜索和读取能力；MCP resource 使用 `source_read_resource` 回查 URI，本地资料使用有界文件读取。不同知识库的工具参数各不相同，不假定存在通用搜索接口。

读取结果区分来源配置版本与本次返回内容的 hash，并保留读取时间。Project 和 MCP resource 可提供原文 URI；其他工具以服务实际返回的文档链接和位置为准，不能用连接名称冒充原文出处。结果 hash 只说明本次取得了什么，远端是否更新需要重新读取。来源撤权或配置变化会使旧依赖退出，读取失败与没有匹配结果分别报告。

## 工作总览与交付物

“当前”“交付物”“历史”分别按需分页，历史支持搜索，任务详情才加载执行尝试与过程产物。Worker 明确声明最终、支持和过程文件；助手审阅真实结果并完成对应投递后，才形成交付物。脚本也可能是用户要求的最终成果，不能仅按扩展名排除。

可在成果清单中将已审阅的文件移出交付物，或恢复展示。这个操作绑定当前清单及文件版本，保留原文件与历史证据，不表示用户接受，也不能把过程材料提升为交付物。

开发验证入口为 `bun run verify:assistant-rollout --output-dir=.cache/verification/<新目录>`。各工作流保存 manifest、日志、数据库或界面证据。验证使用隔离配置与本地确定性模型服务，不代表付费模型质量、真实 Work 数据迁移或安装包发布已经完成。
