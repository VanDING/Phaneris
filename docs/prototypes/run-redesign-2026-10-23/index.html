这版设计的取舍

用同一套视觉语言，让三个视图分别回答一个问题。

各视图直接呈现内容，不另设重复的页面标题和引导说明。运行状态统一放在 Run 顶栏，请求选择放在请求历史卡片内。Decision 统计只读，筛选集中在事项卡片的两个下拉框；导出不纳入本轮。

Overview
运行结果与异常先出现；诊断摘要、环境和计量口径均以常驻卡片呈现，活动形态链接至 Trajectory。
Context
请求历史保持原样；下方使用与参考截图一致的分类折叠列表，同时显示条目数、token、占比和变化，展开后就地阅读。
Decision
沿用 Overview 的卡片结构：结果分布、功能统计和事项列表。处理证据在记录下方展开。

吸收 DSH-CONTEXT 的部分

  • 分类颜色贯穿组成、趋势、浏览器，颜色不承担运行状态。
  • 请求级趋势与具体内容联动；累计与增量切换。
  • 总量与组成分开说明，保留估算、未知、历史缺口。
  • 参考附件的分类折叠列表与变化徽标，保留工具参数、状态与结果原文。

原型与现有能力的边界

所有数字与内容都是固定示例，不读取真实会话。工具定义、工具结果、技能注入拆分为独立类别，以及请求差异和上下文事件联动，是拟议交互，实施前需要补齐或核实数据投影。

分类 token 为估算；供应商 input token 是独立计量，不能把分类估算当作官方精确分项。费用保留未知请求数。决策事项数与模型请求数分开，不用建议推断实际生效，也不把历史缺失视为零。

Decision 使用现有支持的结果、功能筛选，未放入会在分页中漏项的本地全文搜索。Context 和 Decision 在窄面板均就地展开，保持宽窄屏的阅读逻辑一致。

评审范围

Overview、Context、Decision。Trajectory 与 Map 保留导航位置，本次不重设计。浅色、深色、宽屏、窄面板和缺失数据状态均可在顶部切换。
