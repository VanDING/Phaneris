## 设计重点

| 视图 | 第一层问题 | 阅读路径 |
| --- | --- | --- |
| Overview | 运行情况如何，哪里需要关注？ | 状态与计量 → 异常 → 上下文演变与占用 → 输出表现与决策影响 → 常驻诊断、活动、环境卡片 |
| Context | 模型在某次请求中看到了什么？ | 请求选择 → 历史趋势（保持第一版） → 组成条与完整分类列表 → 就地展开条目和原文 |
| Decision | 这次判断实际改变了什么？ | 处理结果（含事项、请求和费用）、功能分布卡片 → 事项列表 → 就地展开处理证据与诊断 |

原有五个 Run 导航入口保持位置。Trajectory 与 Map 本轮不重设计。活动形态与文字链接均跳转至 Trajectory，原型使用仓库已有界面截图承接，明确说明截图是另一条历史示例会话，不与当前演示数字关联；Map 保留禁用说明。

第二版按用户反馈调整：Overview 的诊断和环境改为与其他区域一致的常驻卡片；Context 下方按照用户附件改为 DSH-CONTEXT 式分类折叠列表，呈现条目数、token、占比与相对前次变化；Decision 移除独立的侧栏主从样式，与 Overview 共用卡片、表头、数字和分隔线，处理证据在记录下方展开。

按后续反馈，Decision 移除顶部重复的四项摘要；事项数、辅助请求数、实际处理分布、费用及未知费用数量统一放在“处理结果”卡片中。

第三版进一步移除所有视图顶部重复的页面标题和说明，运行状态统一放在 Run 顶栏，请求选择放入 Context 请求历史卡片。Decision 的结果图例、功能统计改为只读，功能和处理结果筛选集中在事项卡片的两个下拉框；点击同一事项行即可展开或收起，不再另设收起、复制等重复按钮。导出入口与演示逻辑已移除，导出留待用户另开任务处理。

Overview 顶部独立的决策超时提醒同步移除，异常说明和查看入口仅保留在“决策影响”卡片内，避免重复提示。

Context 分类可分别展开，条目再展开后可切换阅读、原文、变化；请求切换保留展开状态。Decision 宽屏以表格展示事项，窄面板按行重排，详情均就地展开，避免宽窄屏使用两套阅读路径。顶部保留浅色、深色、600px 面板及不同数据状态切换。

## 示例数据与实施边界

全部内容都是设计 fixture。未调用真实会话、模型服务或项目 RPC；示例源码节选明确标注为示例。字体使用本地系统字体，不依赖 CDN。只新增本目录，没有修改产品组件、主题引擎或全局 DESIGN.md。

| 交互 / 信息 | 现状与实施时需要核实的事项 |
| --- | --- |
| 请求级上下文、前后请求、原文 | 现有 `TrajectoryContextView` / `trajectory-context.ts` 已具备基本投影，可以调整展示层 |
| 工具定义、技能注入、工具结果独立分类 | 现有投影只有 system / user / assistant / tools / attachments / injected；需要核实并补齐精确来源，不能只换标签 |
| 类别 token 与供应商 input | 现有类别基于内容字符估算，供应商总量是另一种计量；此原型保持两种口径的说明，不承诺精确相加 |
| 当前容量比例 | 示例中固定为 86,400 / 128,000。产品必须使用实际模型窗口与捕获的请求总量，未知时不显示精确占比 |
| 累计组成与净变化 | 请求总量差异可由现有请求顺序推导；详细分类、压缩与条目变化需更完整快照 |
| 上下文事件、引入请求、逐项变化 | 拟议交互，需要稳定身份和可靠事件来源，不用时间接近猜测关联 |
| Context 内容浏览 | 第二版移除第一版的类别筛选与列表/阅读器结构，改为完整分类列表、逐层展开。真实内容分页时仍需明确覆盖范围 |
| 决策事项 / 请求数、模型建议 / 实际处理 | 保留现有决策语义，不能互相替代 |
| 决策功能与结果筛选 | 对应现有查询能力。没有添加会因服务端分页而漏项的本地全文搜索 |
| 决策轮次关联 | 展示不透明 `turnId`，不将其冒充用户轮次序号 |
| TTFT 与输出速率 | 现有性能投影可提供，速率按有效输出 tokens / 有效生成时长加权；无首输出时刻时留空 |
| 费用 | 已知金额旁保留未知请求数；辅助费用包含在会话总额内，不能再次相加 |
| 运行诊断与活动形态 | 常驻卡片展示，活动形态链接至保留的 Trajectory 参考入口。实际可靠性、任务预算、重复信号必须沿用现有记录契约 |
| 历史与异常状态 | 历史仅展示保留的调用信息，不推断实际影响；加载失败不显示为零 |

当前原型没有实时刷新、真实分页、修改上下文或控制会话。运行中状态用于说明统计截止范围。尚未采集的历史数据不因界面重设计而恢复。

## 可重复评审

1. Overview 点击趋势中的 #15，再点击“查看此请求”，确认进入 Context 并保留请求位置。
2. Context 切换“净变化”，查看 #15 的压缩下降；再选择最新请求。
3. 在完整分类列表展开一个或多个类别，再展开具体条目，切换“阅读 / 原文 / 变化”；切换请求后确认展开状态保留。
4. Decision 分别选择回退、未确认、功能与结果的交叉筛选，检查记录和实际处理。
5. 确认 Decision 统计卡片没有按钮；通过事项卡片的两个下拉框筛选，点击同一记录展开与收起。
6. 切换“面板”，就地展开上下文条目或决策记录，再收起；切换深色。
7. 切换历史、空会话、加载失败、运行中状态，检查缺口与恢复入口。
8. 打开“设计说明”；点击 Overview 活动形态进入 Trajectory；键盘左右键切换可用标签。
