# AI 设置重新规划

状态：已按用户确认的“连接 → 会话 → 高级”结构实施，并通过 20 项浏览器验收。2026-10-05。用户随后授权直接替换内置 Default，本轮已同步主题定义和默认样式。

## 当前问题

截图里的混乱来自职责和层级，而不是必须删除设置：

- 会话默认值、工作区例外、连接管理连续出现，用户需要自己理解谁覆盖谁。完全继承的工作区仍重复展示连接、模型和思考强度。
- “Default” 同时出现在主题和连接中；连接的默认标记没有说明默认用于什么。
- “Image input” 容易被理解成图像生成。连接身份显示成 “Phaneris Backend”，没有说明这是 ChatGPT 订阅登录。
- 图像生成在没有可用连接时仍显示 Automatic 和配置表单，再用长警告解释不可用。页面只告诉用户失败，没有提供准确的下一步。
- Context、Performance、Guarded、Decision configuration、Decision features 都是一级大段。Guarded 依赖决策辅助，但显示在它之前，权限页又有同一入口。
- “图像理解”标签由连接中任意模型的能力推断，容易把整个连接误写成所有模型都支持看图。

## 已实现的结构

继续使用与其他设置页一致的单页滚动结构，不增加 AI 内部分页、标签页或左侧二级导航。保留现有 SettingsSection / SettingsRow / SettingsMenuSelectRow；标签在左、操作在右。

| 页面顺序 | 默认可见内容 | 按需展开内容 |
| --- | --- | --- |
| 连接 | 名称、登录方式、可用状态、能力摘要、添加连接 | 重命名、验证、编辑、删除等现有菜单；端点与模型细节在编辑中 |
| 会话 | 连接、模型、思考强度、上下文策略 | 选项说明随当前选择显示；详细解释放选项菜单或帮助 |
| 高级 | 依次显示“图像生成”“决策辅助”“缓存与运行优化”三条折叠摘要 | 三项各自独立展开；图像设置、决策服务和运行优化分别在对应项内 |

先管理可用连接，再决定会话使用哪个连接与模型，最后按需配置高级功能。连接是共享资源，统一管理一次；图像生成在高级中保留独立配置，因为它使用另一条调用链。

“高级”是常驻分区标题，本身不增加一层折叠。其下三项默认折叠，摘要一直可见。每项独立保存展开状态，可以同时展开多项；打开或关闭一项不影响另外两项。展开后直接显示配置，避免再套一个重复的“配置”折叠。

| 高级中的顺序 | 折叠时的摘要 | 展开后的内容 |
| --- | --- | --- |
| 图像生成 | 尚未配置，或当前连接与模型；选定账号失效时显示状态 | 兼容连接引导，或连接与模型选择；必要的修复操作 |
| 决策辅助 | 未启用，或当前服务与就绪状态；需要处理的 Guarded 依赖 | 启用开关、服务、凭据来源、模型和相关功能 |
| 缓存与运行优化 | 使用默认设置，或已启用的优化项 | 缓存时间、缓存预热、RTK 等运行设置 |

三个折叠入口使用一致的标准设置行：左侧名称，右侧状态与展开图标；展开内容的选择器、开关和操作仍统一在右侧。定位到某项配置时只展开目标项，例如权限页进入 Guarded 配置时只展开“决策辅助”。

### 连接

每条连接最多两行常驻信息：首行名称与身份，例如 `ChatGPT Plus · 订阅登录`；次行显示实际支持的用途和状态。地址、后台实现名不占常驻第三行。

能力使用“会话 / 图像理解 / 图像生成”。图像理解按选定模型给出准确说明；连接内只部分模型支持时标注“部分模型支持图像理解”，未知能力不猜测。图像生成标签描述当前 Phaneris 集成的支持范围，认证就绪状态另外表达，不能把“供应商支持”当成“账号已可用”。

把连接的 `Default` 改成用途明确的 `用于默认会话`。如果另一连接用于图像生成，也显示对应用途，避免默认连接看起来管所有功能。鉴权失效、重复账号、验证失败的信息仍需可见。

### 会话与工作区

会话区标题使用“会话”，而不是把所有项目叫“新会话默认值”。连接、模型、思考强度影响新会话；上下文策略影响继续会话时的行为，行说明分别明确作用范围。

会话区下只保留一条标准导航行：`工作区模型设置 → 继承全局设置`。已有例外时显示 `My Workspace 已单独设置 →`。不在完全继承时重复列出全部有效值，也不在 AI 页列出其他工作区。

工作区设置页拥有当前工作区的连接、模型、思考强度例外编辑，AI 页链接到这一处。工作区页保留“使用全局设置”选项、实际生效值和恢复继承操作，避免用户来回猜测。全局变更不得清除已有工作区例外。

上下文策略继续采用右侧下拉菜单，和连接、模型等行一致。选项保持自动压缩、自动接续、手动三种，不另外做前置选择卡片。

### 高级：图像生成

折叠摘要区分三个状态，展开后显示对应操作，而不是统一显示空表单：

1. **无兼容连接**：折叠摘要显示 `尚未配置`。展开后提供 `添加图像生成连接`，并解释：`当前 ChatGPT 订阅连接用于会话和图像理解；此版本生成图片需要 OpenAI 或 OpenRouter API 密钥连接。` 添加流程只展示兼容的供应商，但不自动保存、切换账号。
2. **可用**：摘要 `OpenAI · GPT Image 2`；展开后直接显示连接和模型两项，不再增加内层“配置”开关。自动选择显示实际将使用的账号与模型，例如 `自动：OpenAI · GPT Image 2`。
3. **已选连接失效**：摘要保留原账号并提示失效，展开后给出 `更新密钥` / `更换连接`。这时才使用警告色；不能偷偷改用另一个账号。

未配置是可选功能的正常状态，不显示长错误文案。显式账号不会回退这一规则在显式选择时就近说明，不作为永久页脚。

### 高级：决策辅助与 Guarded

决策辅助默认折叠，摘要显示启用状态与服务就绪情况。展开后显示独立启用开关，供应商、凭据来源、模型与功能开关放在同一个展开区域，按照依赖顺序排列。服务关闭时保留配置，仍可展开准备配置；不在分区外摊开不可用控件。

Guarded 的模式说明、可用状态和进入入口归权限页；依赖的决策服务配置归 AI 页的“决策辅助”。权限页的“配置”精确跳转并展开这一块。AI 页不再重复一个一级 Guarded 分区；决策辅助摘要需要直接说明“Guarded 审核未就绪”，不能藏掉依赖失败。继续保持审核不可用时回退为人工确认的行为。

### 高级：缓存与运行优化

缓存时间、缓存预热、RTK 保留在“缓存与运行优化”，默认折叠，只显示默认状态或启用项摘要。展开后使用标准设置行，保留各项适用范围说明。标题、摘要等辅助任务继续自动复用现有 utility model，不新增独立模型设置入口。

## 模型分类的边界

常规用户只需要两类可见选择：**会话模型**与**图像生成模型**。图像理解是会话模型能力，不创建“看图模型”配置。标题、摘要、压缩等任务不各建一个选择器。决策模型是可选高级服务，只有启用决策辅助时需要配置。

连接作为统一资源保存认证、端点和模型目录；功能引用连接与模型，不复制密钥。分类应反映调用方式、凭据和能力的区别，而不是按每项产品功能拆模型。

## 现在如何配置图像生成

当前源码只接受 `providerType=pi`、`authType=api_key`，且 `piAuthProvider` 为 `openai` 或 `openrouter` 的连接。ChatGPT Plus 走 `openai-codex` / OAuth，不进入这个列表。截图中的三个连接均不满足条件。

实际步骤：

1. 展开 AI → 高级 → 图像生成，点击 **添加图像生成连接**。定向接入流程只提供 OpenAI / OpenRouter API 密钥选项；也可从“连接”区正常添加。
2. OpenAI 密钥来自 [OpenAI API 控制台](https://platform.openai.com/api-keys)。API 使用通过 Platform 账户单独计费，不能把 Plus 的订阅用量视为这条调用链的 API 额度。
3. 返回 Image generation，选择刚添加的连接，再选该供应商的图像模型。当前应用的 OpenAI 内置列表含 GPT Image 2、1.5、1、Mini。
4. 可以继续让 Minimax 作为默认会话连接，图像连接独立设置；随后通过生成图片请求验证真实可用性。当前分析没有发起付费请求。

这是 **当前应用集成的限制**。OpenAI 官方同时提供 Images API 与 Responses API 图像生成路径，并有授权后的 ChatGPT plan Responses API 接入；因此不能概括成“ChatGPT 订阅永远无法在其他应用里生成图片”。若以后接入订阅生图，需另外确认授权范围、账户能力与工具支持，并实现对应调用链。不能只把 OAuth 连接加入下拉框就算支持。

源码依据：`packages/shared/src/config/image-generation.ts`、`packages/server-core/src/services/image-generation.ts`、`apps/electron/src/renderer/pages/settings/AiSettingsPage.tsx`。

官方资料（核对于 2026-10-05）：[API 密钥设置](https://developers.openai.com/api/docs/quickstart)、[图像生成接口](https://developers.openai.com/api/docs/guides/image-generation)、[订阅与 API 密钥认证](https://learn.chatgpt.com/docs/auth)、[ChatGPT plan 推理接入](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)。

## 实施验收场景

| 场景 | 必须达到的结果 |
| --- | --- |
| 页面首次进入 | 按连接、会话、高级顺序显示；高级下图像、决策、缓存与运行优化三项均折叠且有状态摘要 |
| 高级项展开、收起或跳转 | 三项可同时展开、状态互不影响；跳转只展开目标项；配置不套第二层折叠 |
| 只有 ChatGPT 订阅连接 | 明确支持会话及按模型看图；图像区给兼容连接入口，不出现空 Automatic 表单 |
| OpenAI API 与 Minimax 共存 | 会话继续使用 Minimax；图片使用指定 OpenAI，用途标签准确 |
| 选定图像账号失效或被删除 | 保留配置意图并提示修复，不跨账号回退 |
| 工作区继承全局 | AI 页只有继承入口；工作区编辑只在工作区页出现 |
| 工作区存在例外 | 全局更改不覆盖例外；恢复继承后立即更新有效值 |
| 连接切换导致模型不兼容 | 清除不属于新连接的模型选择并明确显示新生效值 |
| 决策辅助关闭、无凭据或 Guarded 未就绪 | 依赖关系清楚；权限页可准确到达配置；人工确认兜底不变 |
| 中文、窄窗口、键盘操作 | 全部沿用标准设置行和右侧操作；无溢出、无新增分页、无不可达配置 |
