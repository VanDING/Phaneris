# 助手「更多」工作总览：侧栏与交付物改版计划

Status: implemented — 2026-11-06 完成代码及本机隔离验收；真实 Host 的成果审阅/纠正 7 场景、桌面界面 32 场景通过，包含分页、版本预览与移出/恢复。最终证据及未验证范围见[实施记录](../process/resident-assistant-native-rollout-2026-11-05.md)。真实运行数据未迁移。

日期：2026-11-05。归属：[最终实施计划](../architecture/resident-assistant-permissions-memory-final-plan-2026-11-05.md)的 P1c，依赖 P1a 的任务/交付事实及 P1b 的查看能力。与[现场调度诊断](../verification/resident-assistant-dispatch-receipt-source-investigation-2026-11-05.md)互补，不以视觉调整掩盖执行问题。

## 1. 问题与目标

用户通过截图指出：历史任务持续堆积，占满侧栏；过程文件被当成交付物。改版前的工作树与之对应：

| 实现事实 | 影响 | 改版要求 |
| --- | --- | --- |
| useResidentPanel 每次刷新循环取完所有历史委派；可见时每 3 秒重复刷新 | 查询和渲染量随历史增长 | 当前与历史分别查询，分页、按需详情、有界刷新 |
| ResidentWorkPanel 连续展示全部 work，逐行排列模型、耗时、操作和详情入口 | 旧记录占据首屏，当前事项难以辨认 | 当前工作优先，紧凑行与逐步展开，历史独立入口 |
| 相关 Session 的全部非 discarded Artifact 都进入 Deliverables | 文件存在、被写入和最终交付混同 | 按任务用途与结果依据认定最终成果 |
| registerDelegatedDeliverables 收集成功 write/edit 的文件，以及部分 shell 后最终回复中的路径 | 辅助脚本、配置修改和中间稿也被收录 | 保留产物追踪，将文件发现与成果选择分开 |

截图确认使用问题，不证明运行客户端与当前工作树完全相同。该面板服务个人用户在与助手交谈时查看当前工作、处理决定、取得成果与回查历史，属于 Operate 场景。验收目标是当前事项易找、最终成果清楚、历史完整可查，并且数据量不再随历史无限增长。

## 2. 信息结构与布局方向

保留「更多」入口、非模态、可调宽、仅在助手页显示及 workspace 内恢复展示状态的行为。改版范围是这个工作总览，不重做全应用导航侧栏。视觉沿用 DESIGN.md 的中性色、字阶、语义状态与共享组件。

```text
助手工作                         刷新  关闭
当前          交付物          历史
────────────────────────────────────
当前视图
  待处理事项（存在时置前）
  正在执行 / 排队的任务
  最近已交付结果的简短入口
  查看更多 / 加载下一页
────────────────────────────────────
消息渠道：连接状态                 管理
```

这是信息层级示意，不是固定高度或最终像素稿。三个视图共用内容区域，不再把全部任务、文件和渠道串成一条长列表。保持一个主滚动区，详情在同一面板内切换并可返回，不层层嵌套滚动。

| 视图 / 区域 | 默认内容 | 进一步操作 |
| --- | --- | --- |
| 当前 | 待决定、执行中、排队、待恢复、待交付任务；最近已交付结果仅一个有界小批次 | 待处理优先；条目多时分页并显示剩余范围；可查看阻塞原因与原任务 |
| 交付物 | 最终成果按任务分组，展示当前交付版本 | 打开、定位原任务、查看旧版；配套材料展开，过程文件进入任务详情 |
| 历史 | 已交付、已失败且已处理、已取消或已结束的任务，以及明确的后续活动 | 搜索、筛选、分页；复用 Session 导航，不复制另一套会话历史 |
| 消息渠道 | 紧凑状态及管理入口；未连接时单一连接入口 | 按需配对与查看详情，默认不展示账号内部标识或平台占位列表 |

当前行主要展示任务名称、可理解的状态与一个主要动作。模型、原始配置、精确耗时、重试记录与原始错误移入详情；简短阻塞原因仍在行内，错误不能仅靠颜色提示。长标题可查看全文，避免截断后无法区分。

旧结果按真实交付事实进入历史，不仅依据 work.state=result_ready。未解决的决定、恢复问题和未交付成果，不因年代久远或关闭面板便消失。查看、隐藏提醒、交付、取消与用户接受各有独立含义。

计数对应当前视图范围，已加载数量与总量分开，不能取得总量时不编造。切换视图、预览返回及后台刷新保持选择、焦点和合理的滚动位置，新结果不挤走正在阅读的条目。

## 3. 交付物的语义与认定

**Artifact 是产物记录，交付物是本次任务承诺交给用户的成果。** 任务完成、成果登记、交付和用户接受不是同一状态。

| 用途 | 默认位置 | 认定依据 |
| --- | --- | --- |
| 最终成果 | 交付物视图 | 与任务目标、验收要求对应，明确进入最终结果，来源与版本可验证 |
| 配套材料 | 对应成果的展开区 | 服务于成果的附件、数据或说明，不单独抢占主列表 |
| 过程产物 | 任务详情 / 原会话活动 | 临时脚本、验证文件、日志、中间稿、缓存、调试导出等 |
| 原地修改或外部操作 | 结果摘要及变更证据 | 默认交付修改说明与验证结果，不自动将整个配置文件或工作目录列为成果 |
| 纯文字答复 | 结果及原消息入口 | 无需为每次完成生成文件，空交付物列表不表示任务失败 |

不能按扩展名或文件名黑名单认定：用户要求 Python 脚本、JSON 数据或配置模板时，它们可以是最终成果；用来验证另一份报告的同类文件则是过程产物。最终回复提到路径只证明被引用，不能单独证明已被选为成果。

已实现的闭环：

1. 派发时保留预期成果与验收条件，不要求用户额外维护文件清单。
2. Worker 在结构化最终结果中声明最终成果、配套材料及版本引用，文件仍由现有 Artifact 所有者管理。
3. Host 校验 delegation/input/run、来源、路径权限、真实文件与具体 revision；写入记录只能成为候选，不能直接晋升为最终交付。
4. 主助手按原任务核对声明，有依据才进入交付物投影并交付；普通分类无需逐项人工审批。不确定候选保留在任务详情，不冒称已交付。
5. 用户可将已审阅文件移出交付物或恢复展示；操作核对清单及文件版本，保留原文件和审计，不能将过程材料提升为最终成果。

引用现有 Artifact ID/revision、任务与来源消息，不另建文件库。用途与 current/draft/ready/accepted/conflict 生命周期分开；ready 不必然是最终成果，accepted 不代表用户接受整项任务。现有 ArtifactDeliverable 表示可导出的文件表示，也不等于已经具备任务成果认定。

同一任务同一成果默认一个条目展示最新已交付版本，旧版可回查。草稿、冲突或未完成修订不替换已交付版本；跨任务、不同交付目标不只凭 hash 合并。原文件变化、移动或删除时显示真实状态，预览与所引用的交付版本一致。

历史兼容保持保守：保留产物及已知交付事实，从可靠旧结果恢复用途；无法判断的条目仍可从历史/过程记录找到。不批量将旧 Artifact 标为最终成果，不物理删除误收录文件。

## 4. 数据与交互约束

- 当前查询只返回当前事项、阻塞原因、必要计数与有界最近结果；历史使用独立分页与稳定游标，执行详情按需加载。
- 交付物按助手/任务关联及成果用途查询，不先加载整个 workspace 的 Artifact 再由前端过滤；通过既有所有者的查询/索引扩展解决。
- 事件更新与有界补查优先；轮询兜底也只刷新所需范围，不能每隔数秒重新遍历全历史。关闭面板、离开助手页、切 workspace 后取消旧请求与订阅。
- 后端与 UI 统一分组、筛选、排序口径；分页期间状态变化或续作按稳定身份处理，不重复、漏项或让旧响应回填。
- 使用 PanelHeader、SegmentedTabs、共享菜单和 FileTypeIcon。沿用现有 384px 初始宽度、320–640px 调宽范围及视口限制；小窗口与较大 UI scale 下重排内容，不缩小字体掩盖溢出。
- 主对话保持可操作，预览复用现有能力；键盘可切换视图、查看详情、预览与返回，Esc/关闭恢复焦点，动效遵守 reduced motion。
- 查看与分类不触发执行，清理展示不等于取消、接受或删除；重试仍走原任务授权。

## 5. 实施与验收

P1a 先修复任务、续作与交付事实。P1c 先冻结当前/历史/成果用途契约和失败 fixture，再实现成果选择、查询与界面，不只在前端截取数组。实施时同步 PRODUCT.md / DESIGN.md 的该面板说明。

实施前覆盖：大量历史与少量当前任务、当前事项较多、过程文件远多于最终文件、纯文字结果、明确交付脚本/配置、同文件多次修订、取消后的独立续作、旧数据用途不明、文件变化/失效、分页期间状态变化、断线/重启和跨 workspace 竞态。

使用隔离数据与真实 Host/RPC 流程，保留请求次数/返回量、匹配 IDs、成果版本、键盘路径、截图和 trace。检查既有宽度边界、亮暗模式、较大 UI scale、长中文/英文标题及空/加载/错误状态。截图不使用私人任务正文；先记录规模和基线，再报告数据量与渲染表现，不提前声称未经测量的性能提升。
