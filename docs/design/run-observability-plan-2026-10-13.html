tokens/s 与折线图的具体规则

推荐按请求展示平均速率

一个点代表一次模型请求的观测平均输出速率。横轴是稳定请求序号，纵轴是 tok/s；选点可回到对应轮次、工具和上下文。这能回答「哪一次变慢」，并与行为记录对齐。

单请求 = 输出 tokens ÷（流结束 − 首输出）秒
范围摘要 = Σ 有效请求输出 tokens ÷ Σ 有效请求生成窗口秒

摘要是按生成时长加权的速率，不取各请求速率的简单平均。并行请求不把吞吐量相加成「模型速度」。主模型与不同辅助模型也不合成一条可比较曲线。

这衡量的是客户端观测窗口，包含网络与流式间歇，不能命名为纯 GPU 解码速度。输出 tokens 需覆盖同一窗口；若供应商不提供可匹配的用量，保留缺失。

缺失、实时与大数据

  • 无时间、无用量、非正区间和未结束请求不进统计；显示有效 / 总请求覆盖率。
  • 缺失样本留断点；慢请求可选中，不自动平滑或插值。
  • TTFT 与速度用指标切换，避免双 Y 轴。范围切换后所有摘要与图表采用同一范围。
  • 运行中显示当前状态和最近已结束请求的统计；不按字符数模拟精确 tokens/s。
  • 如未来需要 1 秒实时速率，需要供应商 token 增量或可验证分词；列为后续增强，不在首轮承诺。
  • 超过 200 点后做保留异常与缺口的分桶，标签注明粒度；点击桶先缩小范围再定位请求。

样式边界

  • 只以已认可 Overview 为视觉方案，保留现有上下文增长柱图；速率放其下。
  • 其余四页的原版就是最终样式依据；补充信息采用现有键值行、请求卡片或诊断折叠区。
  • 顶部四项摘要、现有紫色选中态、紧凑字号、轻分隔线、浅深主题和中英文表达保持一致。
  • 会话跨度、执行时长、当前上下文占用、累计输入各自保留明确口径。
  • 行为事实与任务目标完成分开；建议不能冒充实际应用，旧数据缺失不能冒充没有发生。
