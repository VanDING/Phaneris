四种入口状态

文件、运行轨迹和终端包含未打开、已打开、当前聚焦、收起后保留；浏览器有独立存在状态，帮助包含七个文档入口。

三套候选通过前景、背景和圆点区分状态，不修改原生描边。原库的状态加粗机制需要在正式迁移时重审。

工作台还包含固定／取消固定、放大／还原、收起、关闭。Solar 与 IconPark 的取消固定复用固定图形，以激活底色及按钮名称区分；甘特图分别借用水平条形与时间轴。Fluent 有专用甘特图与 Pin Off，终端则暂用 Code Block。

文件使用独立彩色主题

延续截图中的识别方式：Markdown 绿色 M、JSON 橙色花括号、Git 橙红、Docker 蓝色。目录和未知类型保持中性。

Phaneris 文件树

文件类型和界面操作，各自保持一致

文件类型以 Seti 为基础；Markdown 使用独立的公开 Markdown 标记。切换 A／B／C 只改变目录箭头、通用文件和操作按钮，已识别的类型标记保持一致。

已覆盖的规则

  • 文件名优先，再按最长扩展名与语言识别；包括 Git、Docker、ESLint、TypeScript、React、图片、PDF、Word、Excel。
  • 浅色和深色分别配色，文件名文字保持正常前景色。
  • 这版 Seti 没有 Bun 专用字形：bun.lock 用锁文件回退，bunfig.toml 用配置回退。
  • 同一解析器可覆盖文件面板、附件、产物卡片、预览标题和搜索结果；本轮仅演示。

这里演示接近截图的类型识别方式，并未读取或复制 Codex 的内部文件主题。

替换范围沿用源码盘点

237 个生产导入文件、877 次命名导入、197 个去除别名后的 Lucide 组件。本轮覆盖其中 72 个高频图标用途，演示不等于已完成全部组件映射。

桌面 renderer、共享 UI、查看器与复用 renderer 的 WebUI 都在迁移范围。品牌标识、用户图标和六种业务状态单独保留。

确认后的实施顺序

  1. 固定所选整套与主要语义，补齐剩余组件映射。
  2. 建立公共语义图标入口，解耦 LucideIcon 类型。
  3. 按区域迁移导航、顶栏、工作台、设置与共享组件。
  4. 单独接入文件类型解析器和深浅色主题。
  5. 检查真实 14／16／18／20 px 与所有状态。

需要一起看的取舍

Solar、Fluent 的灯泡偏向能力与想法，IconPark 的光芒则更抽象；循环图形强调重复运行，不能单独说明所有事件触发方式。文件变更也有近似：Solar 用 File Pen，Fluent 用分栏文档，IconPark 用 File Conversion，尚不能直接定为最终映射。

完整图标集仍可能缺少业务专用图形。优先保留这次演示的同套约束，正式映射时逐项解决，不能把覆盖数量当成语义质量。
