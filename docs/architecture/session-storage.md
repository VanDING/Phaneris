# Session 存储与生命周期契约

Status: accepted — Session 基础架构收敛；验证状态与限制见[实施记录](../process/session-foundation-implementation.md)。

Session 是对话自有持久化内容的归属单位。产品编排、运行控制、事务提交、SDK 适配和展示投影继续由不同模块负责；进程内运行状态由 Runtime Host 持有。

## 数据归属

| 内容 | 来源与位置 | 生命周期 |
|---|---|---|
| 标题、标签、项目、规划、已读、设置、富消息和计划批准快照 | `sessions/<id>/session.jsonl`，产品写入经 SessionProductRepository | 跟随 Session；字段由 SessionConfig/SESSION_PERSISTENT_FIELDS 定义，Header 派生配置类型 |
| 附件、计划、长输出、转换结果、下载、笔记 | Session 内的对应子目录和 `notes.md` | 跟随 Session；分支复制独立文件副本 |
| 输入草稿与草稿附件 | `sessions/<id>/draft.json` | 按调用工作区读取；随完整导出和删除，不作为已发生历史复制给分支 |
| 成果清单、私有修订、工作副本、派生预览 | `sessions/<id>/artifacts/` | 清单 `scope=session`，私有路径相对于 Session；跨会话副本重新绑定 owner，fork 生成新成果 ID |
| 用户工作文件、成果最终目标文件 | 用户实际目录，Session 保存引用 | 不随会话删除或迁移；已有内容校验、租约、接受和冲突规则继续适用 |
| SDK 日志与分支锚点 | `.pi-sessions/` 与 `meta/` | 完整包包含隐藏日志；历史分支由 SDK fork，自有产品文件独立复制 |
| 执行提交、用量、恢复证据和待回执 | 工作区 `runtime/` | 仍由事务内核管理；不因产品目录删除而伪造终结或删除未知副作用证据 |
| 任务规格、Pages、Sources、Skills、项目与应用配置 | 各自工作区/应用存储 | 独立或共享生命周期，不强制归入 Session |
| 流式文本、driver、取消信号、窗口与资源句柄 | 进程内 | 不作为会话文件内容强制落盘 |

Runtime 数据库的物理分区不在本次收敛范围。会话目录是产品内容单元，工作区备份才包含完整执行审计与恢复证据；产品导出不承诺搬迁运行中的 operation、凭据或外部副作用。

## 消息与读取

- 新模型结果使用提交事实中的 `model:<model operation id>` 作为产品消息 ID，重复投递不会追加第二条产品消息。
- 历史产品消息 ID 保持稳定。只有执行 operation 和已提交 cursor 能唯一关联同一模型事务时才建立读取别名，不按正文相似度猜测身份。
- 提交事实缺少产品消息时，可恢复最小语义记录；已有 prompt/context snapshot、注释等产品信息保留。无法重建的展示信息不编造。
- 一致性检查和 shadow/legacy 回滚选项保留。产品中存在未被执行事实覆盖的历史或超前 cursor 时，不通过投影丢弃这些内容。
- 分支/导入会清除源工作区的执行 cursor/operation 注解。历史进入目标 Runtime 时标记 `legacy_cache_unverified`、`dispatchEvidence=false`，只能提供上下文，不能授权重放或补造计费。

## 产品写入

SessionManager 对元数据、消息及待执行计划维护同一份产品状态，通过现有 Repository 生成快照与持久化屏障。标记已读、模型清空、分享状态和计划领取不再另读磁盘旧正文覆盖当前消息。

计划执行领取先在内存同步比较并领取，再等待持久化成功；失败撤回本次领取。并发请求只能有一个领取者。计划批准仍绑定用户已看到的不可变消息快照。

外部 Header 编辑继续通过文件监听合并。比较签名与保留字段使用同一字段列表，包含项目和看板列。列表读取不删除可能仍在写入或用于失败恢复的 `.tmp` 文件。

共享标签/状态等底层元数据工具使用同一写入队列的屏障，先完成已接受的产品快照，再读取、修改并复用分批原子写入。它们保留产品 owner 的自身写入签名，作为外部编辑交给监听器合并，不替换 owner 的待写消息。多个底层修改同样串行读取最新结果。

## 分支与传输

| 操作 | 保留/处理 |
|---|---|
| 历史分支 | 截止锚点的消息、当前产品文件的独立副本、成果副本与新成果身份；SDK 日志由 SDK 按分支语义建立；不复制未发送草稿，也不从普通文件推造历史版本 |
| 完整导出 | 已刷新的富消息、所有会话文件（包含隐藏 SDK 日志和草稿），排除临时目录和正在生成的 JSONL 临时文件；会话路径编码为占位符 |
| 导入 move | 保留可移植产品配置、规划与归档信息，重定位会话路径；源工作区项目/父子/依赖/任务/交接引用、分享状态和待执行意图清除 |
| 导入 fork | 在 move 产品字段规则之上，沿用现有连接、工作目录和 thinking level 兼容策略；成果分配新 ID，并更新真实成果事件卡片 |
| 摘要交接 | 保持现有摘要语义，不承诺完整文件复制或执行上下文迁移 |

导入先校验文件路径、大小、重复/保留名称，在隐藏临时目录恢复完整内容、重绑定成果及历史上下文，最后发布目录。失败不留下可见的半成品会话。可确定源目录的旧版包中，已经展开的源绝对 Session 路径仍可重定位。

## 删除与保留

删除会话先停止并释放执行资源、等待已启动的产品写入，再删除产品目录。草稿和成果私有内容随目录删除；用户真实文件不删除。

执行事实、用量、未知副作用及回执继续在工作区保留，不作为会话不存在就可安全清除的缓存。已有 decision evidence 删除语义保持。保留执行事实不会重建已经删除的产品目录；执行状态不能只凭目录有无来推断。

## 旧数据迁移与回滚

- 草稿按访问/导出懒迁移：先原子写入 Session 副本，再把旧 `drafts.json` 原始字节备份到配置目录的 `drafts-backups/<sha256>.json`，最后移除已迁移条目。新文件中的空草稿优先于旧值。
- 旧成果在访问、修改、分支、导出或删除时迁移：私有文件先复制，Session 清单发布成功后再从旧工作区清单移除对应条目。旧清单原始字节保存在 `artifacts/legacy-manifests/<sha256>.json`；旧私有文件保留供回滚。
- 新版始终优先读取 Session 清单。工作区成果列表是各 Session 清单与未迁移旧条目的投影，没有新增第二份成果权威。
- 迁移只处理明确的草稿条目和成果私有路径，不移动用户原始文件。任何复制、校验或持久化错误均可见，不把失败当作迁移成功。
- 本次实现不运行用户数据批量迁移或清理。部署前使用现有工作区备份保留完整快照；回滚旧版应恢复迁移前快照/原始清单与草稿备份。迁移后新增内容继续保留在 Session 目录中，恢复旧快照不会自动把这些新增内容合并回旧版索引。

## 验证

运行 `bun run verify:session-foundation`。每个流程使用隔离配置与工作区，在 `.cache/verification/` 输出独立目录、结构化结果和包含源码身份及文件哈希的 manifest。真实 provider、Office 视觉渲染等未验证范围在各 manifest 中明确记录。
