# Phaneris 0.6.2：助手权限、能力认知与 Worker 管理计划

Status: proposed — 2026-11-06 按用户本轮讨论整理的版本计划；产品原则已明确，以下实现方案及验收项尚未实施。本次仅落盘规划，不修改产品代码、版本或已安装客户端。

日期：2026-11-06，Asia/Shanghai。目标版本：0.6.2。核对基线：`3daa1eec0b85` 及当前未提交工作树，根包与桌面包仍声明 `0.6.0`。不据此假定 0.6.1 已发布，版本递增和发行合并在发布准备阶段执行。

本计划承接[权限与记忆综合计划](resident-assistant-permissions-memory-final-plan-2026-11-05.md)及其[本机实施记录](../process/resident-assistant-native-rollout-2026-11-05.md)，针对后续讨论发现的权限表达、L0 原文访问和管理能力缺口继续收敛。旧版安装客户端、当前源码及本机验证快照分别记录，不互相代替。实施状态统一登记在[实施台账](../process/implementation-value-register-2026-10-13.md)。

## 1. 版本目标与已确认原则

**0.6.2 的目标：主助手能够充分了解工作现场，清楚知道自己当前能做什么，并在用户授权内管理 Worker 完成工作。**

| 本轮已明确的原则 | 0.6.2 的落实要求 |
| --- | --- |
| 主助手拥有广泛读取权 | 直接读取已授权资料、项目、历史会话、任务结果和执行诊断，常规查看不需要创建 Worker 或逐次人工批准 |
| 主助手不直接承担业务执行 | 阅读、分析、对话、记忆维护和任务管理直接完成；业务文件编辑、命令执行、应用操作和外部写入交给 Worker |
| 主助手能管理 Worker | 查看现场，补充要求，调整安排，暂停、恢复、取消、重试和受控调整执行配置 |
| 助手具备功能性的自我认知 | 身份、职责、工具、操作范围、前置条件及当前可用状态由 Host 提供，与实际调用规则一致 |
| L0 是记忆底座 | 已授权历史原文直接可读，不以是否进入 L1/L2/L3、是否命中记忆或是否预先知道消息 ID 为前提 |
| 个人使用，沿用现有所有者 | 一个 workspace 一个助手；跨项目可查询，跨 workspace 不自动串用；不新增团队、多租户或外部记忆平台 |

“查看一切”在本期表示对当前 workspace 已授权工作资料和运行事实具有充分可见性，包括普通会话、Worker、归档及隐藏的普通会话。用户已指定且有访问权的外部文件路径可直接读取；不将当前 Project 当作所有文件的读取白名单。凭证由 Host 使用，模型获得认证状态、权限与故障信息。其他 workspace 的会话和记忆仍保持既有隔离，不因物理路径可达就取得访问权。

本期沿用已授权目标自主推进的方式，不增加日常操作的逐项审批。暂停恢复、重试或调参在原授权内完成；扩大目标、资源或外部效果范围时，沿用现有授权流程。

| 验收 | 上一轮有 21 工作流、351 组场景的隔离通过记录 | 新增“模型所见能力契约与执行一致”的验收；旧通过记录不证明新管理能力或真实模型质量 |

本轮已确认的典型矛盾：主助手可见 `get_session_info`，其 schema 公开 `history` 参数，但 Host 对主助手固定拒绝该参数。实际调用前的信息不足以让模型可靠知道这条限制。源码历史显示，通用历史参数先加入，常驻助手后在回调增加角色限制，工具定义未同步收窄。

依据：[通用工具 schema](../../packages/session-tools-core/src/tool-defs.ts)、[角色工具范围](../../packages/shared/src/agent/resident-role.ts)、[角色工具生成](../../packages/shared/src/agent/backend/pi/session-tool-defs.ts)、[Session 回调和委派限制](../../packages/server-core/src/sessions/SessionManager.ts)、[Worker mode 上限](../../packages/server-core/src/resident-assistant/worker-config.ts)。这是当前源码可确认的契约缺口；未对用户安装包做精确构建归因，也不据一次错误断言模型完全不理解角色。

最新版的[提示词组装](../../packages/shared/src/prompts/system.ts)已区分主助手与普通执行 Agent。本期审查共享工具和指导内容的实际消费者，保留通用 Session/Runtime 的复用，不以源码来自历史演进为由整体重写 Harness。

## 3. 职责与权限模型

### 3.1 三个主体的责任

| 主体 | 直接负责 | 权限边界 |
| --- | --- | --- |
| 主助手 | 理解目标、读取现场、管理记忆、安排 Worker、检查成果、交付和解释 | 不通过 shell、业务写入或通用管理工具绕过角色职责；不能修改 Runtime 事实来伪造进度或完成 |
| Worker / 普通执行 Session | 在具体目标与执行授权内运行命令、修改文件、操作应用或调用外部写入工具 | 只获得该任务相关授权和材料，不获得助手记忆库的枚举、搜索或修改权 |
| Host / Runtime / 原产品所有者 | 确认身份和范围，公布能力，执行管理命令，维护事实、凭证、归属、恢复和事件 | 是执行与授权的权威；模型自述、旧对话、记忆、Source 或 Worker 报告不能改变权限 |

主助手的记忆更新、Project 受控追加、Source 会话激活和 Worker 控制是明确的管理操作。它们允许修改相应产品状态，不应被笼统“主助手只读”规则一并禁止。业务文件和外部系统的变更继续走 Worker。

### 3.2 分开表达三类权限

1. **读取范围**：当前 workspace 的资料、历史、项目和执行诊断，以及用户已授予的本地/外部来源。
2. **管理范围**：哪些任务由主助手管理、允许哪些管理动作、哪些 Session 仅可查看。
3. **Worker 执行授权**：用户原始要求或已批准计划、目标和资源范围、执行 mode、工作区/项目限制、预算及撤权版本。

Worker 的有效权限由用户执行授权、workspace/project 上限、工具效果规则及当前资源授权共同确定。主助手不持有 shell 工具，不应据此推导出 Worker 也只能只读；同时，主助手不能自行将讨论、试探性设想或历史授权升级为新的执行许可。

继续复用 safe / ask / guarded / allow-all 及现有授权检查。若界面当前选择 Explore 明确表示本轮不执行，委派也须遵守。需要把主助手自身角色与“允许派发的执行模式”分开显示；旧设置迁移时按原执行上限保存，不因升级自动从 safe/ask 提升到 allow-all。可用预算和并发沿用既有工作方式，默认不因增加管理能力开启批量并行。

任务授权引用应保留原输入、具体范围及 Host 版本。精确 `goalQuote` 可定位目标，但不能单独创造授权。开始、恢复、重试及配置变更均重新核验当前授权；在同一范围内不反复要求用户批准。

### 3.3 可见与可管理分别判定

- 主助手可查看当前 workspace 其他普通会话的历史和执行信息；只读不要求该会话先成为自己的委派任务。
- 自己派发的 Worker，按原目标和授权管理。
- 普通 Session 可在明确任务中续用或纳入管理，保留其身份和历史；不自动接管正在进行的直接用户对话。
- Tasks / Conductor 所属执行通过原调度所有者管理，不从助手侧修改其底层子会话来抢占任务。
- hidden、archived、Project 切换和模型上下文轮换不单独构成历史不可见理由；真正的撤权、遗忘或所有权隔离分别执行。

## 4. L0 原始会话作为一等读取能力

### 4.1 统一读取契约

Session 原存储继续持有原文。增加或收敛一个由 Session 所有者提供的原文读取服务，供助手直接阅读、历史检索回读、记忆提炼和诊断共同使用。对模型分别表达“找会话/消息”“读取会话原文”“检索/读取记忆”；工具数量以清楚可达为准，不另建第二份聊天库。

| 操作 | 输入与行为 | 输出要求 |
| --- | --- | --- |
| 发现会话 | 按标题、项目、时间、归档状态等分页查询 | 稳定 Session ID、标题、时间、归属及来源是否可读 |
| 阅读会话 | 仅凭 Session ID 即可按时间顺序或从尾部翻阅 | 原消息及分页游标，无须 memory ID 或预先知道 message ID |
| 定位原文 | 按消息、时间范围、工具操作或历史搜索位置展开 | 精确位置、内容身份及完整/截断/缺失状态 |
| 阅读运行现场 | 读取已持久接收/提交的消息、工具结果和错误 | 区分排队输入、已执行观察、未结算效果和后续人类输入 |
| 回查附件与成果 | 返回原文件/Artifact 引用，按需使用文件读取或版本预览 | 引用不等于正文已解析；缺失、失权和格式不支持分别说明 |

返回已保存的用户原话、助手回复、工具名称/参数/结果、错误、时间及附件引用；中间回复和内部控制消息按类别标注，按需展开。通用 `readTaskHistory` 当前只返回部分用户/助手消息，不能直接宣布它覆盖完整 L0。工具执行事实复用 Runtime 已提交记录与现有 Session 投影；没有原文或没有结果的记录披露缺失，不由模型补写。

读取有界、可续读。采用稳定消息 ID / 提交游标和消息内字符位置，携带读取时的快照边界及内容身份；读取期间会话继续增长时，不重复、跳过或无声改变前页。旧记录无稳定 ID 时以 Host 可验证的位置与内容指纹兼容，明确旧数据覆盖限制。按目标读取时，不要求先推进整个历史索引。

### 4.2 原文、有效性和权限分别表达

- 未提炼、候选、冷却、过期或被纠正，不等于原始经历不可查看。允许回查旧说法，同时标记它不再是当前事实，不自动重新激活记忆。
- 显式遗忘的内容和已撤销的来源权限继续受抑制。直读、搜索、附件、工具结果和派生材料回读共用边界，不能通过换入口复活。
- 区分“历史观点已被纠正”和“已撤销访问权”。可审计的旧观点保留原文及失效说明；被禁止再使用的来源只返回不可用状态。对当前一律报材料失效的路径逐项核对原因，不为便于读历史整体关闭依赖校验。
- 读到旧用户请求、Worker 报告或 Source 内容只取得历史证据，不取得当前执行授权。作者、原输入、内部消息类别和执行归属保留。
- 原始 SDK 控制文件、凭证库和正在写入的数据库不作为模型自行操作的入口。所需运行事实通过只读诊断/一致视图提供；路径保护不应阻止获得业务原文和必要故障证据。
- 读取 L0 不意味着全量注入模型、全量提炼、自动学习全部附件，或默认把其他项目约定用于当前项目。记忆学习/使用两个开关保持独立；关掉自动记忆使用仍允许用户要求的历史原文查询。

### 4.3 与现有入口的兼容

先确定主助手拥有完整的授权 L0 读取权，再决定工具 schema 的拆分。可以保留元数据入口，并将历史读取明确分开，也可以在一致的会话读取接口中表达；无论选择哪种，主助手公开参数都必须实际可用。

`assistant_memory_read` 保留旧调用和来源引用的兼容，但内部调用同一来源所有者及权限边界。旧语义不得继续让主助手误以为“只有已经成为记忆来源的消息才可读”。普通 Worker 原有的本任务历史读取能力不因收敛受到削弱。

## 5. 助手的功能性自我认知

### 5.1 Host 提供的事实

| 层次 | 内容 | 更新方式 |
| --- | --- | --- |
| 稳定角色 | 主助手身份、所在 workspace、职责、业务执行分工和事实所有者 | 由产品角色定义生成，明确区别于普通 Worker |
| 当前能力摘要 | 可调用操作、目标范围、只读/管理/执行效果、必要前置条件 | 每次模型请求使用 Host 当前能力快照；正文有界，详情按需查询 |
| 动态就绪状态 | Source 连接/认证、Worker 当前阶段、权限和预算、能力暂不可用原因 | 从原所有者读取，变化后更新快照及工具集合 |
| 已发生事实 | 接受、执行、工具效果、停止、失败、结果和投递回执 | 只从 Runtime、Session、Artifact 及现有事件所有者取得 |

这些事实不写进 L1 或 Persona，不依靠旧会话“记住权限”。L3 协作偏好、AGENTS.md 和知识文本不能扩大运行能力。

### 5.2 同一契约生成说明与检查

复用现有 `SESSION_TOOL_DEFS`、角色定义和权限所有者，补充必要的操作级/角色级描述。由同一组定义派生：

```text
Host 当前角色、授权、资源状态
             ↓
操作契约及能力快照
   ├─ 角色摘要与能力说明
   ├─ 工具名称、描述、参数 schema 和发现结果
   ├─ Host 调用检查及可用后续动作
   └─ 模型请求快照、诊断和验收证据
```

不新增一份独立维护的“助手允许列表”或可由模型编辑的能力文件。稳定禁止的操作/参数不作为可执行能力公布；条件操作描述目标范围与前置条件。可发现但暂不可用的能力可在目录中说明原因，不能同时伪装成已就绪工具。

能力快照带版本/摘要身份；权限、工具定义或来源状态变化后，模型下一请求与 SDK 重建使用新版本。旧上下文、工具发现缓存和持久 Session 恢复不能重新带回已移除能力。准备与实际调用之间发生的变化仍由 Host 检查，并触发有界重新发现或上下文更新。

### 5.3 提示词和错误语义

- 保留独立角色提示词，将稳定职责与细节能力说明分开。工具参数和权限事实避免在长 prompt 中手写第二份规则。
- 审查共享 Session 指导、task-continuity、工具 family guidance、恢复文本和旧会话带入内容；以实际模型请求证明哪些内容进入主助手，不凭文件名判断污染。
- 当前已知 `get_session_info(history)` 矛盾作为第一条失败用例，不以更换报错文案或补一句“不要这样调用”作为完成。
- 区分能力不支持、来源未就绪、范围未授权、状态冲突、内容已变化、未知效果及实际程序错误。返回可核对原因、已执行与否及有效后续动作，复用现有工具/RPC 错误边界。
- 正常范围内自动重新发现、查询或等待控制回执；需要用户提供的真实信息或新增授权才向用户提出具体问题。不能把每次暂不可用都转换为人工确认。

## 6. Worker 全过程管理

### 6.1 统一管理操作

以下是操作契约，具体工具名称在实现契约阶段确定。扩展现有委派/Session/Runtime 服务，不新增另一套 Worker 实体、调度器或任务状态库。

| 操作 | 主助手获得的能力 | Host 必须保证 |
| --- | --- | --- |
| 检查 | 目标、原输入、最近原文、实际活动、错误、等待、配置与成果一并按需展开 | 原任务与后来用户续作分开；元数据状态不冒充 Runtime 状态 |
| 补充/纠正 | 向运行中 Worker 增加资料、收窄要求、请求进展或返工 | 类型化管理输入，保留发送者、授权来源、任务与轮次，不伪装成直接用户新指令 |
| 暂停 | 请求在安全位置停止，并保留待继续范围 | `pause_requested` 与实际已暂停分开；未结算外部效果继续占有资源 |
| 恢复 | 从已保存现场、原要求与完成事实继续 | 恢复同一逻辑任务/Session；可新建 Runtime 尝试，不重放已完成业务效果 |
| 取消 | 停止排队或活动任务，保留记录 | 取消不表示回滚；不能停止原任务结束后新出现的独立用户工作 |
| 重试 | 在识别失败原因后继续未完成部分 | 只对安全、可幂等或已核清效果执行；未知效果不能整段重新运行 |
| 调整安排 | 修改优先级、规划字段、依赖和后续步骤 | 使用原 Session/Tasks 所有者；资源冲突、Conductor 和用户当前工作继续有效 |
| 调整执行配置 | 在允许范围更换模型、思考强度、Sources、Skills 或目录等 | 在边界应用新版本，结果关联实际配置；扩大授权不能由助手自行决定 |
| 检查与交付 | 对照验收要求审阅，提出返工，选取版本并交付 | 保留 Artifact 和原回执归属，不因停止运行自动判为满足要求或用户接受 |

### 6.2 运行中沟通、暂停与恢复

复用现有消息准入和 steering/队列机制，通过管理主体和任务归属传递。运行后端支持安全 steering 时在可接收处应用；不支持时安排到下一边界，返回明确的等待回执。不能假称修改已经进入当前推理。

暂停先阻止后续准入，再结算或核清已开始的效果，保存原输入、工作检查点、配置身份及完成回执。只有 Host 确认不再持有活动执行、且恢复条件可描述时，才显示已暂停。普通命令/外部服务无法瞬间安全暂停时，明确等待或恢复限制，不宣称已撤回外部效果。

恢复以 Host 原事实和工作产物为依据，不能依赖旧模型进程仍在。显式暂停跨应用重启保持暂停；普通故障恢复继续复用既有策略。取消保留取消，不因恢复其他活动自动复活旧任务。

### 6.3 命令回执与并发一致性

管理命令至少关联：稳定 command ID、命令内容指纹、任务/委派及 Session ID、预期状态或配置版本、授权来源、目标输入/执行关系。Host 返回接受、等待应用、实际应用、冲突或拒绝，并附原因和结果版本。

同一命令重试返回原结果；复用 ID 改内容被拒绝。多窗口、助手与用户同时操作时按预期版本处理，不静默覆盖。事件和回执写入现有 Runtime/委派/产品所有者；新增控制记录只表达命令事实，不复制一份可独立编辑的 running/completed 状态。

直接用户的新要求优先于旧的待应用管理意图；旧命令须重新核对目标输入和版本。管理命令不借用通用“取消整个 Session”去干预不属于原任务的后续轮次。

### 6.4 配置变更的应用边界

排队任务在开始前应用已批准的新版本；运行中任务先记录变更意图，在可核验边界停止/切换，再准备下一尝试。已开始的工具结果保留其原配置归属；新增效果使用新配置和授权。撤权立即阻止后续准入，不能等待普通调参窗口。

区分明确配置变更与意外配置漂移。明确变更有命令、版本和授权，允许重新准备；意外漂移仍触发栅栏。不能通过关闭现有材料/能力校验来使运行中调参“看起来成功”。

### 6.5 状态和进度的所有权

| 内容 | 所有者与行为 |
| --- | --- |
| 安排、优先级、下一步、是否返工 | 主助手可在管理范围内调整，调用原产品所有者 |
| 接收、推理、工具执行、等待、停止和失败 | Runtime/Host 记录事实，助手只读取或发控制请求 |
| 业务完成度、阶段估计 | Worker 上报或主助手评估，标记来源和时间，不冒充精确执行百分比 |
| 任务执行完成 | 根据原任务执行与成果证据自动结算，不一律等待人工关闭 |
| 成果审阅、已交付 | 复用现有审阅/投递事实，必要时要求返工 |
| 用户已读、接受或批准新效果 | 依据用户真实表达或既有明确规则，不由模型推断 |

审查旧 `set_session_status` 对 closed 状态的一刀切限制与新管理入口的关系。通过原任务所有者允许有证据的常规完成/取消，同时保留“完成不等于用户接受”；不向主助手开放任意改写 Runtime 终态的字段。

## 7. Source 与界面的必要配套

Source 继续使用现有连接器、凭证和会话激活机制。能力目录区分已配置、已授权、认证就绪、连接中、已连接和操作可用。主助手自主选择相关且已授权的少量来源；不用每轮重新让用户勾选。

只读效果按 Host 可信操作契约判断。当前通用 API 仅允许 GET；若某已适配服务使用 POST 实现查询，应由 Host 的具体只读适配/操作定义表达，不能给通用 POST 或仅凭远端 `readOnlyHint` 放行。没有可信效果定义时如实说明能力缺口，业务写入仍交给 Worker。

沿用已完成的“当前 / 交付物 / 历史”面板，补充必要控制和诊断，不重新设计全应用导航：

- 根据目标与当前状态显示可用操作；请求暂停和已经暂停、等待配置与实际应用分别显示。
- 详情提供最近原文、错误、等待原因和真实配置版本；历史按需读取，列表不载入全量消息。
- 权限设置明确主助手读取/管理职责与 Worker 执行默认上限，避免一个 mode 同时暗示相反职责。
- 调参、返工和管理结果使用原委派/Session 导航；失效响应不回填其他 workspace 或新任务。
- 正常操作直接执行；冲突或需要新增授权时显示具体原因。既有删除/不可逆操作规则保持，不新增固定审批向导。

## 9. 实施前失败矩阵

下表均为待实现/待验证的验收要求，不代表已经通过。优先扩展真实 Host/Pi/RPC 与桌面 E2E；若必须隔离验证，先列全失败方式再修改实现，不在实现后补同构单元测试。真实模型路径选择与确定性 fixture 分别验收。

| ID | 触发场景 | 必须观察到的结果 |
| --- | --- | --- |
| P01 | 主助手读取其他项目或用户指定路径的普通文件 | 直接得到原文，不创建 Worker、不要求逐次审批 |
| P02 | 已有 Worker 执行授权，但主助手尝试 shell/业务写入 | 主助手职责边界仍生效，委派授权不转化为自身业务工具权限 |
| P03 | 主助手不持有业务执行工具，用户已授权 Worker 编辑任务 | Worker 在原执行授权内启动，不被主助手只读角色错误压成只读 |
| P04 | 当前处于 Explore，或用户仅要求研讨 | 不自动派发执行；分离执行上限不绕过用户不执行意图 |
| P05 | 派发后撤销资源或执行授权 | 阻止下一效果，保留已提交事实；旧输入和记忆不能恢复授权 |
| P06 | Host 适配的 POST 查询与普通 POST 写入同时存在 | 前者按可信只读定义可用，后者不因名称/注解获得主助手写权限 |
| P07 | 请求其他 workspace 的会话、记忆或伪造目标 ID | 按 Host 身份隔离，不能仅靠 payload/path 获得访问权 |
| P08 | 发现连接、排查认证、列举能力 | 返回状态与原因，凭证明文不进入模型请求或错误文本 |
| C01 | 导出主助手 `get_session_info` 及相关历史 schema | 不再公开固定不可用的参数路径；实际获准的 L0 入口清楚可达 |
| C02 | 同一通用工具分别供主助手和 Worker 使用 | 参数、描述和校验符合各自职责，普通 Worker 历史能力不退化 |
| C03 | 要求助手说明自己角色、可读范围与管理能力 | 模型请求中的身份/能力事实与当前 Host 一致，回答可用真实工具执行验证 |
| C04 | 模型请求准备后 Source 失权或工具移除 | 调用重新检查，后续请求刷新；不循环重试或声称原操作成功 |
| C05 | SDK 恢复、压缩或模型切换后能力集合改变 | 不恢复过期工具/schema，稳定助手身份与新能力快照同时保留 |
| C06 | 旧会话或共享指导提到当前角色不具备的工具 | 历史不授予能力；实际主助手请求无冲突的产品指导 |
| C07 | 未认证、未连接、状态冲突及真正程序错误 | 返回不同原因和合法后续动作，不将所有失败转化为用户确认 |
| C08 | 记忆或 Source 声称助手拥有额外权限 | Host 能力不改变，角色说明不从长期记忆学习 |
| H01 | 读取没有任何已提炼记忆的普通会话，仅已知 Session ID | 可顺序/从尾部阅读原文，无须先生成记忆或定位消息 ID |
| H02 | 跨项目、归档、隐藏普通会话 | 在当前 workspace 原权限范围内可读，检索覆盖和物理存在分别说明 |
| H03 | 会话包含工具调用、错误、中间回复及内部投递 | 原作者、工具结果、类别和执行归属保留；内部报告不变成用户指令 |
| H04 | 超长消息、附件引用、文件缺失或不支持格式 | 分页续读无静默丢文，未解析与已读取分别标明 |
| H05 | 翻页过程中运行中的会话继续追加 | 按快照边界/稳定游标续读，无重复、漏项或读到另一任务结果 |
| H06 | 翻页期间原文被外部编辑或旧位置改变 | 内容身份冲突可观察，按新快照重读，不替换成错误消息 |
| H07 | 来源已遗忘或撤权后尝试多种历史/附件/派生入口 | 均遵守抑制和访问规则，原文直读不能使被禁内容复活 |
| H08 | 查询已纠正或过期但仍可审计的旧观点 | 原文可查并标明历史性，不当成当前事实或重新准入 |
| H09 | 主助手要求排查 Runtime / Session 错误 | 有只读诊断入口获得必要证据，仍不直接操作可写控制库 |
| H10 | 关闭自动记忆使用或只读取一次历史 | 显式 L0 查询可用，不触发全库模型扫描、全量注入或权限扩张 |
| W01 | Worker 正在推理时补充资料或收窄要求 | 在可接受边界应用，类型化输入保留原授权和作者，有真实回执 |
| W02 | 请求暂停后立即退出、重启或重复发送 | 暂停请求与实际暂停准确，重启后不自动恢复显式暂停任务 |
| W03 | 暂停/取消时存在未知外部效果 | 不假报安全停止、不释放冲突资源后重复运行；无关任务仍可推进 |
| W04 | 恢复或重试已完成部分操作的任务 | 延续原任务与完成事实，不重做已提交写入或重复投递 |
| W05 | 运行中更换模型/思考强度/Source/目录 | 配置按边界与版本应用，旧工具结果和新尝试各自归属准确 |
| W06 | 调高优先级但与未知效果或同目录任务冲突 | 安排可变，资源保护与原调度约束继续生效 |
| W07 | 管理命令重试，或同 ID 携带不同内容 | 原结果幂等返回，变更内容被拒绝，不重复控制 |
| W08 | 原委派结束后用户直接在该 Session 发起新工作 | 原管理命令不能中止、改写或冒领新的人类工作 |
| W09 | 对 Tasks/Conductor 所属 Session 进行管理 | 通过原调度所有者，不绕开 DAG、资源和任务关系 |
| W10 | Worker 停止、业务不完整或结果已完成但未获用户反馈 | 真实执行、业务评估、已交付和用户接受分别表达，不制造假完成 |
| W11 | 管理或成果通知在 ACK、持久化间重启 | 同一命令/结果有界补送，无第二个 Worker 或重复交付 |
| W12 | 新用户要求到达，旧调参/补充命令尚未应用 | 新要求优先，旧命令重新核对原输入/版本，不迟到覆盖 |
| W13 | 两个窗口或助手与用户同时修改安排 | CAS/版本冲突可核对，旧响应不覆盖新状态或另一 workspace |
| R01 | 0.6.2 候选包实际启动并执行 L0 与 Worker 操作 | 包内角色、工具 schema、Host 版本一致，安装版/开发版明确可辨 |
| R02 | 执行既有综合回归及新工作流 | 实际运行全部要求，计数来自新 manifest，旧 351 组通过记录不充当本次结果 |
| R03 | 桌面进行管理、原文回查、错误处理与返回 | 亮暗/窄窗口、键盘、焦点、滚动和分页保持；列表请求量有界 |
| R04 | 真实已配置模型完成代表性日用任务 | 保留模型、提示词/工具快照、选择路径、实际结果与失败，不用确定性回路代替模型质量结论 |
| R05 | 旧设置、旧回执、旧客户端及中断迁移 | 原执行上限不扩大；未知新能力明确不可用，暂停/撤权/完成事实不丢失 |

## 10. 验证产物与完成标准

继续使用 `VerificationRun` 及 `bun run verify:assistant-rollout --output-dir=.cache/verification/<新目录>`，按本期契约扩展子工作流或纳入新工作流。每次运行使用独立配置根，保存实际源码/构建身份、模型请求、角色提示、工具 schema、调用/拒绝轨迹、管理命令回执、数据库/消息证据及桌面截图。新输出不能覆盖旧运行来隐藏失败。

验收分三层，分别报告：

1. **契约与确定性流程**：已知权限/参数矛盾消除；L0 和全部承诺的 Worker 管理操作通过真实 Host/Pi/RPC E2E；没有重复事实所有者或授权扩大。
2. **实际模型行为**：选取“读取未记忆历史”“检查运行中 Worker”“补充/暂停/恢复”“失败后选择合法路径”等任务，用本机实际配置且支持工具调用的模型保留样本。证明该配置下的表现，不宣称所有模型零误用；未运行不能写为通过。
3. **桌面候选与发布**：实际候选包跑核心纵向流程，验证包内能力与源码一致；类型、lint、i18n、身份、版本、文档及发行要求按仓库原门禁执行。真实用户数据操作与安装替换单列，开发验收不自动执行现场迁移。

完成必须同时满足：

- 主助手能直接查读授权范围内其他普通 Session 的原文和执行证据，不依赖已经存在的记忆条目。
- 角色摘要、能力快照、工具发现、schema 与 Host 执行规则一致；固定禁止路径不作为可调用能力公布。
- 本期列出的 Worker 管理操作有实际可用实现、真实回执与恢复路径，不能只增加按钮或 prompt。
- 读取、管理、执行授权分开生效；用户原有执行模式与不执行意图保持，常规操作不增加手动审批。
- 控制意图、Runtime 事实、业务评估、交付及用户接受各有归属；暂停、取消、调参和重试不重放未知效果。
- 历史、记忆和知识源共享有效的抑制/撤权边界；旧原文可审计与禁用内容不可复活两项均有证据。
- 既有助手记忆、Project、目录、交付物、普通 Session 和 Tasks 能力通过相应回归；记录实际失败和未验证平台/模型范围。

## 11. 兼容与恢复

本期不重做 `assistant/` 目录迁移，不复制现有 L0 或重写原始历史。新增 schema、授权字段和命令回执采用版本化、可恢复迁移；旧数据缺少新字段时从既有权限设置恢复保守上限，不以模型推断补授权。

旧 API 可短期适配到统一所有者；适配路径与新入口必须共用校验。历史读取入口、工具定义和角色规则一起切换，避免只改 Host 或只改 prompt。旧客户端不认识的管理动作不回退成直接数据库写入；由版本/能力协商返回实际可用能力。

遇到中断，先核对管理命令、执行事实与原输入，再继续未完成步骤。版本回退须识别新记录与未知效果，不能只切回旧数据库而丢失暂停、撤权、遗忘或完成事实。实施时保留原未提交工作及基线副本，不重置用户改动。

## 12. 本期边界与旧路线关系

本期不新增人格文件、全局学习记忆、跨 workspace 共享、团队功能、外部 Memory Provider、通用 Wiki/CodeGraph、全量自动技能整理、独立常驻监督模型、无限轮询、完整 OS 进程沙箱或新的自主巡视目标。已有内置记忆的四层结构、Project 单一文件权威、Sources 凭证和执行所有者继续适用。

原 [0.6.x 路线](resident-assistant-0.6-roadmap-2026-11-03.md)对 0.6.2 的“长期主对话与多议题接续”属于早期建议切片。本次以用户新确定的权限、L0 和能力认知问题重定 0.6.2 重点；已有多议题、材料更新和身份连续性作为回归基础，新增的大规模长期质量工作不自动并入。

与旧综合计划相比，本稿明确提出调整“Worker 上限机械继承主助手 mode”的表达、补足完整 L0 访问，并收敛角色工具参数与管理闭环。这些调整在本计划进入实施并完成验收前，不描述为已生效行为。旧版 21 工作流/351 组场景及其通过边界保留为历史证据。

本期的产品结果应能由一个连续场景验证：用户让助手回查某个历史项目的原始决定，检查当前 Worker 的实际错误，补充要求并调整执行方案；助手能够选择真实可用接口，在原授权内继续工作，检查并交付成果，全程无需用户解释内部工具禁区或手动修正状态。
