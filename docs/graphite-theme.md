# Graphite 主题 — 设计与校验记录

文件：`~/.phaneris/themes/graphite.json`（即 `C:\Users\dotty\.phaneris\themes\graphite.json`）
状态：已落盘，已被应用的主题加载器接受（见下"验证"）。

---

## 1. 它是什么

一套**刻意无彩**的主题：所有表面来自同一个冷灰家族，层级完全由可测量的明度台阶 + 发丝边框 + 克制的阴影承担，而不是靠色相区分。四个语义色保留各自的识别度，但饱和度压到最低，所以界面第一眼读起来是黑白的，同时状态仍然可辨。几何（12px 圆角 + 1px 平直规则）是唯一的表现维度。

| | light | dark |
| --- | --- | --- |
| background | `#F4F5F6` | `#101114` |
| foreground | `#1A1B1E` | `#E7E8EA` |
| accent / ring | `#5A5F6E`（石墨紫灰） | `#B6BAC8`（近白，反相） |
| border | `#DBDCDE` | `#2A2D32` |
| radius / 字号 / 行高 | `12px` / `15px` / `1.55` | 同左 |
| depth / 阴影强度 | `elevated` / `0.05` | `elevated` / `0.30` |
| shiki | `min-light` | `min-dark` |

## 2. 几个刻意的选择

- **accent 与 ring 用同一个石墨灰，暗色下反相成近白。** 黑白主题里，品牌强调色如果还是紫色，整套就白做了；而这个主题里「深底白字 / 白底深字」本身就是品牌色。暗色模式下 `--accent` 与 `--foreground` 亮度接近（9.75:1 vs 15.4:1），因此不靠色相也能区分。
- **语义色低饱和但没去掉。** 色相两两仍然拉开 34° 以上，所以 Ask / Connected / Failed 靠色相仍可区分；饱和度上限 42%，在浅色底上读起来是"有颜色的灰"而不是彩色徽章。试过更纯的版本（55%、63%），测下来会退化成普通的彩色 UI，所以维持现状。
- **shiki 用 `min-light` / `min-dark`**，是白名单里最中性的两套，代码高亮不会把黑白的整体打散。
- **没有写 `navigator`**，所以左侧边栏自动继承 `--background`，与主背景融为一体（这也是主题规范的默认建议）。
- **`fontSize` 保持 `15px`（应用默认值），不跟随主题规范的 16px 建议。** 这一条是有意违反：Tailwind 的尺寸工具类全部基于 rem（`--spacing: 0.25rem`），而 `--font-size-base` 改的是根字号 —— 从 15px 提到 16px 等于给整个 UI 加 6.67% 缩放，`p-*` / `m-*` / `gap-*` / `space-*` 会跟着放大，图标、命中区、宽高、变换全部受牵连。主题引擎专门为此造了 4 个独立密度变量，并在源码注释里写明"不要动 Tailwind 全局间距"。这个教训来自本次实测：16px 版本装上去后整个界面肉眼可见地变大了一圈。

## 4. 需要你知道的两处取舍

**一、纯中性。** 主题规范里明确写了「纯中性黑（饱和度 0–10%）是最平淡的选择，至少给底色 20% 以上的色相偏移」。这套主题**故意违反**了那一条 —— 因为你要的就是黑白。为了让它在无彩的前提下仍然成立，做了两件补偿：表面台阶拉得比内置 Default 更开（light 2.15 L\* vs Default 约 2.1；dark 3.08/4.04 L\*），并且边框对比更强。如果哪天觉得太素，最小的调整是给 `dark.background` 加一点冷色偏移（例如 `#0F1116`）。

**二、`fontSize` 必须是 15px。** 见第 2 节最后一条：改成 16px 会给整个 UI 加 6.67% 缩放。这是硬约束，不是口味问题。

## 5. 如何启用

设置 → 外观（Appearance）→ 主题，选 **Graphite**。主题目录有 watcher（`UserThemeWatcher`），文件改动会即时生效，不用重启。
