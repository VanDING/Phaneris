# 会话决策专项：实施与验收

2026-10-09。已实施用户确认的 [设计方案](../design/decision-assistance-run-plan.md)，并完成隔离会话、真实页面和 Windows Electron 客户端验收。失败场景先于实现写入 [失败矩阵](decision-run-failure-matrix.md)。

## 交付行为

| 页面 | 当前职责 |
| --- | --- |
| Settings → Permissions | 权限规则；移除只承担跳转的 Guarded 区块 |
| Settings → AI → Decision assistance | 启用、服务、凭据、模型、时限、连接测试与功能开关；不再查询或展示累计运行统计 |
| Run → Overview | 绑定会话的决策摘要和进入记录的入口；一行范围、四个数字与「查看记录」 |
| Run → Decisions | 状态行 → 四块同权重指标瓷砖（决策事项／实际改变／回退／决策费用）→ 功能对比 → 决策记录 → 详情抽屉 |

固定会话与跟随当前会话保持各自的绑定。查询身份包含服务器、工作区、会话及筛选；晚到响应不能覆盖新的范围。Decisions 独立于聊天消息加载，空消息会话也可以查看持久化决策。

筛选后的页内统计、功能分布和记录使用同一范围；Overview 始终显示完整会话摘要。更新时保留已加载的历史及仍存在的详情节点和焦点；重连重新读取事实，旧分页版本失效时重查。**两种范围不可混用**：瓷砖与功能对比取服务端的完整筛选范围，记录列表只是其中一页，因此列表计数显示「本页 / 范围」。

详情在宽面板是右侧非模态抽屉（列表保持可用），窄面板是底部模态抽屉；两者由实测面板宽度决定，不由外层传入的宽度状态决定。状态筛选只提供服务端查询契约里的五个桶（已改变／回退／未确认／失败／已取消），不会出现服务端答不出的选项。

## 事实与统计

| 内容 | 口径 |
| --- | --- |
| 决策事项 | 不同 `decisionPointId`；实际进入但配置不可用的判断也有事项记录 |
| 模型请求 | 已进入发送阶段的不同 `attemptId`；批次属于同一事项，未发送不计供应商请求 |
| 实际改变 | 宿主处理边界确认的 `applied` 且 `changed`；建议、丢弃、采用未知均不算改变 |
| 回退、失败、取消 | 回退按确认事项统计；失败、超时、取消按请求尝试统计，取消独立于服务失败 |
| 用量与费用 | 只取原 `usage_ledger`，按精确尝试身份关联；既有会话消费已经包含辅助调用，不再加第二遍 |
| 已知零／未知费用 | 供应商明确报价为零才是已知零；缺价格、在途及中断但未结算的发送请求显示未知 |
| 上下文占用 | 新观察事件为 `modelVisible: false`；辅助 Token 计入消费和任务预算，不成为主模型输入 |
| 历史记录 | 缺事项身份的旧调用单列为历史请求，不猜分组、应用、轮次和费用关系；覆盖不完整有明确提示 |

模型判断、实际处理、后续观察分别保存。判断详情只使用已有结构化答案和输入摘要哈希，不补写推理过程。会话证据去掉可能回显输入的自由文本 metadata，保留数值／布尔计数及脱敏事实。

## 功能接入

| 功能 | 确认边界 |
| --- | --- |
| decide 工具 | 答案交付给智能体；下游采用缺证据，明确显示未确认 |
| 建议、自适应思考 | 主聊天调用接收提示／思考覆盖；过期和未开始的聊天不确认 |
| 大结果筛选 | 宿主交付筛选结果；多批请求归同一事项，取消或旧进程结果丢弃 |
| 大结果摘要选择 | 当前请求接收摘要／预览分支；取消或旧进程返回丢弃，原摘要策略继续工作 |
| 运行中消息 | 确认转向接收、实际队列合并；模糊的 SDK 接收状态保持未知 |
| 轮次结果、语义标签 | 实际状态／标签变更；人工修改和新轮次后的晚到结果丢弃 |
| 智能标题 | 延迟命名、请求正常命名、刷新后的真实名称变化 |
| Guarded、风险标记 | 宿主权限分支和请求信息更新；审核不可用仍需人工确认 |
| 自动化条件 | 实际条件放行／跳过分支；有事件会话才进入对应 Run |
| 任务判定、修复 | 任务状态／节点处理和实际重调度范围；预算、停止与过期保护继续生效 |

无会话自动化继续使用既有历史的跳过原因和按 matcher 关联的诊断记录，不挂到当前聊天。归档会话仍可读；分支不复制父会话消费。删除会话清除新增决策明细并忽略晚到观察；通用账本与旧诊断日志沿用既有保留机制，不能据此声称全部历史已物理删除。

## 视图改版（2026-10-10）

Run → Decisions 的第一版是单列平铺：所有文字 11–12px、所有分区同一条 `border-y`、状态只有右对齐灰字、详情把原始 JSON 倾倒进 `<pre>`。改版按 [演示稿确认的方向 C](../design/decisions-view-redesign/README.md) 重建信息架构，并把组件规格全部对齐 Run 其余四个标签页（来源与逐条映射见该目录的 `index.html`）。数据契约未改动。

顺带修掉四个已核实的缺陷：

| 缺陷 | 后果 | 修法 |
| --- | --- | --- |
| `trajectory.decisions.status.applied` 键不存在 | 「已应用但未改变基线」是最常见形态，界面直接漏出键名 | 新增该键；状态推导同时认识 `applied` 与 `changed` 两级 |
| `failed` / `cancelled` 在行内状态里不可达 | `application.status` 的联合类型不含这两个值，按「失败」筛选会看到「未确认」徽标 | 宿主无处理结果时改看请求层：失败／超时→失败，取消→已取消，全部成功才是未确认 |
| 三个计数串缺复数形式 | 英文下出现 `1 model attempts`、`1 points · 0 changes` | 改为 `_one`/`_few`/`_many`/`_other` 四态键 |
| 详情倾倒原始 JSON | 可读信息被标点淹没 | 触发来源改为键值行，原始记录退到折叠里 |

证据与截图见 [结果目录](results/session-decisions-redesign/run.json)。该目录的 `run.json` 记录了本次命令、浏览器通道、20 项流程与五项 UI 检查覆盖的内容；截图覆盖浅／深色 1040px 与中文 480px 的列表、详情抽屉，以及概览的决策摘要。

## 可重复运行

在仓库根目录执行，下面的浏览器流程依次运行，避免 Vite 优化缓存被并发启动干扰：

```powershell
$env:PHANERIS_TEST_BROWSER_CHANNEL = 'msedge'
bun run scripts/verification/session-decisions-workflow.ts
bun run scripts/verification/ai-settings-structure-workflow.ts
bun run scripts/verification/decision-feature-workflow.ts
bun run scripts/verification/task-governance-workflow.ts
```

首项自行创建临时配置、工作区、受控 HTTP 决策服务、SQLite 宿主和带认证的 WebSocket 服务器；浏览器挂载真实 Run 面板并使用真实查询链路。输出位于 `.cache/session-decisions/`；其余流程使用各自已有的输出目录。可设 `PHANERIS_VERIFY_SKIP_SCREENSHOTS=1` 只重跑功能检查。

构建及实际 Electron 主进程／preload／renderer 验收：

```powershell
bun scripts/electron-build-main.ts
bun scripts/electron-build-preload.ts
bun run --cwd apps/electron build:renderer
bun run scripts/verification/session-decisions-packaged-workflow.ts --stage-from=E:/Phaneris/apps/electron/release/win-unpacked
```

`--stage-from` 复制现有 unpacked 运行时及资源到新临时目录，覆盖本次新构建的主进程、preload 和 renderer，随后用一次性 profile 启动。保留原打包目录和个人配置。也可用 `--app=<unpacked 目录>` 验证已有完整产物。此次检查没有重做或安装 NSIS 安装包，没有替换本机已安装版本；结果记录了运行时来源及新 bundle 的 SHA-256。
