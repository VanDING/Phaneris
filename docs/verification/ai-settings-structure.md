# AI 设置结构实施与验收

2026-10-05。已实现用户确认的“连接 → 会话 → 高级”，对应 [规划](../design/ai-settings-replan.md)。修改产品代码前的 [失败场景](./ai-settings-structure-failure-matrix.md) 和浏览器验收流程保留在仓库中。

## 已实现

- AI 设置仍为单页滚动；一级分区只有连接、会话、高级。高级下图像生成、决策辅助、缓存与运行优化默认收起，各自独立展开，可同时打开，没有重复的内层配置折叠。
- 会话区包含全局连接、模型、思考强度和上下文策略。上下文沿用公共设置行与右侧菜单，支持键盘选择及失败回滚。
- AI 页只保留当前工作区的模型设置入口及继承／例外状态；连接、模型、思考强度的工作区例外集中到工作区页。保留逐项恢复继承及实际生效值。切换连接在一次写入内清除不兼容模型，失败恢复原值，工作区切换隔离迟到的异步结果。
- 连接常驻信息压缩为身份与用途／状态两行。明确订阅登录、API 密钥、默认会话和图像用途；能力优先使用连接自己的模型目录，部分模型支持图像理解时明确标注，不把未知能力当作支持。
- 图像区展示实际自动账号／模型，或者明确保留失效的显式账号。没有兼容连接是中性未配置状态，提供定向接入入口，仅展示 OpenAI / OpenRouter API 密钥供应商。普通添加连接继续保留订阅等完整接入流程。
- 决策区在服务关闭时仍可准备配置；服务、凭据、模型与功能在同一展开区域。Guarded 的模式入口留在权限页，配置按钮只定位并展开决策辅助。状态加载失败可重试，不将 Guarded 标记为可用。
- 缓存和 RTK 设置保留，增加失败回滚与保存期间的操作限制。七个语言字典同步，清除已移除分区的失效文案。

## 可重复验收

在仓库根目录运行：

```sh
bun run scripts/verification/ai-settings-structure-workflow.ts
```

旧入口 `scripts/verification/ai-settings-refinement-workflow.ts` 转到当前流程，避免继续依赖已经移走的工作区卡片。主题预览流程的定位器也已适配新结构；本轮未重新生成主题候选或替换主题预览截图。

验收挂载实际 AI、工作区、权限页面及公共接入组件，使用隔离的内存传输、测试账号和测试工作区。没有读取或写入个人配置，也没有向模型供应商发起实际 API 请求。

| 检查 | 结果 |
| --- | --- |
| 浏览器工作流 | 20 / 20 通过，无未捕获页面错误 |
| 全仓 `typecheck:all` | 通过 |
| `lint:electron` | 通过，无错误；保留原有警告 |
| 本轮相关文件 lint | 通过，无错误；`ApiKeyInput` 有一条既有依赖警告 |
| 国际化键一致、排序、覆盖、失效键检查 | 四项均通过；每个字典 2430 个键 |
| 浅色／深色 1040px，中文浅色 480px | 截图已人工检查，无横向溢出和缺失翻译 |

20 个流程覆盖分区顺序和独立折叠、上下文鼠标／键盘与失败回滚、工作区页面归属及继承、一次写入清除模型、保存失败与工作区切换、订阅连接的中性图像引导、供应商过滤、提交接入后默认会话保持不变、工作区加载失败重试、图像账号／模型保存与失效保留、图像加载失败重试、关闭时配置决策功能、权限页精确跳转、决策加载失败重试、连接身份和验证菜单、缓存／RTK 回滚，以及三种屏幕组合。
