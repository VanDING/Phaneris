# 会话启动与 thinking 活动：实现前失败矩阵

2026-10-23。依据[六例复核](session-start-latency-review-2026-10-23.md)，在现有 harness 分支实施。用户已明确 thinking 与其他活动一样，默认一行，点击进入现有全屏详情查看；**不做列表内展开**。后续视觉更正：使用普通活动行的图标和文字，不添加专用背景、边框或标签；不同请求的思考与工具按实际顺序交错。保留默认 skill 不发现、不主动启用的设计，不调整用户的 max 或生产连接。

| 失败场景 | 必须验证的结果 |
| --- | --- |
| provider 只输出 thinking，暂未产生正文 | 真实 Pi/Host 收到 thinking 增量；客户端活动列表立即出现内容，不等待正文或完成 |
| 10 万字符 thinking 高频输出 | 只传增量，宿主批量转发；一段思考只有一行，无累计 partial 的平方流量 |
| thinking→正文→工具→下一次 thinking | 活动顺序与模型输出一致；思考不进入最终答案或被误当成正文 |
| 点击正在流式或已完成的思考行 | 进入其他活动使用的详情查看入口；键盘同等可用，不在活动列表内展开 |
| 取消、错误、重试、重载、切会话 | 已接收内容可恢复；不复用上次请求的增量或重复累加终态内容；状态不永久转圈 |
| 无思考或仅提供隐藏/签名块的 provider | 不伪造思考正文，不生成空白活动 |
| 中文正文少于五个空白分词，随后流暂停 | 缓冲有真正的时间上限，时间到达可主动刷新；完成态立即显示 |
| 区域截图/CDP/capture 永不返回 | 有界失败并能继续，后续批次不继续执行；不能把等待超时当作外部操作一定没有执行 |
| 浏览器批次中取消或一项失败 | 已完成步骤保留；停止后不再发起后续步骤，返回已知结果可结算，未知效果保留 reconciliation |
| 已停止的代理工具迟到返回错误结果 | 错误与成功一样可记为实际 T2，不能因 isError 就永远留下 effect_pending |
| 新轮次遇到 recovery_parked | 保留现有恢复详情入口和明确状态，不能清空未知副作用以强行继续 |
| DeepSeek 自定义连接选择 off | 已识别的 DeepSeek 兼容格式显式关闭；保留 max，不向其他兼容端点猜测添加私有参数 |
| 自定义端点使用 OpenAI auth 命名 | 不因此优先选择未验证的 OpenAI utility 模型，明确配置的 utility 仍优先 |
| 旧会话含已有 outputBlocks.thinking | 无需数据迁移即可显示，Viewer/WebUI/Electron 共享同一活动投影 |

先运行现有代码以记录失败，再修复。优先真实 Pi/SQLite、真实组件浏览器与原生 Electron 验证，保留 manifest、截图和调用轨迹。不以 fixture 推理替代线上长篇思考因果验证，不宣称更换 API 已被验证。

错误与重试沿用既有 `text_discard`：撤销未完成的失败尝试，不将其思考或正文增量拼入下一次请求。停止场景则保留已接收内容。
