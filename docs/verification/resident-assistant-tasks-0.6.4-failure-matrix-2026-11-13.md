# 0.6.4 助手任务管理失败矩阵

日期：2026-11-13，Asia/Shanghai。实施前基线：`f79e18f28`。

本矩阵先于产品修改建立。隔离 Host / RPC / Runtime 验收不读取真实 Work 数据、不调用付费供应商。受控供应商验证真实执行链路，不代表真实模型的管理质量。

| 编号 | 失败方式 | 必须验证的事实 |
| --- | --- | --- |
| TM01 | 隐藏助手的工作被当作无父卡的 subtask 隐藏 | 新旧直接子工作成为 Board 主卡；Session 的真实 parentSessionId 不变，来源可追溯 |
| TM02 | 根据父项是否在当前列表里决定升根 | 普通 P→Q、助手→A→A1 继续收纳；搜索、过滤、归档均不释放普通子项 |
| TM03 | handoff 被当作新工作 | handoff 接续不新增主卡 |
| TM04 | 委派输入与 Session 规划不一致 | 新工作 description / acceptanceCriteria 与委派要求一致；接续既有 Session 保留规划字段 |
| TM05 | 已保存委派输入被算成完成 | 排队子项不会仅因 messageCount>0 显示完成；运行、错误与真实结果分别取证 |
| TM06 | 最终回复等同业务完成，或结果始终停在 todo | 结果就绪进入 needs-review；必须明确复核通过才进入 done；单纯 ACK 和成果选择不关闭工作 |
| TM07 | 返工创建第二份任务或重放原始效果 | 复核不通过回到 open，后续沿用原 Session；旧结果不能再次通过复核关闭返工 |
| TM08 | 取消受理先于执行结算就关闭工作 | 仅在执行停止且无未结算工具效果时进入 cancelled |
| TM09 | 旧结果覆盖新用户输入或人工状态 | 复核检查原输入、最新结果、seq、后续直接输入与状态所有权；冲突拒绝且保留人工状态 |
| TM10 | 重启丢失状态或重复复核 | 同一结果复核幂等，结果/状态可恢复，显式暂停不自动启动 |
| TM11 | 全局串行门阻止独立工作 | 至少两项真实 Runtime 模型请求区间重叠；最多占用公布容量，其余显示容量等待 |
| TM12 | 仅删除串行门导致共享写入冲突 | 复用现有文件范围 lease；共享只读可并行，写/读和写/写冲突等待，无关资源可继续 |
| TM13 | 依赖只是展示信息却声称已生效 | 若接入自动依赖，只有成功完成前置工作才启动；失败/取消/缺失明确等待；循环拒绝 |
| TM14 | 总览把 agent 存在当运行、手算时间失真 | 有界投影使用 Runtime 事实、Host 当前时间、实际占用、等待原因及省略数量 |
| TM15 | 权限配置与快照失配，错误不能定位 | Worker 直接改模式、启动 clamp、收紧响应边界分别复现，返回具体失效项；无关分支变化不影响任务 |
| TM16 | 用户修订只出现在主助手回复 | 排队/运行中的指定工作有真实命令及应用回执；优先级安排改变待启动顺序 |
| TM17 | 内部回执被拒绝合法接续或创造新授权 | 核验原始用户输入与原目标范围，允许原授权后续工作；拒绝内部报告产生新授权及重复派发 |
| TM18 | 受控 Worker 代替真实多轮管理质量 | 单独记录真实主助手与真实 Worker 样本、模型调用及实际产物；未运行不得声称本项通过 |

## 真实样本补充证据

2026-11-13：官方 DeepSeek 两次 HTTP 402 后，用户明确选择已配置的 Command Goat。真实并行、queued 修订和原授权分阶段续办共 3 个样本 / 7 项检查通过，原始输入、模型请求、Runtime/Session 结果和账本见实施记录。

真实失败新增固定：goalQuote 只包含第一阶段时，后续阶段被 Host 正确拒绝；不能用 instructions 的更宽说明、替换 quote 或 worker_control 绕过。schema/角色契约现明确整项目标与当前执行范围。另固定已复核原 Session 在新阶段运行时仍显示 done 的问题：新输入与 todo/guard 同写后开始，人工改状态仍保留；新增管理场景验证。

最终强化验收：通知必须为 delivered，主助手轮次已停止，delivery 引用的实际回复包含任务结果。另固定三类失败：同一 Session/消息结果的 JSON 字段顺序导致续办误拒；无 manifest 的纯文字结果选择零文件时阻断回执；复核理由重述被误当成改变结论。当前分别按字段身份、显式零文件和保留首次理由实现，反向结论仍拒绝。取消请求在重启或持久化等待后继续结算，未知效果的资源范围在 cancel_requested 期间继续占用，不因中间状态变化放行冲突任务。
