# C02 日历与工作项性能：实施前失败矩阵

状态：accepted — 2026-10-14，先记录失败方式与测量口径，再修改产品实现。当前授权及收口状态见[统一台账](../process/implementation-value-register-2026-10-13.md)。基线为 `19e730ffe` 的既有未提交工作区；保留 R01–R07 和其他并行工作。

| 编号 | 必须覆盖的失败方式 | 验收方式 |
| --- | --- | --- |
| C02-01 | 日历同时全量读取 calendar 与 workItems；同工作区多消费者重复读取 | 同一合成样本三次打开日历，记录实际 RPC 次数、字节、handler/投影耗时及可见条目 |
| C02-02 | handler 立即广播与 SessionManager 延迟广播重复；跨工作区合并互相遗漏 | 真实 SessionManager、真实 RPC：一次编辑 / 短时批量编辑仅由宿主合并通知，每工作区每兼容通道一条 |
| C02-03 | 两个窗口或列表/日历/甘特消费者各自缓存后数据分叉 | 两个真实 WebSocket 客户端，改期、标题、归档和删除后可见值与 Session 一致 |
| C02-04 | 绕过 calendar/workItems handler 的 Session 修改不失效 | 经 Session 原生修改与外部元数据恢复链路，验证各投影刷新 |
| C02-05 | 切工作区后迟到读取/写入污染新工作区 | 阻塞旧读取、切换作用域、完成旧请求，验证新工作区保持独立 |
| C02-06 | 读取过程中收到失效信号被吞掉或造成请求风暴 | 真实 handler 快照后延迟响应，连续写入；保留最终状态，最多一个在途读取及一个必要后继 |
| C02-07 | 本地成功修改被旧快照覆盖；删除项复活；初始读取并发写入丢其他行 | 现有甘特工作流与交互读取竞争；保留 R06 的改期、回滚和重挂载保护 |
| C02-08 | 日历创建变成独立存储；删除日程误删会话；修改丢项目/说明/时间 | 日历读写仍投影到同一 Session，清除日程只清日期；核对磁盘与其他视图 |
| C02-09 | 读取失败永久锁死、只剩 loading；重连沿用过期缓存 | 一次真实 RPC 故障、后续刷新与实际断线重连；保留错误与恢复事实 |
| C02-10 | 写入失败伪装成功、清空原值或静默失去错误说明 | 注入写入拒绝，真实日历/甘特交互验证提示、回滚和持久值不变 |
| C02-11 | 退订后仍无限监听/拉取；视图切换或 StrictMode 产生重复监听 | 离开全部消费者后写入不拉取，再打开一次获取最新值；保留订阅与请求计数 |
| C02-12 | 共享投影遗漏隐藏/归档/draft 过滤，日历打开清空列表筛选或选择 | 固定可见/不可见/未排期数据，跨视图筛选与选择回归 |
| C02-13 | 日期格式、末日、offset、DST 或无时间日程因统一投影改变 | 既有日期/日历事件回归及真实投影字段比对；保持 R06 已验证语义 |
| C02-14 | 旧 calendar RPC 或只订阅旧通道的消费者失效 | 保留现有通道；旧客户端写入、现代投影刷新与兼容广播可核查 |
| C02-15 | 平均值掩盖慢样本、放宽预算、开发冷编译被记为产品收益 | 同机、同数据定义/摘要的生产 WebUI，保留各次原始样本；沿用暖切换 2000ms、输入至两帧 250ms、heap 256MiB、后端 RSS 1024MiB |
| C02-16 | 没有归因就引入日期索引/永久缓存/新事实仓；旧结果被覆盖 | 先测重复读取/广播，优化后再决定范围查询；Session 唯一事实来源；独立 before/after 目录和 SHA |

测量使用独立配置、固定合成工作区及回环服务；不读取个人工作区或调用付费 provider。导航首次加载仍单列原始值，不把无关冷启动问题计为 C02 的改善。工作流结束保留可重复的 JSON、生产构建摘要、trace 和必要截图。
