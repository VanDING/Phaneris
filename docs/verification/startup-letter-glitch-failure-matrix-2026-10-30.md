# 启动字符背景：实施前失败矩阵

用户确认白色 Letter Glitch：加载阶段只有字符，实际就绪后在同一背景上播放 Logo，然后进入应用。替换小型 Loading 窗口与独立 Logo 启动页。

状态：Windows 原生启动工作流 13 项已通过，见[实施与验证记录](startup-letter-glitch-2026-10-30.md)。

| 场景 | 必须满足 | 验证方式 |
| --- | --- | --- |
| 后端启动慢 | 正常尺寸的白色字符界面持续显示，无 Logo、无 Loading 文案 | 原生 Electron，延迟就绪并截图 |
| 渲染器加载慢 | 应用首帧不能提前盖住启动界面 | 原生 Electron，业务窗口可绘制但未发送就绪 |
| 实际就绪 | 同一 canvas 保留，才开始 Logo 描边与填充 | 比较就绪前后 canvas 身份，记录动画阶段 |
| 快速就绪 | 等待实际 Logo 入场完成再交接，不使用启动最短等待计时 | 原生 Electron，立即发送就绪 |
| 最终交接 | 业务窗口接管，启动窗口销毁，无残留窗口 | 原生 Electron 窗口与可见性断言 |
| 非工作区入口 | 引导、重新登录、工作区选择和可重试错误都能交接 | 渲染就绪条件检查与原生应用冒烟 |
| 减少动态效果 | 字符静态，Logo 无描边动画，不额外等待 | 原生 Electron reduced-motion 场景 |
| WebGL 不可用 | 仍有静态字符背景，正常交接 | 禁用 WebGL 原生场景 |
| 多窗口恢复 | 只播放一次启动动画，其他窗口在交接后展示 | 原生 Electron 双窗口场景 |
| 关闭与失败 | 关闭启动窗口会取消启动；页面失败不能留下永久遮挡 | 原生 Electron 关闭、加载失败场景 |
| 隔离与离线 | 启动页面无 Node、preload、RPC；字体与脚本本地加载 | 打包构建 CSP 与原生沙箱断言 |
| 正常主题 | 启动固定白色，进入应用保留用户主题 | 原生截图与主题就绪回归 |

重复命令：`bun run scripts/verification/startup-feedback-workflow.ts`。产物使用 verification-artifacts 目录，保留截图、阶段与窗口交接证据。

## 2026-11-02：中央 LOADING，实施前追加

用户确认第二版演示：加载阶段在字符网格正中固定 `LOADING`，使用深紫色 `#4c296f`，其他视觉参数不变。本次要求取代上表最初的“无 Loading 文案”。

| 失败场景 | 验收要求 |
| --- | --- |
| 单词叠在随机字符上或字体不一致 | 七个字母占用原 atlas 的七个网格单元，字号、字重、间距与背景相同 |
| 窗口宽高或 DPI 改变 | 始终居中，不放大或位移；与演示相同的奇数行列网格 |
| 颜色或呼吸与确认版不符 | 仅单词使用 `#4c296f`；3.2 秒透明度呼吸，范围 0.30–0.64；原背景色和动效参数保持不变 |
| 指针或故障闪烁改写单词 | 七个字母固定，不受随机替换、热度或指针影响 |
| 就绪时单词与 Logo 重叠 | 单词淡出，Logo 按演示延后 200 ms 开始原有动画；同一 canvas 保留 |
| GPU 不可用或上下文丢失 | 仍有居中的 LOADING，与静态背景和后续 Logo 正常交接 |
| 减少动态效果或加载期间切换偏好 | 停止呼吸，单词保持可见；就绪时正确清除，不留下叠字 |
| 真实应用目的页 | 工作区、首次引导、最终主题和字体就绪条件不变，无重复背景或启动窗口 |

2026-11-02 结果：上述追加要求及原有窗口生命周期共 13 项 Windows 原生启动检查通过；证据目录与边界见[实施记录](startup-letter-glitch-2026-10-30.md#2026-11-02确认版-loading-接入)。
