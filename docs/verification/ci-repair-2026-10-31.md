# CI 修复：失败矩阵与验收

起点：`origin/main` 的 Validate 运行 `40770629056`，提交 `40c2e0876`。本次同时交付已确认的白色字符启动界面。

| 已观察的失败 | 修复目标 | 验证 |
| --- | --- | --- |
| Web UI 类型检查无法解析启动组件的 JSX 供应商模块 | 提供真实组件参数声明，并保留共享 App 的启动就绪交接 | 全工作区类型检查、Web UI 构建 |
| 三个平台主题验收仍等待已移除的 `ink` | 验证 Default 深浅模式、旧 ID 归一化与浏览器主题交付 | 原生主题工作流，不跳过旧 ID 场景 |
| 文档链接指向未纳入 Git 的 `.cache` | 本机路径明确标注为本机产物，不作为可移植仓库链接；门禁拒绝此类链接 | 干净检出文档检查 |
| macOS 连接探测被 30 秒 RPC 截断；补齐观察后，Pi 子进程报 Electron 加载错误 | RPC 运行时上下文必须保留平台选择的 Bun 路径；探测通道时限覆盖服务端预算，其他通道保留原时限 | 实际原生 Pi 探测；真实 WebSocket 延迟响应超过 30 秒仍完成，普通通道仍超时 |
| 依赖审计新增高危/严重公告 | 更新修复版本，保留不同 undici 主版本，限制强制更新到 Pi 的旧精确固定项 | 审计、固定锁文件安装、运行时与打包版本检查 |

RPC 时限实现前的边界：探测成功与错误都应原样传递；普通请求仍使用调用者配置的时限；断开后不得残留请求；不可通过增大全局时限掩盖卡住的普通请求。

执行结果在完成验证后补充。产物写入 `.cache/verification/`，不随 Git 仓库分发。
