# 数据源激活后会话静默阻塞修复

## 结论

这次故障包含两个连续问题：激活重启提前释放了宿主回合；随后到达的真实结算恢复了数据库检查点，但内存阻塞状态未刷新。自动续接被拒绝时又缺少可见错误，最终表现为只能重启应用。

会话 `261016-steady-glade` 的只读证据见[失败矩阵](source-activation-settlement-failure-matrix-2026-10-16.md)。关键区别是：模型请求并非一直没有结算，而是在挂起 **19 ms 后**已写入 `aborted` 结算；SDK 也随后正常停止。

## 修复行为

| 位置 | 变化 |
| --- | --- |
| Pi 子进程协议 | `abort` 支持关联 ID；等待 SDK `session.abort()` 完成后返回 `abort_result` |
| 激活重启 | 保留同批工具结果；先停止并确认结算，再发布 `source_activated`，随后进入原有隐藏重发路径 |
| 消息准入 | 用已有 `refreshRecovery()` 重新核对持久化状态，使已收到迟到结算的会话直接恢复接收消息 |
| 失败反馈 | 停止确认超时、子进程退出和自动重发拒绝都会产生可见错误；失败重发释放去重占位 |
| 生命周期 | 停止确认有 5 秒上限；销毁、重连及进程退出会清理等待者；用户主动停止优先于自动续接 |
| 国际化 | 两条错误提示覆盖现有全部语言；检查器纳入实际产生会话错误的 `server-core` |

没有跳过结算、推断“未计费”或自动放弃未知操作。仍未收到模型结果、或仍存在未知工具副作用的会话继续要求恢复对账。
