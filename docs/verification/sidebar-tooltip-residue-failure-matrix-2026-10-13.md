# 侧栏收起后的 Tooltip 残留：失败矩阵

状态：实施前定义。基于已合并的 `e27698d91`。问题由实机截图确认：收起侧边栏后左侧轨道同时出现多个提示标签。

根因（已由探针证实）：`786bf6d08` 把 `LeftSidebar` 的 Tooltip 从"仅收起时挂载、非受控"改成"常驻、受控"（`open={isCollapsed && tooltipOpen}` + `onOpenChange={setTooltipOpen}`）。展开态下受控值恒为 `false`，而 Radix 的 `useControllableState` 只在 `next !== prop` 时才回调，于是指针或焦点离开时触发的 `setValue(false)` 被静默丢弃，`tooltipOpen` 永久停在 `true`（闩锁）。收起瞬间所有被闩锁的行在同一次渲染里 `open === true`，一次性挂载各自的标签；指针不在这些触发器上、也没有 `TOOLTIP_OPEN` 派发，因此无人关闭。

只有顶层轨道行肉眼可见：子行（状态、来源、自动化子项）由 `renderExpandedContent` 以 `isCollapsed={false}` 渲染，其提示永远不会挂载——这解释了截图里恰好是那排图标。

| 场景 | 可能失败 | 验收 |
| --- | --- | --- |
| 展开态悬停后收起 | 顶层行停留 ≥300ms 即闩锁；收起后挂载出用户没要求的标签 | 指针停在内容区、键盘收起，逐帧提示内容节点恒为 0 |
| 展开态键盘聚焦后收起 | `onFocus` 直接打开（无延迟），同样闩锁 | 聚焦行收起后不产生提示 |
| 收起态悬停 | 修复把正常提示一起关掉 | 收起态悬停仍显示，且恰好 1 个，文本等于该行 `aria-label` |
| 离开轨道 | 收起态提示不关闭，变成新的残留 | 指针离开后 0 个 |
| 收起→展开 | 展开态残留提示内容 | 展开过程与展开后均为 0 个 |
| 子行 | 用统一选择器扫行时把永不显示的子行当作场景，掩盖真实残留 | 场景只使用顶层轨道行（`nav[aria-label="Main navigation"] > .sidebar-section > .sidebar-nav-button`） |
| 按钮 DOM 连续性 | 用"条件包裹 Trigger"换回非受控会重建按钮节点，丢失焦点与插值 | 两态保持同一按钮节点（沿用既有断言） |
| 收起态键盘可达 | 修复后收起态键盘聚焦不再显示提示 | 收起态聚焦仍可打开提示 |
| 既有治理 | 覆盖 `sidebar-style-transition-2026-10-12` 已登记的档案 | 原目录与 SHA 不变；新证据写独立目录 |
