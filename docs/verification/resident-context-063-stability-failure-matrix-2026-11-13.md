# 0.6.3 上下文展示与稳定性专项失败矩阵

范围：收回助手上下文管理前台 UI；只读分析当前安装版会话与卡顿；在隔离数据中复现和修复已确认的问题。保留上下文核心、原始会话和执行事实，不清理用户数据库，不替换安装版。

## 实施前固定的失败方式

| 场景 | 失败方式 | 验收 |
| --- | --- | --- |
| S01 精确来源读取 | MemoryStore 为单条来源读取、解码整个 Session，绕过 SourceReader 的按需读取收益 | 通过真实 MemoryStore 入口精确读取，预热索引后只解码目标记录，不随无关历史增长 |
| S02 共享依赖图 | 同一同步验证内重复递归验证已成功的共同祖先，工作量随路径数膨胀 | 多层菱形图只验证不同来源；记录读取和缓存计数、耗时 |
| S03 缓存有效期 | 验证缓存跨边界保留，使原文修改、删除或遗忘未被发现 | 后续边界立即拒绝旧版本；原有来源回归覆盖删除、遗忘和 workspace 隔离 |
| S04 来源环 | 验证缓存掩盖自引用/循环，使派生来源被错误接受 | 环仍拒绝；错误后独立来源正常读取 |
| S05 上下文 UI | 仅隐藏按钮，仍保留前台分支控制或引入布局空位 | 桌面、窄窗口无上下文入口；头部保留 More / Share / Close；上下文 Host 命令和模型分支仍通过回归 |
| S06 回执 | 用延长 15 秒超时掩盖主进程同步阻塞，或自动重放不确定效果 | 保留 Runtime 的执行边界和恢复行为；不自动重放；用时间戳对比区分已观察超时与推断原因 |

## 调查基线

- 源码 HEAD：`48c2450ed`；安装版 package.json：`0.6.3`。
- 助手原文：1,834 条消息，21,301,553 字节；16 条顶层错误包含 8 次 API 请求拒绝、5 次上下文失效、3 次 Runtime 回执不可用。历史跨越 0.6.3 安装前，不能全部归因于本次发布。
- 2026-11-13 实际 ContextView 记录：读取 42,599,740 字节、解码 3,669 条记录；其中首次索引扫描 21,301,551 字节。
- Runtime 派发快照 `capturedAt=1794538019035`，提交 `createdAt=1794539105434`，相差 1,086,399 ms。子进程握手默认超时 15,000 ms；这证明派发边界发生长延迟，不单独证明全部延迟由某个函数造成。
- MemoryStore.readSource 在单条读取边界循环 `reader.catalog(...).entries`，逐条 `reader.read(...)`；派生来源验证也未对已成功的共享祖先作边界内去重。

原始私人会话与本机数据库保持在用户目录；提交的验收材料仅使用合成数据，不复制私人对话正文。
