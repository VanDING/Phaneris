## 修复前失效矩阵（首轮）

| 场景 | 发现 / 风险 | 验收证据 |
|---|---|---|
| 固定高度内切换五个标签 | 内容容器缺少 flex 纵向约束；`.pane` 覆盖原生 `hidden` 显示规则 | 滚轮确实改变内容 scrollTop，页头固定，非活动标签不可见 |
| 展开 Context 分类 | 分类、条目、工具栏、正文多重嵌套；正文又有独立滚动 | 仅分类可折叠，条目直接阅读，正文随 Run 主内容滚动 |
| 长历史 / 长正文 | 每分类只显示 50 条且无法继续；阅读模式只显示前 12 段 | 分批加载完整历史；长正文明确预览并可查看全文 |
| 跨请求比较 | 请求级 system/schema ID 无法匹配上一请求；只比较字符数 | 同长但不同正文报告变化，同内容报告未变化 |
| Decision 筛选加载/失败 | 首次过滤未返回 report 时回退未过滤数据，掩盖加载与错误 | 延迟期间不显示不匹配记录；失败可重试，统计卡保留 |
| 300 请求趋势 | 总量峰值抽样可能吞掉压缩及最大的负变化 | 压缩标记按桶保留；变化模式保留最大绝对变化，点击对应请求 |
| 剪贴板不可用 | optional chaining 后仍显示复制成功 | 不虚报成功，原文可选择 |
| 窄屏 / 深色 / 键盘 | 修复布局后可能出现溢出或焦点回归 | 390/600/1280px、两种主题、分类/标签键盘验证与截图 |

先扩展既有端到端工作流并运行修复前基线，再修改实现。结果补充于本文件末尾。

## 首轮修正（Context 阅读方案由下方追加反馈更新）

- **P1 · Run 滚动**：接通 `runMain → pane → view` 的 flex 高度约束；为缓存标签补充作者级 `[hidden]` 规则。页头和标签固定，活动内容独立滚动。
- **P1 · 决策筛选**：过滤请求拥有自己的加载、错误与重试状态，不再回退显示未过滤事项；概览的失败提示打开 `failed`，回退提示打开 `fallback`；补回取消筛选。
- **P2 · Context 阅读路径**：只保留分类折叠，条目直接阅读；去掉条目折叠、工具栏/正文重复边框及正文内滚动。关闭分类时不挂载正文。
- **P2 · 内容可达性**：50 条一批加载旧记录；长正文明确标注 6,000 字符预览并可查看全文；取消 12 段静默截断。复制失败明确提示，原文保留可选择。
- **P2 · 证据准确性**：系统提示按分类、工具定义按名称匹配上一请求，比较保留正文而非仅比较长度；无工具完成证据时不显示成功。未选定/已失效的请求选择回到最新可用请求。
- **P2 · 趋势**：总量按桶保留峰值，净变化按桶保留绝对值最大变化；压缩标记按请求区间保留；超出窗口的总量不被纵轴裁平。请求范围与实际打开的代表请求同时显示。
- **P2 · 决策详情**：恢复建议/处理的结构化依据、后续观察、费用缺失原因与完整原始记录；没有已知费用样本时显示未知。
- **维护**：清理 147 个随旧视图删除后失效的翻译键；另有 13 个键随诊断证据恢复而重新使用，未以白名单绕过检查。

未新增页面级标题、重复摘要、导出入口；Trajectory 和 Map 的内容布局未改，只修正其共享标签容器。

## 最新请求窗口容量 · 追加核查

SDK 的 `getContextUsage()` 同时返回占用和完整模型窗口；`contextFromPi()` 目前只保留减去 reserve 后的压缩阈值。Pi adapter 的另一路窗口缓存仅靠静态模型注册表或切换模型回执填充，因此部分模型虽然返回了容量，Run 仍显示未记录。另发现 durable usage 重投影没有保留 `contextUsage`。

先补充以下失效场景并运行失败基线，再修改实现：

| 场景 | 验收 |
|---|---|
| SDK 256K 窗口 / 240K 压缩阈值 | 两者分别保留，不把阈值当完整容量 |
| SDK 切换窗口 / ledger 残留旧容量 | 新的 SDK 容量优先 |
| 压缩后占用未知 | 容量仍保留，占用不回退旧数值 |
| durable usage 重投影 / JSONL 重载 | 容量与 occupancy 快照均保留 |
| SDK 128K 窗口 / 最新请求输入 41.3K | Run 显示 32.3%，空余 86.7K，实际色条约占 32.3% |
| 旧记录只有压缩阈值 | 不推算完整窗口，不显示虚构百分比 |

卡片继续表示最新一次请求输入相对完整窗口的占比；SDK 实时占用在模型生成、工具执行和压缩后可能不同，不能替换这张卡片的分子。

核查结果：完整窗口不是无法获取，而是原始 SDK 元数据在归一化时丢失。已给 occupancy 快照增加独立的 `contextWindow`，在 Pi adapter、会话事件和持久化/重投影中保留；renderer 优先使用当前 SDK 窗口，兼容旧 ledger，绝不使用压缩阈值推算完整容量。

修复前的 浏览器基线（运行时生成，不入库） 复现缺失窗口；边界测试也复现 SDK 窗口丢失、压缩后容量丢失、旧 ledger 容量压过新 SDK 与 host 未更新容量。首次修复后的浏览器实测还发现分类最小宽度把色条从 32.27% 撑到 33.08%；已移除最小宽度和占空间的分隔间隙，以内部阴影分隔分类，保持真实占比。小分类仍可通过图例访问。

兼容边界：旧会话若从未保存完整容量，不从压缩阈值或模型名称猜测窗口；下一份新 SDK 快照会自动补上。未改全局模型默认窗口。

追加验证完成：最新报告（运行时生成，不入库），断言（运行时生成，不入库），完整窗口截图（运行时生成，不入库）。真实 Run 组件的浏览器验证 **33/33 通过、23 张截图、0 个执行错误**；SDK snapshot / adapter / 会话账本与重载 / renderer 的相关回归 **117/117 通过**。全量类型、lint、Pi 子进程构建、Electron main 与 renderer 构建均通过，日志已随 manifest 登记。

浏览器证据明确使用 128K SDK 完整窗口、112K 压缩阈值、45K 实时占用和 41.3K 最新请求输入四个不同数值：卡片显示 `41.3K / 128K · 32.3% · 空余 86.7K`；色条实测 32.2534%（像素舍入），压缩后实时占用未知也不会改变这次已完成请求的数据。本次已重建开发目录产物，未重启客户端或打包安装器；未调用真实供应商 API。
