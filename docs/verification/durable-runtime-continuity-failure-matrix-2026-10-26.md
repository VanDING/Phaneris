# Durable Runtime 连续性修复失败矩阵

Status: accepted — implementation authorized on 2026-10-26; declared before production changes.

基线 `bc2f436a0`。真实现场为 `261026-prime-iron`：应用正常退出后工具结果晚到，旧调用缺少回执导致整段会话挂起。验收同时要求不盲目重复外部动作、保留真实结果、用户自然继续任务，不以人工核对为前提。只在隔离工作区进行故障注入，不改真实会话数据库。

| ID | 实施前确定的失败情形 | 验收行为 |
| --- | --- | --- |
| RC01 | Ls / tool_search / 任意工具有旧 T1 无 T2 | 历史未知不占据前台；下一输入、模型请求和无关工作可继续 |
| RC02 | 老调用结果未收集，provider 需要完整调用/结果配对 | 工作上下文明确表达结果未知，不伪造业务成功/失败；迟到真实结果替换缺失视图，不重复调用 |
| RC03 | 本轮结算提交失败，存储随后恢复 | 自动重试结算，释放已结束的执行位置；不残留 accepted + blocked |
| RC04 | 模型已经返回成功，结果或计量提交失败 | 原响应照常交付；保存待补写收据并自动补写，不丢结果、不虚构 ledger 序号 |
| RC05 | 宿主已收到工具结果，补写失败或 ACK 丢失 | 已知结果保留并自动补写；仅重试写收据，不重新执行工具 |
| RC06 | T1/T2 内部 RPC 不返回、被取消或进程关闭 | 有界等待和明确取消结算；不能无限等待；未确认动作不自动重放 |
| RC07 | 输入收到但消费/回执不确定，随后重启 | 原始要求继续可见并由系统恢复；不要求用户检查后重发，不把未知效果当成重放输入的理由 |
| RC08 | 接续时存在历史未知调用 | 新会话仍可携带任务事实与未知说明，禁止仅因历史收据不足拒绝接续 |
| RC09 | 一个工作区数据库打不开、损坏或投影不可用 | 隔离故障、自动选择可用恢复存储，原库保留；其他工作区和正常会话初始化继续 |
| RC10 | 正常退出时 PowerShell/Python 仍在运行 | 先取消/等待实际 SDK 执行收尾再拆通道，允许迟到收据入库；避免 shutdown 后立即杀掉收据进程 |
| RC11 | 用户继续后，旧调用迟到、旧 observer 或旧代次回调到达 | 可补写原操作，不能结束新一轮或覆盖新输入；效果不重复 |
| RC12 | 模型尝试重复一个结果未知的非幂等动作 | 仅限制该具体动作，返回可处理的工具反馈；不冻结整个会话，不要求填写内部核对表 |
| RC13 | 已有历史/压缩、工具结果与恢复后的 native journal 不一致 | Pi 保持工作上下文所有权，真实原文和结果不被旧投影覆盖；完整工具配对与原生压缩回归通过 |
| RC14 | UI 把后台恢复变成必须由用户完成的审计流程 | 普通对话不再提供强制 reconciliation 操作；未知结果为准确状态，恢复由系统负责 |
| RC15 | TaskRunner 重启时已有运行中节点，或创建子会话后尚未记入调度回执 | 复用同一调度身份与已有子会话；已有完成结果直接使用，未完成工作在原会话检查续做，不要求人工核对 |
| RC16 | TaskRunner 的事实提交暂时失败，canonical 日志落后于 JSONL | 执行与结果保留，下一边界自动补写；重启读取完整事实，不能因较旧 canonical 投影丢失节点完成结果 |

RC15–RC16 在连续性回归发现 TaskRunner 同类阻塞后补充，先于该路径的生产代码修改与独立验证工作流。

采用既有 VerificationRun、真实 Runtime/SQLite/Pi 子进程、文件与受控 provider；保存重复运行命令、原始输出与 SHA-256。真实 provider 质量、签名和跨平台发行单独列出，不以 fixture 通过替代。
