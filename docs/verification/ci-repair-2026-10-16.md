# CI 修复记录（2026-10-16）

工作延续至 2026-10-17 凌晨。基准：本地 231a7942b，远端 origin/main 为 5781218ce。
远端原始失败运行：[Validate / 38677812473](https://github.com/VanDING/Phaneris/actions/runs/38677812473)。

## 修复内容

| 根因 | 修改 |
| --- | --- |
| unzipper 在未使用的 Open.s3_v3 分支 require 可选 AWS SDK | 在 main 打包中保留该可选适配器为 external；本地档案路径不加载它，不新增整棵 AWS 依赖 |
| 容器安装 node-pty 时缺 make | frozen install 前安装 Python、make、g++；补充 Docker 输入门禁及真实独立安装 main 构建 |
| Linux 关键原生浏览器工作流没有显示服务 | test:critical 置于 Xvfb；进程失败先报告 stderr，再读取结果 |
| Linux 脚本沙箱缺依赖/用户命名空间 | CI 显式配置 bubblewrap；临时 runner 允许其所需命名空间 |
| /tmp 后挂载覆盖会话 bind | 先准备系统临时目录，再挂载会话及可写路径 |
| tee 覆盖验证程序失败 | 含日志管道的步骤显式使用 Bash，启用 Actions 默认 pipefail；门禁和负向变体防止退化 |
| Windows 多条原生命令只传播最后一条退出码 | i18n、版本检查、跨平台回归步骤使用显式 Bash，任一命令失败即停止 |
| 构建在验收启动前失败，没有证据目录 | checkout 后初始化源码证据；原生构建输出 tee 到验证目录；继续保持“缺证据即失败” |
| setup-uv 的环境变量使 Node 环境测试不确定 | 对“不新增 Python 变量”的原有测试传入显式空环境 |
| Linux 执行 Windows 大小写路径语义断言 | 原有 Windows 专属用例只在 Windows 执行 |
| Windows 生命周期夹具以 kill(SIGTERM) 模拟正常停机 | 测试专用 preload 派发同一停机信号处理器；仍要求真实子进程退出码 0 |
| Pi 固定 500ms 后注入全局故障 | 等待真实启动标志再注入，避免在模块加载期间触发默认处理器 |
| 新增安全公告 | proxy-addr 2.0.8、source-map-js 1.2.2 定向锁更新；不扩充安全基线 |

主进程只将 **未使用的 S3 适配器**外置；产品若将来调用 Open.s3_v3，需要显式声明并提供该 SDK。现有文件提取路径继续打包 unzipper 本身。

## 复验入口

在具备仓库依赖及浏览器的环境执行：

~~~sh
bun run validate:ci
bun run test
bun run audit:dependencies
bun run scripts/verification/governance-gates-workflow.ts
bun run scripts/verification/distribution-inputs-workflow.ts
bun run test:clean-install
bun run test:critical
bun run test:theme-native
~~~

Linux 原生关键路径使用 xvfb-run --auto-servernum bun run test:critical。Linux 容器验收使用 bun run test:container；distribution 使用 bun run build:smoke。
