# 全项目统一动效规则建议

日期：2026-09-21。基线：`f2f5ef74`。状态：设计建议，未实施。

本规则覆盖 Electron、WebUI、Viewer、共享 UI、独立启动/登录页和 Playground。CLI 用文本/终端反馈适配同一状态语义，不照搬网页动画。动效由产品行为层拥有，继续独立于主题引擎。

## 1. 产品定位

Phaneris 是持续使用的工作界面。动效主要表达输入已接受、状态已变化、元素属于何处、内容从哪里来、操作如何返回。日常操作应安静、敏捷、可打断；低频品牌场景可以保留个性。

“整体”意味着同一语义使用同一规则；“全面”意味着进入、退出、反向、取消、失败和减弱动态都被定义；“连贯”意味着内容身份、布局、焦点和滚动在同一转换中一致。不是所有组件拥有相同曲线或全部都移动。

## 2. 保留现有参数体系

单一来源：`packages/ui/src/lib/motion.ts` 与 `packages/ui/src/styles/motion.css`。目前 JS 与 CSS 为两份镜像，应检查一致性，不再新增业务页面级平行参数表。

| Token | 当前值 | 建议语义 |
| --- | --- | --- |
| instant | 60ms | 极短视觉收尾；真正即时动作仍为0ms，名称不代表零时长 |
| fast | 100ms | 简短反馈、退出、颜色/透明度变化 |
| standard | 160ms | 同级内容交接、常规显现 |
| emphasis | 220ms | 内联展开、需要解释的状态改变 |
| spatial | 280ms | 主要空间变化、面板容器 |
| enter | `[0.16, 1, 0.3, 1]` | 新对象/内容出现，快速起步 |
| move | `[0.2, 0, 0, 1]` | 已存在对象的连续位移/尺寸变化 |
| exit | `[0.4, 0, 1, 1]` | 既有短退出语义；不因通用“ease-in不好”规则全局替换 |
| responsive spring | stiffness500 / damping42 / mass0.8 | 直接响应的共享布局指示 |
| spatial spring | stiffness400 / damping36 / mass0.8 | 导航与较大容器移动 |
| distance | 2 / 6 / 12px | micro / floating / content 的幅度上界起点，不要求每次入场都加位移 |
| scale | pressed0.98 / floating0.98 / dialog0.96 | 非文本密集表面的微小尺度变化；不用整个阅读区域缩放制造过渡 |

上述值来自项目现状。落地先用已有 token 验证，不先大改数值。物理弹簧不承诺精确在280ms结束；逻辑不能按该时间猜测弹簧已经停止。品牌动画的已有例外应有场景、理由和减弱动态方案。

## 3. 语义动作表

| 行为 | 正常模式 | 减弱动态 | 生命周期与边界 |
| --- | --- | --- | --- |
| 按下/释放 | 数据操作即时；允许pressed比例和fast视觉反馈 | 保留颜色/边框；不依赖缩放识别状态 | 不把点击处理放到动画完成后 |
| 键盘选中/列表导航 | 选中、焦点、必要滚动即时 | 同样即时 | 连续按键不堆积过渡 |
| 菜单/命令选择器 | 延续高频即时策略 | 即时 | 开关、Escape与焦点恢复由控件状态机管理 |
| Tooltip | 使用统一延迟策略，不飞行、不弹跳 | 文字照常出现 | 区分首次发现与连续悬停；不要为每个按钮创建独立策略 |
| 普通 Popover | 保留现有160ms淡入/100ms淡出；若加入空间提示，从实际触发位置起始 | 即时或短淡变，不移动 | 碰撞翻转后的方向也要正确；退出层立即不可交互 |
| Dialog | 遮罩与内容同时响应，允许共享standard/emphasis节奏 | 去位移/缩放，保留可理解的状态变化 | 焦点捕获与恢复不等待装饰动画；中心出现不要求从按钮飞来 |
| Drawer/移动层级 | 使用空间方向说明层级；前进与返回互为逆向 | 即时切换或短淡变 | 来源页保留状态；遮挡页inert；手势中断不重置到起点 |
| 同级标签内容 | 状态即时切换；如需软化，整体交接不串行等待两段standard | 即时 | 当前标签、当前内容、当前焦点必须对应同一身份 |
| 内联展开/收起 | 以emphasis/move为默认候选；必要时允许高度过渡 | 尺寸直接到终态 | 不给已有行普遍加stagger；保护滚动锚点；关闭层立即失去交互 |
| 面板开合/最大化/恢复 | 容器关系统一，由spatial或spatial spring解释布局变化 | 一步到最终布局 | 保持编辑器/会话实例；不得先内容淡出、再空白、再布局重排 |
| 拖拽调整宽度 | 手指/鼠标直接驱动 | 同样直接驱动 | 交互中不叠加弹簧追赶；结束后才允许必要收尾 |
| 排序/跨列移动 | 拖动反馈明确；落点确定后再短暂收尾 | 不自动飞行；位置与状态清楚 | 取消/失败恢复来源；不要用动画暗示尚未成功的持久化结果 |
| 工具状态 | 新状态立即成为权威内容，短淡变可选 | 即时 | pending→running→complete快速到达时可略过中间视觉阶段，不隐藏最新结果 |
| 流式输出 | 文本更新直接出现，稳定阅读位置 | 同样直接出现 | 不给每token/每段落添加逐字/飞入动效 |
| 跟随最新消息 | 根据用户是否处于跟随模式更新位置 | 即时滚动 | 上翻即停止自动跟随；新消息不会强制夺回阅读位置 |
| 显式定位记录/文件 | 可使用可取消平滑滚动 | instant | 高频键盘定位直接跳转；滚动只影响目标区域 |
| Loading→结果 | 状态及时，宽高稳定；必要时短内容显现 | 静态状态与文字可识别 | 不为看完spinner而延迟结果，不伪造进度百分比 |
| Toast/完成提示 | 延续统一通知层；保留既有明确取舍 | 消息、关闭、撤销仍可操作 | 业务成功由实际结果确定；手势取消与堆叠交由统一宿主管理 |
| 品牌/欢迎 | 维持已有经记录的时长例外 | 静态最终图形/文字 | 不扩散到普通会话切换和编辑器操作 |
| Canvas/Shader | 仅低频背景场景允许自主运动 | speed=0或静态替代 | 偏好变化即时生效；不可见/卸载后不保留无用循环 |

## 4. 同一转换的五项契约

### 4.1 内容身份

每次转换应明确旧内容与新内容的身份。标签名、新内容和状态更新同步；不能标题已切换，旧内容仍可被复制/提交。动画层不要借用业务主键变化无意重放每次入场。

### 4.2 交互归属

退出开始即可退出点击、键盘和读屏顺序；进入内容在可理解时接收焦点。可复用 SessionList 的 useIsPresent/inert 模式。实际的用户操作被新状态处理，不被陈旧退出表单处理。

### 4.3 空间与滚动

先确定最终布局与锚点，再决定是否需要动画。打开工作台不丢失原会话的滚动；输入区变高不会重复补偿；虚拟列表不为过渡挂载整个数据集。修改尺寸的动画须实测代价，transform也不能以模糊文本、错误命中区域为代价。

### 4.4 中断与清理

反向动作从当前视觉位置接续。新的导航/选择取消旧的延迟滚动和回调。动画完成事件只通知视觉生命周期，不成为业务状态唯一驱动力。组件卸载应取消rAF、WAAPI实例、监听和计时器；保留已有正确cleanup。

### 4.5 减弱动态

保持当前全局CSS兜底与正式入口MotionConfig，补齐独立机制；不要为了某个组件削弱整个项目的偏好处理。共享helper当前返回duration:0，这是明确契约；若未来允许短淡变，应统一修改并验收，不能各组件自行解释。

动态切换系统偏好也要验收。直接拖动、点击后位置变化与自动播放是不同情形：保留操作能力，减少自主运动。旋转停止后，应仍能识别“正在处理”，不能只剩看似静止完成的图标。

## 5. 全项目落地映射

| 层 | 责任 | 主要位置 |
| --- | --- | --- |
| 参数层 | 时长/曲线/弹簧与CSS镜像一致 | packages/ui/src/lib/motion.ts；styles/motion.css |
| 宿主层 | 偏好、通知、覆盖层统一配置 | Electron/WebUI/Viewer main；playground.tsx；独立HTML入口 |
| 原语层 | Presence、退出隔离、折叠、标签替换、忙碌反馈 | ui/collapsible、popover/dialog、InputContainer、共享Island |
| 导航层 | 来源/去向、紧凑模式层级、面板开合与布局协同 | SurfaceContainer/SurfaceSlot/CompactPanelTransition/MobileAppMenu |
| 业务层 | 真实异步状态、输入提交、消息与任务顺序 | ChatDisplay/TurnCard、设置、自动化、插件/来源、消息接入 |
| 非React机制适配 | WAAPI、Canvas、直接MotionValue、浏览器滚动 | sortable-list、ImageCardStack、WorkspaceCreationScreen、滚动调用点 |
| 验收与门禁 | 场景测试、例外记录、跨入口规则 | Playground、现有测试/ESLint、独立CSS扫描 |

优先建立少量行为原语，避免把每个组件包装进一个包含所有参数的巨大Motion组件。业务层保留状态所有权，动画层只表达状态；不重写路由、授权流程或任务状态机。

## 6. 技术选型原则

- 延续当前 Motion + CSS + 原生控件机制。简单颜色/透明度用CSS；动态几何/手势用已有Motion；Canvas单独适配。
- 参考库的代码只有在语义、焦点、减弱动态、主题和触屏均符合要求时才移植。
- 面板库的收益必须包含维护性与完整交互，不能只凭演示流畅度。先使用代表性布局比较，不直接替换所有工作台结构。
- 不把 `x/y/scale` 出现自动判为性能缺陷。Motion版本、渲染属性、层数与主线程负载共同决定效果；以trace验证。
- 不全面禁止width/height动画。折叠文本、编辑器重排和真正的布局变化有不同约束；保留清晰度和可操作性优先。
- 门禁应阻止新增未知transition-all、未登记循环动效、缺少偏好适配的独立动画入口，同时支持有理由的例外。

## 7. 交付完成条件

全项目完成意味着审计中的确定问题处理或明确作出保留决策；主要操作链路在正常/减弱动态、正向/反向/中断均通过；生产与Playground一致；关键性能场景有实际trace；外观参数与主题分离。只修改参数、只通过TypeScript或只展示单个漂亮组件，都不足以达到目标。
