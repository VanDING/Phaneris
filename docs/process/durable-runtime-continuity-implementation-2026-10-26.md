# Durable Runtime 连续性修复

Status: implemented — 2026-10-26 用户授权完整修复；分支 `codex/durable-runtime-continuity`，基线 `bc2f436a0`。本机验收与提交状态以下文和 Git 历史为准，未发布或替换已安装客户端。

本轮由真实会话 `261026-prime-iron` 触发：正常退出期间命令尚在执行，结果文件稍后生成，但工具 T2 没有收集到。旧实现将历史调用的未知结果升级为整个会话的前台锁，用户输入“继续”无法进入。问题不限于命令：只读调用、提交故障、模型计量、输入回执、交接和任务节点均存在同类阻断。

[失败矩阵 RC01–RC16](../verification/durable-runtime-continuity-failure-matrix-2026-10-26.md)记录事先验收条件；TaskRunner 条目在发现该路径后、修改其生产代码前补充。只操作隔离副本与 fixture；真实会话及工作区数据库保留。

## 行为与职责

| 层面 | 已实施行为 |
| --- | --- |
| 前台执行 | Host 在实际执行结束后释放前台位置、通知观察者并推进队列。旧 ledger 保持 parked/unknown 事实，不再拥有会话锁；结算暂时失败亦不留下永久 busy 状态 |
| 模型与工具 | 历史未知工具不禁止下一模型请求。只在同一会话或交接祖先中限制名称与参数散列完全相同的未确认非幂等调用；其他工作、检查和模型推理可继续。Pi 仍负责实际执行顺序 |
| 工作上下文 | 缺失工具结果在 provider 视图内明确标注 unknown，并保持调用/结果配对；它不是业务失败或成功的 T2。迟到实际结果可补回；孤立输出保留原内容。原生压缩与 journal 所有权继续属于 Pi |
| 已知结果 | 模型实际终态照常交付。宿主和子进程共用最小收据格式，存储故障或 ACK 丢失时保留已观察结果，自动重试入账；不会重放工具或 provider。收据身份或内容冲突仍被拒绝 |
| 输入 | SDK 实际收到的用户消息携带输入身份，模型结果记录已消费身份。重启时跳过已消费输入、自动恢复未消费输入，并附原始范围与检查已有结果的说明。观察或附加输入事实写入失败不能阻止 SDK 投递 |
| 停止与退出 | 四类 durable RPC 有期限与取消结算；停止前未调用的工具保留 not_dispatched 事实。普通停止等待 SDK abort ACK；正常退出先等待 SDK 取消与子进程收尾，再升级为强制终止。旧 ACK 不能结束新输入 |
| 存储与投影 | 一个工作区故障不拖垮全局初始化。原数据库保留，自动选用经过校验的备份副本或独立恢复库；不可持久化时使用有明确状态的内存存储。投影失败或待补写结果期间保留较新的 native 工作上下文。无法保存动作意图时，只拒绝该动作的派发 |
| 任务节点 | 子会话创建前持久化 `taskNodeDispatchId`；同一身份复用已有创建结果。重启优先复用原子会话或已完成输出；未完成节点在原会话检查续做，丢失子会话时携带原身份与范围恢复。任务 JSONL 与事实提交互不形成执行门槛；下一边界自动补写积压事实，较旧的非空 ledger 不覆盖完整 native 日志 |
| 普通对话 UI | 移除强制人工 reconciliation 对话框入口和回调。内部诊断接口保留兼容，但不再构成普通用户继续任务的条件 |

持久化结果不等于执行权限。原有权限、真实取消、实际运行中的互斥和工具授权继续生效。这里改变的是执行生命周期与后台记录的耦合，不将“未知”改写为“已经成功”。

## 验收与证据

完整回归命令：`bun run verify:model-harness`。聚焦连续性命令：`bun run verify:durable-continuation`。二者复用既有 VerificationRun，成功和失败均生成独立 manifest、产物散列、重复运行命令与未覆盖范围。

| 检查 | 结果 |
| --- | --- |
| 完整 harness 回归 | 17 个工作流、173 个场景通过，包含最后补入的 RPC ACK 丢失、模型收据跨重启补写与输入去重 |
| 新增连续性工作流 | Runtime/SQLite 27、真实 Pi/Host/SQLite/PowerShell 10、TaskRunner 4 个场景通过 |
| 既有边界与崩溃恢复 | 边界 15、崩溃 8、独立 Pi 6，共 29 个补充场景通过 |
| 全工作区类型、lint、i18n、身份、版本、文档门禁 | 通过；实际日志与源文件身份保存在证据索引 |
| 既有 Pi 测试 | 200 pass / 0 fail；未新增单元测试 |
| 既有服务端测试 | 449 pass / 4 fail；4 个旧流式夹具以 `Object.create` 跳过构造函数，未初始化现有 `deltas`，相关夹具及批处理路径与基线相同。未为本轮扩展无关兼容层 |

退役了要求旧行为的四个单元断言：模型 T1 失败必须阻止推理、模型 T2 失败必须丢弃成功回复、任何未知工具必须阻止下一模型请求、任务恢复必须要求人工核对。替代验收覆盖实际会话/任务连续性、真实收据和作用域限制，没有在实现后新增同构单元测试。

[最终证据索引](../verification/results/durable-runtime-continuity-2026-10-26-final-v2/index.json)保存 manifest、原始输出、失败基线、源文件/构建 SHA-256 与未覆盖范围。真实会话副本验证仅保存[最小结果摘要](../verification/results/durable-runtime-continuity-2026-10-26-final-v2/live-session-summary.json)：保留 1 条未知调用，新前台及模型请求可进入，没有请求真实 provider，也没有改动用户原库。另有[真实 SessionManager 补充验收](../verification/results/durable-runtime-continuity-2026-10-26-final-v2/task-session-identity-summary.json)的 4 个检查，覆盖并发重复创建、持久身份冷加载、新尝试排除旧结果和旧会话自动恢复；未归档用户原数据库或对话正文。

## 验证边界

- 本机 Windows 使用 Bun 1.4.2、Pi SDK 1.3.0；分发输入仍锁定 Bun 1.4.3，未将本机运行等同该版本的发行验证。
- 受控 provider 用于验证请求、终态、输入、停止及文件链路，不证明真实模型质量改善或所有第三方系统的 exactly-once 效果。
- 未声称未知外部动作已完成，也没有替用户作业务完成判定。无法证明结果时，AI 可检查既有产物并继续其他工作，系统不要求用户填写审计表。
- 源码与本机验证不替代打包、签名、安装或跨平台发行。旧客户端需要运行包含此修复的构建；未改动真实工作区数据来制造恢复成功。
