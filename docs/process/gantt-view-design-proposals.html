现状观察与优化建议

下面是基于当前组件与 CSS 的判断；设计稿重点调整视觉组织，任务过滤、折叠、定位、跳转等既有行为可继续保留。

优先处理

把层级和时间跨度连成一条阅读路径

父任务改为与子任务同属条状表达，但用更完整的底色和内部填充显示主任务进度。父任务日期与状态只放在标题下方的标签行；折叠后仍保留主任务条和进度百分比，不再用细括号代表父任务。

优先处理

加强时间刻度和“今天”的定位

保留年／季度／月度尺度切换；明确区分月份与周刻度，给当前日期一条细但连续的定位线，并让周末或非工作日的底色保持很轻。这样空白区间也能说明任务落在什么时间，而不会让网格压过任务条。

优先处理

让进度和状态无需只靠颜色推断

日期范围与状态各显示一次，沿用标题下方的标签样式；不再重复铺成独立字段列。叶任务保持当前轻量进度提示，主任务则在条形内展示可见的进度填充与百分比。状态色配合文字标签表达，避免只靠颜色判断。

优先处理

建立依赖关系的聚焦反馈

依赖箭头在 10–30 条任务时有价值，但多条连线同时出现会抢视线。默认降低连线存在感；悬停或选中一项时突出它的前置／后续关系，并同步高亮左侧任务行和时间条。原有行与条的悬停联动适合延续。

其次处理

把工具栏分成“范围”和“时间”两组

当前项目筛选、已排期数量、尺度切换、“今天”集中在同一行。可将项目范围与任务数量放左侧，把尺度和日期定位放右侧；窄窗口下允许收起任务列，避免操作控件挤压时间轴。

其次处理

补足空数据与窄窗口的引导

当前空状态主要是一句说明，未排期的父项提示也在图表下方。建议提供清楚的下一步入口，并在横向空间不足时保留任务名和当前日期刻度的可见性；空状态入口的目标需确认后再接到已有编辑流程。

建议保留

日期与状态标签、层级缩进、里程碑菱形、任务行与时间条的同步悬停，以及点击任务跳转详情都继续保留。主任务的形状统一改成条状，内部填充表示主任务自身的进度。

主任务进度口径

本稿用主任务已有的 progress 值绘制条内填充；不把子任务百分比擅自平均成主任务进度。示例里的 47%、56% 和 0% 仅用于展示条形状态。
