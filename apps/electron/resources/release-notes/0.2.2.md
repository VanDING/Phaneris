# Phaneris 0.2.2

A maintenance release. It absorbs the parts of upstream's v0.13.4 that apply to a
Pi-only fork, and closes the defects behind them — including two that had reached
us from directions upstream had already fixed, and one that made the prompt itself
writable from the context it carries. Nothing changes about how a session is
stored or how your workspace is laid out.

## Prompt context blocks are escaped

The system prompt carries several blocks of text that the app does not author: the
working directory, the list of discovered `AGENTS.md`/`CLAUDE.md` files, and your
saved preferences. Those values were interpolated raw, so a directory inside a
cloned repository, a crafted file name, or a saved note could close its block early
and have the remainder read as instructions rather than as content.

All prompt-injection escaping now lives in one module (`prompts/prompt-sanitize.ts`,
replacing two private copies): control characters are stripped, closing tags are
neutralized case- and whitespace-insensitively, values placed inside quoted
attributes are escaped, and repository URLs in the prompt are relieved of embedded
credentials. The preferences block is now wrapped in `<user_preferences>` with every
line sanitized, so it reads as data with a stated precedence instead of a heading
competing with the prompt's own instructions.

## Steered messages arrive together

Sending several messages while a turn is running is a normal way to redirect the
agent — but only the first of them was being delivered at the next model boundary,
with the rest trickling in one per later turn, and anything still queued when the
turn ended could be discarded by a queue reset. The subprocess was relying on the Pi
SDK's default steering mode; it now pins `steeringMode: 'all'`
(craft-agents-oss#1040), so every message pending at a tool boundary reaches the
model in the same call, in order, and later arrivals wait for the next boundary.

The regression test drives the installed SDK offline — no provider access — and
fails on the previous setting.

## Context occupancy is measured, not remembered

The context indicator derived its figure from the last assistant message, which is
billing usage, not occupancy. After a compaction it therefore kept showing the
pre-compaction total until the next turn finished, and the Pi SDK's own occupancy
metadata was ignored entirely.

The subprocess now reads the SDK's authoritative `contextUsage` and its compaction
settings at every turn boundary and after every message, forwards them before the
turn can complete, and the manual `/compact` call returns the post-compaction
estimate. The host keeps occupancy as its own field, separate from the cumulative
billing counters, and no longer re-publishes an unchanged count at a compaction
boundary. When the context has changed but no fresh count exists yet, the badge says
"Usage unknown" rather than showing a stale number or a percentage computed from one.

## The agent starts oriented

The session's system prompt now carries a `<developer_context>` block for the
working directory: the git repository root and its parent, the selected path inside
the repository, the `origin` remote (credentials redacted) and the default branch,
plus standing guidance — treat uncommitted changes as user work, keep diffs
minimal, create worktrees as siblings of the repository root, and do not switch
branches, reset, rebase or force-push without being asked. The half that changes
between turns — current branch or detached HEAD, upstream, ahead/behind, worktree
cleanliness and counts, and a sample of up to 20 changed files — rides the volatile
user-message tail, so the cached system prefix stays stable and prompt caching keeps
working. Every git call is bounded to 700 ms and fails soft: outside a repository the
block is simply absent.

Project context files are now discovered relative to the git repository root and
filtered to the ones that can govern the selected directory, so a session in
`packages/api` sees the root file plus its own subtree instead of every sibling
package's instructions. On Windows this also fixes the file list: platform
separators made every nested file read as a root-level one.

The system prompt also gained an `## Automations` section, which states what
automations are, where to read the guide before creating one, that validation beats
guessing schemas, and that label or status changes can themselves trigger
automations.

## Bug fixes

- **A plan approval can no longer be sent twice.** "Accept & Compact" persists the
  pending plan, compacts, and then sends the approval. Live completion and reload
  recovery used to be separate paths — an event listener plus a mount-time check with
  a fixed delay — and the persisted record was stamped rather than claimed, so a
  second window or a remount could each dispatch their own copy. Both paths now share
  one dispatcher over the persisted record, and an atomic host claim decides which
  caller owns the send: it is refused while the session is busy, while compaction is
  still running, or once someone else has claimed it. The fixed delay is gone,
  replaced by the session's idle transition as a second wakeup.
- **The calendar header follows the app language.** The schedule calendar built its
  title from a fixed `yyyy年M月d日` pattern, so an English UI still read "2026年9月21日",
  and its day view named weekdays through a default locale that is English in every
  language. Both now format through the active UI language — "September 2026" and
  "Monday" in English, "2026年9月" and "星期一" in Chinese, "2026. szeptember" in
  Hungarian — ordered and separated per locale.

## Getting it

Phaneris builds from source; published installers and self-update are still not
part of a release. Setup is documented in the application itself, from the help
menu — including a guide to installing and editing plugins.
