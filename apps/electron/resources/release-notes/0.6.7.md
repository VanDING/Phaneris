# Phaneris 0.6.7

This release makes the resident assistant's execution continuity explicit: routine work executes against a prepared work context, and every effect can be reconciled without replaying an unknown one. It also adds workspace-level custom icons for skills, sources and plugins, and unifies navigator icon sizing.

## Features

- **Prepared work context** — `assistant_context prepare` records a turn's requirements — its verbatim scope and, for work that changes files, a `workScopeQuote` from that text — then publishes a ready preparation carrying a generation and material fingerprint. A bare select, a prepare/delegate in the same batch, stale materials and forged producers do not inherit eligibility from the newest pointer; business execution is admitted only for the matching preparation.
- **Atomic receipts and recovery** — Local command receipts commit with the command transaction. Progress queries, recovery and Runtime reconciliation converge on stored facts; a missing receipt keeps an effect unknown rather than replaying it. Deterministic admission failures stop after three attempts, and the next user input restores tools.
- **Multi-work attribution** — Branches and segments keep their own target references. Background views no longer rewrite the foreground HEAD, a continuation inherits requirements from the host-verified execution, and Worker control checks both producer and target work while retaining scope and effect facts.
- **Custom resource icons** — Skills, Sources and Plugins gain a "Change icon" control in the navigator and detail views: twelve built-in presets plus image upload (SVG, PNG, JPG or WebP up to 5 MB, rasterized and cropped to a 128 × 128 PNG) and restore-to-default. Icons are stored per workspace in `resource-icons.json` (atomic write, mode `0600`, 8 MiB cap), validated at the server boundary and broadcast to every open window.

## Improvements

- **Reusable source index** — The context index is reused by byte budget instead of rescanned: a second read of a 13-source session drops from 3,930,449 scanned bytes to 0. Cold indexing runs on a worker thread and is checked against per-file generations before publication; failures are cached by generation. Collaboration profiles sort candidates before validating the selected eight, and async preparation and sync read costs are recorded separately.
- **Deferred maintenance** — Maintenance targets that cannot be written keep their reason and pending overrides instead of counting as having no candidates. Routine maintenance prefers direct user sources and final replies, while mechanical tool traces stay searchable.
- **Versioned context schema** — Schema upgrades preserve existing HEAD and view references, never promote a pre-proof view to ready, and refuse writes from a higher schema version.
- **Navigator icon sizing** — Resource rows reserve one fixed 16px icon slot (48px in the detail header), with consistent right padding when the icon action is present (40px, 60px on coarse pointers). The new-session control uses the bordered card surface, and emoji and image icons scale with the slot.

## Bug Fixes

- **Stop during reconciliation** — A stop that arrives while reconciliation is waiting can no longer open a new T1; results that are already known can still be recorded.
- **Background continuation isolation** — Background continuation no longer changes the foreground HEAD or the visible view.
- **Bounded retries** — Queued input waits for actual completion, deadline barriers keep expired runs from reopening execution, and external effects are never replayed by recovery.
- **Derived records** — History extraction, memory storage and delegation keep their recorded scope and actual-effect facts instead of inferring them from the latest state.
- **Pi request provenance** — Pi provider requests carry the preparation generation and material fingerprint, and Pi branch recovery derives its branch from the journal on both sides of initialization.
- **Icon update races** — A save no longer replaces a newer broadcast event, and icons updated while the initial load is in flight survive the merge.

## Compatibility

- Existing sessions keep their HEAD, pointer and view references. Views recorded before preparation proofs existed do not become ready, and the upgrade writes nothing to their authority tables.
- The host validates quote references, generations and producers; the semantic decision about scope remains the assistant's, so natural-language understanding is not mechanically guaranteed.
- The 16 MiB locator index is an in-process budget estimate, not a heap measurement; the release makes no production-latency percentage claim.
- Icon uploads are rasterized client-side; the server stores and broadcasts only validated 128px PNG data URLs, and SVG markup is never persisted or rendered as stored markup.
- Production installation, production data migration and signed artifacts are not part of this release preparation. Windows verification used an unsigned, isolated candidate; macOS and Linux native acceptance was not run.

## Validation

- Continuity acceptance: 9 workflows, 63 scenarios across the sub-flows. Full resident-assistant rollout: 25 workflows, 390 scenarios. Live real-model semantics: 5 checks with recorded evidence.
- `validate:ci` passes: workspace typecheck, lint gates, shared, doc-tool and table tests, four i18n gates, docs, fonts, identity, version, runtime and Electron pins.
- The Windows unsigned candidate passed structural inspection 9/9 and isolated startup 5/5. A production-context copy opened 25 sessions, left six authoritative table groups unchanged and promoted no old ready view.
