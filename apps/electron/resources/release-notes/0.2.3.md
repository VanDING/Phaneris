# Phaneris 0.2.3

This release rebuilds how project work is scheduled and edited. The calendar gains a
rail for work that has a date but no time, the Task Definition editor becomes the one
place a task is created or changed, and the timeline's task list now follows the
window. Three defects are fixed, including one that only appeared on plans long
enough to scroll.

## A rail for work without a time

Most planned work has a date and no time, and the calendar's all-day row could only
show the week you were looking at. Those entries now live in a 300px rail beside the
day and week grids:

- It lists **every** entry with no time, in every week, grouped by day, with past
  dates marked rather than hidden.
- **Drag one onto the grid** to give it that date and time. **Drop a timed entry on
  the rail** to take its time away again.
- Dragging to the top or bottom edge of the grid **scrolls it while your pointer is
  still**, so a time that is off-screen is reachable without scrolling first.
- A small **+** adds an entry from a title and a date alone.
- When the panel is too narrow for a 300px rail, it collapses into a header chip that
  opens the same list — nothing becomes unreachable by collapsing it.

The month view keeps its day cells and has no rail.

## Day and week headers

Headers are two lines — weekday over date — with **today marked in the header**
instead of by tinting a whole column, which on the day view tinted the entire grid.
All three views share one header height, so switching between day, week and month no
longer moves the grid.

## One editor for project work

Creating or editing a task now opens the Task Definition editor from the board, the
list, the calendar and the timeline alike — the simplified new-task form and the
standalone schedule page are gone.

- The editor gained a **Planning** section: start and due date with an optional time,
  status, progress, milestone, parent and dependencies.
- **Click an empty slot** to create at that slot, or **drag down the grid** to select
  a range; either way the editor opens with the date and times already filled in.
- Leaving the time empty keeps an entry date-only, which is what the rail reads back.

## Timeline

- The task list is a **share of the window** rather than a fixed 370px, and a width
  you drag to is remembered per workspace.
- **Task rows follow that column.** They previously hugged their content, so widening
  the task list moved the divider and left the rows behind.

## Fixes

- **The date header no longer shares its band with task bars.** The timescale is
  pinned with a background drawn from a token the library references but never
  defines, so in this app the band was pinned and transparent: scrolling a long plan
  slid its rows up through the month and week labels. The token is now defined, which
  also restores the chart surface, weekend shading, rollup borders and the task-list
  header.
- **A reversed date range can no longer be stored.** The check lived only in the
  calendar's own update path and in the two editor pages this release retires, so
  saving through the task editor or the board accepted an end date before the start.
  It now runs at the single point every write goes through.
- **The timescale band is verified in the browser suite**, which fails if the band is
  transparent or if it changes while the grid scrolls.

## Improvements

- 165 translation keys that nothing referenced were removed from all seven locales,
  and a **dead-key check** now runs in CI, so strings cannot accumulate after the
  feature that used them is gone.
- Accessibility linting (`jsx-a11y` recommended) is enabled for the board, calendar,
  timeline and the new editor overlay.
