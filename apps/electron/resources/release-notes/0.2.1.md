# Phaneris 0.2.1

A maintenance release. The agent kernel moves to Pi SDK 0.86.0, the desktop
runtime to Electron 44.4.3, and the dependency tree is brought current — which
closes 21 of the 24 known advisories. Nothing changes about how a session
behaves or how your workspace is laid out.

## Agent kernel: Pi SDK 0.86.0

Pi now hands providers a normalized transcript, so instruction and tool changes
travel as in-place prompt deltas that keep the cached prefix intact instead of
rewriting the prompt. The Phaneris system prompt is still projected as the
request's leading system message, and prompt snapshots in the trajectory view
keep showing exactly what the model was sent. Built-in file and shell tools ask
for JSON-schema-constrained arguments where the provider supports it, and
agent-level retry backoff is capped at 60 seconds.

One SDK default is deliberately not taken. Pi 0.86.0 enables prompt-cache
warming, which re-sends the last request before its cache entry expires and
bills it as a full-context cache read; during long tool runs that is real spend
with no visible author. Those refreshes go through the SDK's own model runtime
rather than the path Phaneris wraps, so they would never appear in the durable
ledger or the audit trail. Warming therefore stays off until it can be committed
and attributed like every other request. Background spend is unchanged from
0.2.0.

`extendedPromptCache` is now driven by Pi's own `cacheRetention` rather than by
rewriting Anthropic cache TTLs in the network interceptor, so it reaches every
request the SDK makes instead of only the ones that pass through the
interceptor.

## Request evidence in the durable record

Model outcomes now carry native evidence: a hash and byte count of each payload
the SDK actually dispatched — never content, credentials or arbitrary metadata —
plus an allowlist of response headers (request ids, `retry-after`, rate-limit
remainders). The evidence is committed in the same transaction as the usage, so
a request cannot be recorded without it.

A read-only observer on the SDK's lifecycle hooks records tool proposals, tool
results, compaction, retries and model/thinking-level switches as
`sdk_observation` entries tied to the run that produced them; events outside an
active run are dropped rather than attributed to an unrelated turn. When a run
settles, Phaneris compares the model outcomes against the usage ledger and
reports what does not line up — separating "dispatched but never resolved" from
"completed at zero cost". None of this changes execution: no observation can
block a tool or rewrite a result.

## Desktop stack

Electron 44.4.3 (Chromium 152), React 19.3, jotai 3, and React-PDF 11 with
PDF.js 6. PDF previews keep their existing loading and error behaviour — the new
Suspense default is opted out per viewer — and the browser shares a single
PDF.js copy with the server instead of loading a second one.

## Security

| Dependency | Was | Now |
| --- | --- | --- |
| `xmldom` | 0.6.0, abandoned since 2021 (2 critical, 9 high) | the maintained `@xmldom/xmldom` |
| `xlsx` in the document converter | 0.18.5 (prototype pollution, ReDoS) | SheetJS 0.20.3 |
| `exiftool-vendored` | 29.3.0 | 38.1.0 |
| `@azure/identity` | 3.4.2 | 4.13.3 |
| `uuid` | three copies across the tree | 11.1.1 |

The bundled OCR helper no longer builds a shell command out of the file path it
is given: a document named `pic$(touch PWNED).png` executed the embedded command
while being converted. Only image conversion reaches that code, and this release
routes Office formats to the converter, so it was not reachable in practice —
the helper now passes its arguments directly and the class is gone. The two
replacements live in `patches/` so a fresh `bun install` applies them.

Three advisories remain, all inside the WhatsApp library's own audio-metadata
stack. They wait on that library's next stable release rather than on a version
bump here.

## Bug fixes

- **Sources enabled through a plugin or a skill's `requiredSources` are usable in
  the same session.** The cached source runtime still described the previous
  set, so the agent was handed the old list and every call into the source that
  had just been switched on failed with `Tool not found`.
- **Provider connections are classified by endpoint protocol, not by the presence
  of a URL.** Every built-in provider (DeepSeek, Minimax, Groq, …) has its own
  endpoint and the setup presets prefilled it, so those connections were stored
  as custom endpoints: Pi neither routed them to the provider nor registered
  them as endpoints, image input was treated as unsupported, the thinking-level
  selector was disabled, and model refresh always failed. Existing connections in
  that state are repaired on startup, and the model picker lists every connection
  in one flat list.
- **The macOS icon sits on the platform grid.** The Dock icon was full bleed and
  read about 23% larger than the apps beside it; the `.icns` now carries the
  same 824/1024 margin stock apps use, and a packaged bundle's own icon is no
  longer overridden at runtime.

## Getting it

Phaneris builds from source; published installers and self-update are still not
part of a release. Setup is documented in the application itself, from the help
menu — including a guide to installing and editing plugins.
