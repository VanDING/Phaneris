# Phaneris 0.6.1

This release completes the resident assistant's permissions, memory and
knowledge foundation: it reads the workspace directly, learns and maintains
memory on its own, keeps project facts in one authority, uses existing
knowledge sources, and manages work from a new overview with Current,
Deliverables and History.

## Features

- **Assistant memory settings** — Workspace settings add Assistant memory with a learning mode (Automatic learning, Explicit requests only, Pause learning) and an independent Use memory switch. Learning covers local conversations and task results in this workspace, while connected knowledge bases are read on demand; pausing learning keeps existing records, and turning memory use off stops future recall and injection without deleting anything.
- **Automatic learning** — With automatic learning on, the assistant retains supported, durable observations from direct user statements or Runtime-verified observations. Unsupported or merely plausible content stays a candidate and is never presented as confirmed user fact, and a tool result cannot confirm a user preference on its own. Corrections and replacements retire what they supersede, so superseded content stops entering later requests.
- **Bounded maintenance** — Background distillation runs in the assistant's own session and is limited per slice (6000 characters; 6 model preparations, 16 tool preparations or 30 seconds) and per UTC day (8 runs, 48 model preparations, 128 tool preparations), with persistent counters, checkpoints that survive restarts and backoff after repeated failure. Foreground messages and work-set switches take priority, and these counts describe admissions rather than model billing.
- **Assistant overview** — More opens a non-modal, resizable overview (384px default, 320–640px, clamped to the viewport) anchored to the assistant header. Current lists pending decisions and unfinished assignments with the concrete blocked reason (session, source, directory or configuration) and can retry in the original session; History and Deliverables are paged and searched on the server; task details load on demand with execution settings, attempts and process files. The panel stays open while you use the assistant, hides when you leave the assistant page, and restores its presentation per workspace.
- **Deliverables** — A worker declares its final, supporting and process outputs; the Host checks the delegation, ownership, path and revision, and the assistant reviews the real result before a file becomes a deliverable. Supporting files are disclosed under their result and process files stay in task details; previews open the reviewed revision, and a reviewed file can be removed from Deliverables or restored later without touching the file, its versions or the task outcome. Existing artifacts are never promoted automatically.
- **Project facts** — Every project keeps its writable authority in its own `MEMORY.md`. `project_memory_append` validates the source text, project ownership, learning policy, request identity and current file hash before appending, and a retry returns the original receipt instead of duplicating an entry. Search and read return the file URI, read time, position and version, so a section omitted from a prompt summary can be read back, and native write tools cannot overwrite the file. An external edit invalidates in-flight reasoning snapshots.
- **Knowledge sources** — Existing MCP, API and local sources can declare a `knowledge` purpose and project associations; the metadata describes relevance and grants nothing. MCP resources are read back by their original URI with `source_read_resource`, and read results keep the source-configuration version, the returned content hash and the read time. Revoking or reconfiguring a source retires the derived results that depended on it, and a failed read is reported separately from no match.
- **Native reading** — The assistant reads files, lists directories, finds names and searches contents directly in its authorized directories, and a search from a parent directory still returns public project content. Assistant state, other sessions' raw control files and credential stores remain unreadable, and ordinary workers do not receive this exception.
- **Messaging channels** — Bound channels stay visible with their connection state and management actions; an assistant without a bound channel gets a single connection entry, and available platforms appear only in its transient picker. Setup, pairing and credential entry reuse the existing messaging flows, and different platforms can be connected from inside the assistant.
- **Storage layout** — Assistant data (session location, sessions, memory, context, delegations and migration evidence) moves under `<workspace>/assistant/`. The migration runs behind a single write lease with resumable checkpoints and keeps its evidence in `assistant/migrations/layout-v1/`; the assistant identity is preserved, sessions are not cloned on restart, and the old database is no longer a writable alias.

## Improvements

- Delegation recovery: an input that was accepted but never reached the model can resume from the exact original input after a restart; a saved material pack continues the same worker and receipt; later direct user work stays independently attributed; and a later delegation's error is never assigned to an older input.
- Unknown external effects keep their resource scope until the original transaction is reconciled, and a known-complete result can recover an unrecorded receipt without taking the result of follow-up user work.
- Model and history handling: `pi/`-prefixed model IDs validate canonically on both sides, provider-reported endpoints are checked against the selected connection protocol instead of catalog membership, and an explicit history query prioritizes that session within the existing eight-session budget.
- Recall: Chinese text recalls by word and two-character match from a searchable projection advanced at most 32 entries per query within the allowed scope, and episodes, project scope and a bounded collaboration summary participate without copying preferences or forming a second persona authority.

## Bug Fixes

- **Foreground priority** — Switching the active work set no longer stalls behind a hidden maintenance run: the foreground operation waits for the run to stop, while ordinary user responses keep their abort protection.
- **Maintenance scheduling** — A long-range maintenance timer no longer blocks new receipts from being delivered.
- **Legacy migration** — Migration keeps legacy source references readable by their original expanded-path hash and invalidates them only when the real content changes, so an unchanged source stays usable across the move.
