# Phaneris 0.5.0

This release improves how long tasks continue through tool interruptions, application restarts and context compaction. Background runtime records recover automatically while conversations remain usable. The Run workspace and Default appearance also bring task progress, context and everyday controls into a more consistent view.

## Features

- **Run workspace** — Bring task overviews, decisions and context browsing into one workspace.

## Improvements

- **Task preparation** — Resolve the working directory, selected skills, task requirements and available capability families before execution. Keep user requirements, task criteria and artifact versions available across handoffs.
- **Capabilities and evidence** — Discover product tools by family and receive guidance when relevant. Preserve file ranges, original evidence, images and structured tool values. Skill and source recommendations remain optional advice; message delivery follows the connection's steer or queue preference.
- **Pi context ownership** — Preserve native compaction summaries across subsequent turns and restarts. Keep the model's full context window distinct from an optional compaction threshold, and recover late tool results without replaying their actions.
- **Material feedback** — Keep original files and recoverable evidence available alongside bounded model views, with shared context-capacity accounting for tool results.
- **Default appearance** — Use one product theme with light, dark and system modes. Align the palette with Run and apply one color policy to startup, runtime and contrast checks. Preserve mode, font and user-owned theme files when an earlier theme selection falls back to Default.
- **Thinking activities** — Show model thinking in chronological order alongside tool activities. Open an activity to read its full content.

## Bug Fixes

- **Conversation recovery** — An older unknown tool result no longer locks the entire conversation or requires a manual reconciliation form. Keep unknown effects explicit while allowing inspection and independent work to continue.
- **Results and input delivery** — Preserve actual model and tool results when runtime bookkeeping fails, automatically backfill retained receipts, and distinguish RPC correlation from outcome identity. Recover unconsumed user inputs without duplicating inputs already used by a completed model request.
- **Stopping and restarting** — Bound internal runtime waits, drain SDK cancellation before process teardown, and prevent an old cancellation acknowledgement from ending a newer turn. Isolate workspace storage failures and preserve the original database during automatic recovery.
- **Task resumption** — Reuse existing child sessions and completed outputs after restart. Keep task scheduling usable during fact-recording failures, and distinguish a resumed node from a new repair attempt.
- **Conversation feedback** — Forward thinking updates during reasoning, retain received thinking after a stop, and release short paused responses after the display-buffer deadline.
- **Browser cancellation** — Cancel capture waits, preserve completed batch output and settle observed tool errors returned after a stop.
- **Custom connections** — Preserve DeepSeek thinking settings on recognized custom endpoints and avoid choosing an unrelated utility model from the connection's authentication label.
