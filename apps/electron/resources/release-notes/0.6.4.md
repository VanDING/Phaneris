# Phaneris 0.6.4

The assistant can manage several delegated tasks at once, receive revisions
without stopping a Worker, and review results against the original user request.
Task state remains attached to the existing Session and execution records.

## Features

- **Concurrent delegated work** — Run independent Workers in parallel, with a default workspace capacity of four and a configurable range of 1–16. Tasks waiting for capacity, dependencies or overlapping write scopes expose a specific waiting reason.
- **Task-scoped materials** — Each Worker receives the requirements and sources for its own task. Switching the assistant to unrelated work does not mix materials or cancel an independent Worker.
- **Queued revisions** — Send ordinary corrections to the existing Worker without interrupting its current turn. Delivery acknowledgement and evidence that the model actually read the revision remain separate; explicit interrupt requests keep their existing behavior.
- **Result review** — Completed or failed delegated work enters review. Accepting the current result closes the task; rework returns it to an open state. Tasks reserved for user review cannot be accepted by the assistant.
- **Continuation under the original grant** — Continue an authorized multi-stage goal in the same Session after reviewing the previous result, while preserving the original user request, source references and permission scope.
- **Board and task overview** — Show the assistant's direct work as top-level cards, with planning details, execution activity and a bounded overview of active and waiting tasks.

## Bug Fixes

- A delivery acknowledgement or a selected output file no longer counts as completed review. Stale results, withdrawn sources and manual status changes cannot authorize an old automatic completion.
- Pending revisions keep an earlier response from being sealed as the final task result. Text-only results can explicitly select zero files without publishing old deliverables.
- Restart, pause and cancellation recovery preserve input identity and settled execution state instead of treating saved queue markers as proof of a live execution.
- Shared source validation avoids repeatedly walking the same ancestors, and the assistant conversation header keeps context-management controls internal.

## Compatibility

- Historical delegations without recorded status ownership are not automatically marked done from old acknowledgements or review timestamps.
