# Phaneris 0.6.0

This release introduces the resident assistant: one assistant per workspace with
its own identity, a durable workspace memory, a bounded main conversation, and a
typed path for handing execution to ordinary sessions and taking their results
back.

## Features

- **Resident assistant** — Every workspace gets one assistant with its own role prompt and identity. A centered brand entry in the top bar opens it; the original logo keeps the application menu. The assistant reuses the ordinary conversation page, composer, drafts, streaming and navigation, so no second chat surface or assistant sidebar is added, and a new model context keeps the same assistant identity and complete timeline.
- **Assistant memory** — Memory entries are stored per workspace with revisions, request receipts, suppression markers and a monotonic version. Each entry keeps provenance to a real session message with a content hash; explicit user statements and inferred candidates stay distinct, and hidden messages or the assistant's own earlier answers cannot become user statements. Remember, revise, invalidate, cool down and forget are separate operations, with optimistic revision guards and deduplication across repeated requests.
- **Durable delegation** — The assistant creates or continues ordinary sessions with a complete execution configuration (model, permission ceiling, budget and resources) and receives typed completion, failure, decision and attention events. Instructions and results stay with the session, and receipts keep only delivery references. A read-only projection of the original runtime attempt shows what actually ran, and rework can target up to 16 artifact revisions of the owning session.
- **Bounded main context** — The assistant conversation is organized into logical segments and work sets. Direct user text that must survive is pinned with a hash, old tool output leaves by default, and every model request fixes its material list, source hashes, memory revisions and capacity snapshot. When required text does not fit, the request blocks explicitly instead of truncating, and later retrieval never backfills into a request that was already sent.
- **History that stays out of the prompt** — Ordinary session history is indexed incrementally with persisted checkpoints and a visible coverage count (indexed, pending, unreadable; text only, with messages whose attachments remain unparsed reported). Search and extraction run on demand, and the assistant's own context history is queried separately from ordinary history.
- **Persistent delivery** — Completion, failure, decision and attention events are appended as immutable, deduplicated references and consumed through prepared, entered, handled, attention and delivered states. The assistant is woken through its original admission with a hidden internal input, and a result must be read from the real source before delivery is acknowledged; an acknowledgement means handled, not read, accepted or authorized. Cold start reconciles work that actually completed without re-running inference or dispatching it again.
- **Assistant views** — A management menu on the assistant page opens memory, context, history and delivery details in the existing dialog pattern: memory search with state, validity and source read-back, context segments with pinned evidence, indexed-history search, delivery progress, and the requested-versus-effective execution configuration. Decisions link back to the original session, where you answer them.

## Improvements

- Assistant memory methods and change events travel over the existing routed transport; the handshake or window workspace must match the target, and neither memory nor sources accept a client-specified disk path.
- Model context edits replace what an assistant request sees, so material that left the working set cannot return through the ordinary task-continuity injection.
- The brand entry is centered on the viewport and reserves space for the existing left and right controls; on narrow windows it builds its tool menu from the existing action registry, so every original action stays reachable.
- Drafts, focus and navigation behave like any session: an explicitly loaded ordinary session is not replaced by a late assistant read, and the assistant's own draft is kept separate from ordinary session drafts.

## Bug Fixes

- **Forgetting** — Forgetting suppresses the entry and the historical revisions of the same source, clears an open source preview and rejects late reads from that source; re-extraction from a forgotten source is refused instead of silently re-creating content.
- **In-flight responses** — A response is checked against its materials before release; a response whose materials expired keeps its usage and execution evidence but does not become a delivery and cannot continue running tools.
