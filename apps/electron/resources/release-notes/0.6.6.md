# Phaneris 0.6.6

This release carries the frontend audit and the sidebar refinement, and backports
eight runtime fixes from upstream v0.15.4–v0.15.10. The accessibility work is the
largest part: the audit's opening measurement of 721 axe findings is down to the
rules listed below, with the remaining groups named under Compatibility.

## Features

- **Filterable resource lists** — Skills, Sources and Plugins gain a filter field that narrows rows by the text the user sees, not by markup. An active filter with no matches says so and offers a clear action instead of claiming nothing is configured; Escape clears the query rather than closing the surface behind it.
- **Layout primitives** — `Stack`, `Cluster`, `Center`, `Truncate` and `Switcher` ship in `@phaneris/ui`; `Switcher` responds to its container, not the window. A `check:design-drift` counter freezes the hand-rolled centered-block pattern so it cannot be copied into the next empty state.
- **Shared Button atom** — `Button` moves into `@phaneris/ui`. The renderer keeps its import path through a re-export, and the Web client's error and crash screens use the atom instead of hand-written tags, inheriting the control height, focus ring and pressed treatment.
- **Session filter as a tested function** — The 110-line session-visibility `useMemo` becomes `lib/session-filter-model.ts`, pinned by 13 tests covering archive-only filtering, descendant label expansion, project include/exclude and the non-session surface.

## Improvements

- **Readable columns in narrow windows** — Columns now concede in a defined order: the sidebar drops to its 48px rail, the navigator narrows toward its 220px floor, and only then is it hidden. The content column holds a 480px floor, with panel sashes subtracted from the budget. Measured content width at an 800px window rises from 288px to 486px; nothing changes above 1024px.
- **Sidebar refinement** — Main navigation icons are 20 × 20px with identical centers in both states; rows are 34px on a 36px pitch; the collapsed rail is 48px wide with a 24px center; child rows use 14px icons in 28px rows. The menu role keeps its own 16px icon, the footer aligns a 22px avatar with a 20px settings icon, and the new-session control uses shared ghost surfaces. The top-bar brand mark is unchanged. The 60px touch rail keeps at least 44px targets.
- **One type scale** — The duplicate `.craft-text-*` family and the `--ui-*-size` variables are gone, replaced by the contract tiers. Assistant prose now renders on the reading tier with its own 1.7 line-height, while the user's prompt stays on the body tier. Settings pages emit a page `h1` above `h2` sections, and panel titles are documented as body size rather than left to drift.
- **Honest loading states** — `EntityList` takes `loading`, withholds the empty state until the request answers and marks the container `aria-busy`. Three inline resource fetches in `AppShell` become `useWorkspaceResources`, returning `{ items, loaded }` per resource so the distinction cannot be dropped. A failed fetch counts as answered and is logged rather than shown as a permanent spinner.
- **Startup paints the loader** — The inline loader was transparent for a 300ms delay that could not run before bundle evaluation, leaving the window blank for roughly 2.5s. It is now visible at parse time. The 2.9s FCP that motivated the investigation belonged to a window hidden until `ready-to-show`; the perceived first paint is the separate startup surface, which completes about 1.2s after launch.
- **Semantic shell** — The toolbar is a banner, both navigation columns are named navigation landmarks, and each content pane is a named region qualified by its session title or surface id. `html lang` follows the active locale, the composer textbox has a name, and selected rows carry `aria-current="page"` instead of a colour tint alone. Heading level is a per-route decision in `lib/navigator-heading.ts`; Board, Calendar, Timeline and full-width panels supply their own `h1`.

## Bug Fixes

- **Tab order** — `nav.nextZone` had taken Tab, so 40 presses produced four stops and the composer's Send button was unreachable. Zone cycling moves to F6 / Shift+F6 with a `nav.previousZone` action, its label in all seven locales and a shortcuts-page entry. Tab now walks 21 distinct controls and reaches Send.
- **Controls inside controls** — Sortable rows drop the interactive role that dnd-kit spread onto the wrapper and keep pointer dragging only. Kanban cards become plain containers whose title is a real button with a stretched hit area, so the tile's own controls keep their own clicks; the session row's status chip becomes a sibling of the row button.
- **Kanban flag** — The stray filled dot becomes the product's 13px outline flag, placed after the project name and given an accessible name in all seven locales.
- **Popover triggers** — Controlled edit popovers use `PopoverAnchor` instead of stamping trigger attributes on a zero-size span, and the working-directory badge forwards trigger props to its own button. A panel title menu is now the trigger with an `aria-hidden` chevron, and the settings "more actions" control is a real button rather than a mouse-only `div`.
- **Contrast and target sizes** — Measured failures are fixed rather than assumed: board status pills, calendar headings and gutter, mode badges, composer placeholders and the animated new-session slogan all move to roles that meet their surface. Small status, share, branch and subtask controls sit on the 26px control tier; sub-24px targets across the audited surfaces fall from 350 to 43. An `EntityRow` icon rule no longer squashes buttons to 11px.
- **Landmarks and names** — The remaining 49 loose resize handles are wrapped in a pointer-transparent named region, taking `region` from 458 to 0. `aria-allowed-attr` goes 27 → 0, `nested-interactive` 309 → 0, `page-has-heading-one` 11 → 0, `button-name` 24 → 0 and `aria-input-field-name` 14 → 0. Sidebar row names include their badge counts, and nested navigation landmarks are named per section.
- **Strict tool schemas** — Injecting tool metadata no longer deletes `additionalProperties: false` from Chat Completions or Responses payloads. Metadata is already declared in `properties` and `required`, so the strict field stays. Built-in and MCP tool metadata policies are unchanged when rich metadata is off.
- **Automation variables** — Prompt text, labels and Telegram topics use only the event-generated `PHANERIS_*` context, passed as written: no process environment, no shell escaping. Scripts and webhooks keep their own environment boundaries and prefix rules.
- **Webhook payloads** — Both variable syntaxes expand in a single pass, and inserted text is never expanded again. Object and array bodies expand per JSON value before encoding, and direct requests, immediate retries and the action copy saved for delayed retries share one path. Special object keys remain plain own properties.
- **Instruction discovery** — Project instruction files are collected from root to the working directory first, then only from that directory's subtree, with a six-level, 4,000-directory and 150ms soft budget. Hidden, dependency and build directories are skipped, directory links are not followed, and the cache is keyed by root and working directory.
- **Pi branch recovery** — A branch forks once at initialization and then reads its own journal; the cutoff is persisted as a custom non-model entry. An invalid anchor is rejected before the fork file is written, and an initialized branch keeps working when the parent file is unavailable.
- **Tool set changes** — A changed tool set waits for compaction on the old session and rebuilds only when idle and not retrying; otherwise it defers. Stop invalidates a waiting prompt through an epoch. Revoked SDK proxy tools are re-checked at host preflight, after dispatch and before execution, so the auto-source path cannot re-enable them.
- **Git branch query** — The active shared RPC uses an asynchronous argv call with a five-second timeout, bounded output and a hidden subprocess window. Detached HEAD, non-repositories and failures return `null` instead of blocking the process.
- **Automation loading** — Each matcher is validated and loaded independently, so an invalid entry no longer rejects the whole configuration. Valid entries load and reload on their own; the local contract still reports `success: false` with the specific error while applying the valid subset. Unknown events keep warning, and invalid JSON or a bad root structure keeps the previous configuration on hot reload.

## Compatibility

- Automation writes remain strict: tolerant reading never becomes a way to save an invalid matcher. Unknown event types still warn and are ignored rather than failing the file.
- Automation prompts that relied on inherited process variables or on double expansion of inserted text no longer receive either. Script and webhook actions keep their documented environment contracts.
- Instruction discovery's 150ms budget is checked between directories; a single synchronous filesystem call can still exceed it. The budget is not a promise that scanning finishes within 150ms.
- The workspace switcher keeps its avatar initial, so `label-content-name-mismatch` still counts that control's glyph (43 findings). Removing the letter was tried and reverted: the visible initial is worth more than the rule, and hiding it from accessible text would require rendering it as an image. The selected-row accent bar was also removed after a positional CSS rule turned it into a 16px disc; `aria-current` remains.
- `aria-required-children` (12 findings) is left as a design question: the session navigator is a listbox whose rows carry a status chip and a menu button. The honest fix changes the keyboard model, not the markup.
- The RPC contract snapshot changed only for seven line-number shifts in the shared system handler; 445 channels, 69 input contracts and the wire strings are unchanged.
- The architecture branch merged after the 0.6.5 tag is tree-identical to that release commit, so this release adds no second copy of its content.
- Cloud-disk startup handling (upstream C01) and macOS HEIC decoding (C02) are deferred as separate batches.

## Validation

- `typecheck:all` and `lint` pass across the workspace (2,700 files, 24 registered warnings), together with `check:docs` (239 documents, 1,833 relative links), the identity, version and four i18n gates, and the theme, scale-contract, design-drift, contrast-floor, visual-contract, UI-merge and file-size gates.
- Production Electron main, preload and renderer builds pass, including the Pi bundle and launcher, the network interceptor and the WhatsApp worker.
- The 29-surface axe audit covers the frontend batches. The sidebar workflow re-runs 13 browser scenarios against the production components, and the upstream backport runs 14 core scenarios through real traffic and 7 Pi scenarios through the real subprocess and SDK journal.
- The related legacy suites pass: 253 tests, 2 skipped (the existing script symlink containment case and a malicious-filename case unsupported on Windows).
- Real provider accounts, macOS and Linux execution, signed installers, an installed client and physical touch hardware are not claimed by this release preparation.
