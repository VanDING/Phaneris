# Phaneris 0.2.4

This release closes the gap to upstream 0.13.5 and 0.13.6 — twelve fixes, ten of which
were live defects here — and adds one genuinely new thing: an optional decision model,
off until you turn it on. It also fixes a class of bug in which the app did not
recognise its own data directory, and part of the permission model had quietly stopped
running because of it.

## Decision model (Jev)

A second model surface beside your chat model. Where the agent needs a judgement rather
than prose — classify this, route that, score these, yes or no — it can now ask a
decision model and get back **probabilities and a confidence, not a paragraph**, in a
fraction of a second and for a fraction of a cent.

- **Off by default.** Turn it on under **Settings → AI → Decision model (Jev)** and pick
  a provider: TypeSafe, OpenRouter, Vercel AI Gateway, a local `laya-serve`, or any
  custom endpoint. If you already have an OpenRouter or Vercel AI Gateway connection,
  its key can be reused.
- **One item or two hundred.** The agent can ask about a single piece of text, or hand
  over a batch of up to 200 and get the answers back in the order it asked.
- **Three kinds of question** — pick one of a fixed set, rate against criteria, or give
  a yes/no with a probability.
- **Below 0.5 means unsure**, and the agent is told to say so rather than pick. A high
  confidence is still an estimate.
- **The key never leaves the credential vault.** It is stored there and is not returned
  to the interface — not to this window, not to any other.
- **Every call is logged with a fingerprint, never the text.** One line per call in
  `~/.phaneris/logs/decisions.jsonl` records the SHA-256 and the byte count of what was
  submitted. The state text itself is not written, and provider error messages are
  dropped from the record because a validating gateway can echo the state back.
- **An answer is advice, not permission.** Nothing in the app turns a decision into an
  approval: it cannot approve a plan, widen what the agent may do, or stand in for the
  permission mode you chose. The agent is told to re-check the real state and the
  current mode before acting.
- The text you send goes to the provider **you** configured. Do not put secrets in it —
  and note that the agent can choose to ask a question in Explore mode, the most
  restricted one, so treat the setting as the control that matters.

## Permission checks that were not running

Three checks in the permission layer looked for the literal path `/.craft-agent/`. This
fork stores its data in `.phaneris`, so those branches never matched: the "writing
outside the application data" case and the "workspace root" case were both decided by a
comparison that could not be true. They now derive from the configured data root, and
still recognise the old name so an existing installation keeps working.

Related, the app now follows a custom data root everywhere: previously a second instance
shared the Chromium profile and the single-instance lock even when pointed at its own
data directory.

## Upstream fixes

Twelve fixes from 0.13.6, ported one by one.

**Writes you have allowed.** `allowedWritePaths` was only honoured in Explore mode. In
Ask to Edit you were still prompted for every write, including writes to directories you
had explicitly allowed. One matcher now serves both modes. (Note the match stays purely
textual, as upstream's does, and on Windows a POSIX-style pattern such as `/tmp/**`
cannot match — use `C:/...` or `~/...`.)

**Source credentials.** A source configured with a single header name stored its key
wrapped in JSON, so a source test could pass while every real call sent
`{"x-goog-api-key":"…"}` as the header value — a JSON blob where the key belonged. One
implementation now parses and assembles credentials for both the test and the live call,
so a passing test means real calls authenticate. Entering a credential through the
multi-header prompt for a single-header source unwraps it instead of sending the blob.

**Transcript paths.** With no session working directory, or one at a filesystem root,
tool paths are now recorded as they are. They used to be rewritten relative to the app's
own working directory, which turned `/Users/x` into `./Users/x` in the transcript.

**Compaction owns the turn.** A message sent while `/compact` runs is queued and
replayed, instead of being steered into a turn that has no agent loop left to receive
it. As part of the same fix, that replayed turn no longer tells the model the previous
response was interrupted and may be incomplete — it was not. A compaction that times out
now cancels its subprocess rather than leaving it running behind the turn.

**Silent turns and silent failures.** A turn that produced output tokens but no text —
what DeepSeek does when its reasoning exhausts the budget — now says so instead of
ending with nothing. MCP sources that fail to connect report themselves by name instead
of disappearing, and they are connected in parallel rather than one after another.

**Connection tests and the key you typed.** Testing an edited connection now uses the
stored key rather than the masked placeholder from the form, which had made a
correctly-configured connection fail its own test.

**Browser panes.** Closing a popup no longer throws inside its own close handler and
leave the popup registered forever, and tearing down a pane now detaches its debugging
session.

## Sign-in

- **OAuth sources and MCP servers** carry the RFC 8707 resource indicator through
  authorisation, token exchange and refresh, so servers that issue audience-scoped
  tokens accept them. If a server rejects the indicator, the request is retried once
  without it, and discovery now falls back across the well-known candidates.
- **Slack desktop sign-in** goes through your own relay's callback route. With no relay
  configured it stops with an error that names both remedies — configure one, or
  register the exact desktop callback URL with Slack and pin the port — rather than
  failing obscurely. It will not fall back to upstream's hosted relay.

## Models

- **Opus 5.5 and Opus 5 are available**, with their real 1M-token context window. They
  are additions to the catalogue, not a change of default: existing connections keep the
  model they had, and picking "Opus" still means Opus 4.8.
- **Retired DeepSeek v4 Flash ids migrate** to `deepseek-flash`, so a saved connection
  keeps working instead of failing on a withdrawn model.
- **Title generation no longer fails** on accounts that reject the configured mini
  model. The fallback chain tries the mini model first, then the model the session is
  already using, then the provider's own defaults — and only ever after a model is
  actually rejected, never as a speculative substitution.
- **No invented default model.** The task board no longer silently picks a model when
  none is configured; it says **Connect an AI provider to select a model**.

## Installer

The Windows installer is no longer the stock wizard. Every surface is drawn by the app:
buttons resolve hover, pressed, focused and disabled before anything is painted, and
keyboard focus is a proper ring instead of the native dotted rectangle, which is
invisible against a coloured fill. Progress is staged and its caption moves with it —
preparing, extracting, installing, finishing, cleaning — instead of sitting on one word
for the whole install, and nothing but the success path can paint 100%. The welcome page
no longer offers a licence link.

Confirmation dialogs that a server asks for now render as the app's own dialog, in your
language, instead of a native message box.

## Improvements

- The network interceptor's debug log — development builds only — is now size-bounded
  (32 MiB, with one rotated copy, and a 4 MiB cap per entry). Request bodies are replaced
  by a size placeholder unless you opt in with `PHANERIS_DEBUG_FULL_BODIES=1`. Previously
  the file grew without limit and full bodies, including prompts and images, were
  written to it.
- Tooltips on file paths strip the workspace and session prefix for both the current
  data directory name and the legacy one.
- The decision model's agent-facing guide ships with the app and is available to the
  agent while it works.
