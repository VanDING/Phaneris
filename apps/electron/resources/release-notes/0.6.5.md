# Phaneris 0.6.5

This release hardens task publication, session persistence and workspace
boundaries, and consolidates the shared interfaces used by the desktop, Web,
CLI and Agent tools. It includes the 0.6.4 assistant task-management milestone.

## Improvements

- **Recoverable task publication** — Publishing from the task editor or an Agent tool validates the complete operation before changing a task. Stable operation identities and a recovery journal let retries and restarts recover the same card and specification while protecting later edits.
- **Responsive assistant settings** — Identity and execution-mode changes use metadata-only requests. Opening a conversation loads its history separately, and existing full-history clients remain compatible.
- **Consistent planning** — Calendar, board and timeline views share the same Session-backed planning facts. Invalid patches are rejected before partially changing titles, projects or scheduling fields.
- **Shared mutation owners** — Pages owns its post-commit notifications and thumbnails; source access shares credential selection with explicit legacy compatibility rules. CLI and desktop clients share request exchange while retaining their own connection policies.

## Bug Fixes

- **Session write integrity** — Independent writers use exclusive temporary files instead of sharing a fixed filename that could mix or truncate a large conversation. Concurrent cold loads also preserve the order of subsequent status changes.
- **Workspace isolation** — A workspace-bound connection cannot search, mark all messages read or consume task output from another workspace. Explicit-target operations on unbound connections, intentional imports and global unread summaries remain supported.
- **Permission delivery** — Compound privileged commands and responses for the wrong Session cannot consume an approval. Remembered authorization is recorded only after successful delivery to the matching request.
- **Safe image replacement** — Image access checks canonical workspace containment, including links and junctions. Conversion or validation failure keeps the previous image intact.
- **Durable gateway settings** — Settings and bindings become visible in memory only after successful persistence; partial policy changes report their effective state and can be retried.
- **Transfer and import recovery** — Replayed chunks are checked by content, concurrent commits share one result, and published Session imports can reconcile their files and Runtime facts after interruption.
- **Viewer recovery** — HTTP, upload and paste share one public-Session decoder. Malformed messages produce recoverable errors while supported legacy fields and timestamp fallbacks remain readable.
- **Project deletion and writer ownership** — Project removal coordinates Session and Page references before deleting the project. Process-owned writer leases avoid admitting two writers during stale-lock recovery.
- **Navigation and shutdown** — Cold startup preserves the latest requested destination; rapid navigation waits for the previous snapshot read to close. Closing RPC connections no longer recreate reconnect timers that keep a process alive.

## Compatibility

- Newly imported history remains searchable and citable, but cannot alone establish a direct user statement or a new management authorization. Existing local history and memories remain readable.
- Legacy assistant GET/SET bridges still return complete history. Legacy calendar deletion still clears only the schedule, while work-item deletion retains its deployed void result.
- Sources missing `authType` retain the existing Pages/session distinction; explicit `none` never sends credentials. The public `@phaneris/shared/auth/github-copilot` compatibility entry is restored.
- This release contains the architecture implementation branch. The separate frontend layout and accessibility changes are not included.

## Validation

- The implementation passed full workspace validation, 30 targeted workflows and the seven-workflow Session foundation suite covering 53 scenarios. All 126 architecture review areas were revisited, and source identities and evidence hashes were checked.
- Electron main/preload/renderer, WebUI, Viewer, Pi subprocess and WhatsApp worker production builds passed. The aggregate server assembly check remains unsupported on Windows; native Electron/macOS execution, signed installers, live account coverage and the old-client version matrix are not claimed by this release preparation.
