# Phaneris 0.6.3

This release rebuilds the assistant context core around shared originals and
work branches. The assistant can move between independent goals without mixing
their materials or asking the user to restate requirements, while ordinary
sessions and Workers keep their existing linear, task-scoped behavior. It
includes the 0.6.2 desktop runtime and security updates.

## Features

- **Work branches** — Keep independent goals in separate work branches and switch back without restating the original requirements. A branch is a navigation and recovery identity inside the same assistant Session, not a second task, Session or message store.
- **Checkpoints and sleep** — Save a bounded checkpoint with confirmed requirements, open questions, next steps and source coverage, then sleep the work item. Restoring it returns the corrected requirements and evidence instead of an accumulated transcript.
- **Task-scoped Workers** — A Worker receives only the materials for its delegated task. Selecting, sleeping or compacting another work branch does not invalidate it, and a late result returns to its original work rather than the latest conversation.
- **Shared originals, linear ordinary sessions** — The assistant, ordinary sessions and Workers keep using the same original Session and Runtime execution owners. Ordinary conversations remain linear; no second message database or Worker engine is introduced.
- **Bounded context** — Work directories are paged and searchable, source reads return exact ranges and versions, and context capacity is handled with bounded materials, folded long results and a stable request view inside the assistant Session.

## Improvements

- **Automatic context management** — The assistant manages work branches and recovery through Host commands. Context management stays internal; the conversation header keeps More, Share and Close.

## Bug Fixes

- **Completed management actions no longer repeat** — After a checkpoint and sleep have succeeded, the next request carries their committed receipts, so the assistant reports the saved state instead of selecting the work again, saving another checkpoint or claiming the checkpoint was missing.
- **Checkpoint immediately after selection** — Saving a checkpoint after selecting or associating a work item uses the materials of the current request. A short read or association no longer causes a false “unread source” retry.
- **In-flight history** — A Session tool that is still running is shown as unavailable in a same-turn history read, never as a committed source or a completed result.
- **Exact source reads** — Reading one original through the memory owner no longer opens and decodes every message in its Session.
- **Shared source validation** — A single validation checks shared dependency ancestors once, avoiding repeated recursive work that can block the desktop and exceed Runtime receipt deadlines. Edits and revocation are checked again at the next boundary.

## Storage

- **Context metadata** — Work branches, associations, checkpoints and request views live in `workspace/context.db`; original Session JSONL and Runtime facts stay with their existing owners. Legacy `assistant/context.db` metadata is imported read-only when present, and ordinary sessions are not rewritten.
