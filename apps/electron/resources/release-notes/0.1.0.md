# Phaneris 0.1.0

Phaneris is a fork of **Craft Agents** — the same application, renamed and
repointed, with three deliberate changes in what it does with your data. This is
the fork's first release, so everything below is a comparison against upstream.

## A different application, not a different build

- **Its own identity throughout** — Phaneris, app id `io.github.vanding.phaneris`,
  `phaneris://` links, `@phaneris/*` packages, a `phaneris` CLI.
- **Installs alongside upstream** — data lives in `~/.phaneris` and the userData
  directory is pinned to `Phaneris`, so the two share no caches, locks, or
  protocol registration.
- **One file defines all of it** — checked in CI, so a rename cannot leave a
  stale path behind; runtime paths derive from it rather than hardcoding.
- **Its own icon set**, generated cross-platform from one artwork file.

## Nothing is published to a third party

- **Conversation sharing is closed.** Upstream uploads a whole session — every
  message, tool call, and path — to a hosted viewer. That is now refused on the
  server, not just hidden in the UI, so a stale or browser client cannot reach
  around it. Withdrawing an existing share still works.
- **Page publishing is closed.** Pages stay local. Unpublishing a previously
  published page still works, because withdrawing something must never depend on
  the feature that published it.
- **Crash reporting is opt-in** — inert until you set both an ingest URL and
  `PHANERIS_TELEMETRY_ENABLED=1`, and scrubbed before sending.
- **No remote icon lookups.** Provider logos are bundled, and a test rejects a
  URL literal in that table, so connecting an account cannot tell a third party.

## Documentation ships with the app

- **46 pages inside the application** across thirteen sections. Upstream's help
  links point at a website documenting a different product.
- **The agent was being sent upstream too** — the system prompt and bundled
  guides told it to fetch setup guidance from that website, whose content was
  never in this repository. They now point at what is installed locally.
- **Corrections made while writing it** — the guides claimed skills are invoked
  with a slash command (they use `@mention`), named a CLI binary that no longer
  exists, and referenced sixteen service setup guides that shipped nowhere.

## Its own release line

- **Version 0.1.0**, with a guard that fails the build if it drifts between the
  manifest the app reports, the one the installer is stamped from, and the
  lockfile.
- **Auto-update says so when it cannot update.** Upstream's packaging config
  produces no feed, so every check failed and the failure surfaced as "You're up
  to date" — success for a check that never happened.
- **Upstream's release history removed** — 74 version notes describing versions
  this product has never been, which would have been announced in-app as latest.

## Moving an existing profile over

- **`bun run scripts/migrate-legacy-profile.ts`** copies a profile from
  `~/.craft-agent` to `~/.phaneris` and rewrites the paths pointing at the old
  root. Read-only on the source, dry run by default.
- **Credentials must be re-authorized once, and that is deliberate.** The vault
  key is an OS-protected blob bound to the application that wrote it; copying it
  would not preserve access, it would guarantee the new build can never unwrap
  the key nor create a fresh one — a windowless process on first launch.

## Fixed in inherited behaviour

- **The terminal follows the theme** — it rendered black on a light theme
  because the bundled stylesheet hardcodes it and the theme bridge produced an
  invalid colour.
- **Windows caption buttons no longer cover overlay headers** — the strip is
  measured from the system, so it adapts to display scaling and maximize state;
  nothing moves on macOS.
- **The app icon uses the mark's own bounds**, not the artwork canvas whose
  margins left the glyph at about half the tile.
- **A shipped default no longer violates its own type** — it carried a thinking
  level that is not a valid value and resolved only through a shim marked for
  removal, and the code fallback had drifted from the file it mirrors.
- **The network interceptor stopped pinning the data directory** at module load,
  which had made `PHANERIS_CONFIG_DIR` ineffective for the processes needing it.

## Breaking changes

- **Data lives in `~/.phaneris`.** Nothing is copied automatically and upstream
  keeps its own data. `CRAFT_CONFIG_DIR` is ignored on purpose — pointing the new
  product at the old app's live database is how two applications end up writing
  one state file. `PHANERIS_CONFIG_DIR` pointed at the old directory works as a
  transitional bridge and warns.
- **`CRAFT_*` environment variables are now `PHANERIS_*`.** One exception is
  honoured for a transition: webhook secrets in your shell profile (`CRAFT_WH_*`)
  still work and log a one-time notice naming the replacement.
- **Script and page-refresh variables use the new prefix only**
  (`PHANERIS_WORKSPACE_PATH`, `PHANERIS_PAGE_SLUG`, `PHANERIS_EVENT`, …). The old
  names are not injected alongside, so such a script needs updating.

## Not in this release

- **Self-update and packaged installers.** There is no release feed, so the
  installers refuse to run without an explicit `PHANERIS_RELEASE_BASE_URL` rather
  than silently installing a different product. Build from source.
- **Service endpoints still point upstream** — OAuth relays, the version
  manifest, the update feed. Features depending on them either work against
  upstream or are disabled.
- **Documentation is English only.** The structure supports more locales; only
  English is written.
- **macOS auto-update would need a code signature**, which is why no feed is
  wired up yet even though Windows and Linux would work.
