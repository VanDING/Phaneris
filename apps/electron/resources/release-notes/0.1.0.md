# Phaneris 0.1.0

Phaneris is a local-first agent workspace for work that lasts. Sessions, tools,
files, and results live on your machine, keep running across restarts, and leave
a record detailed enough to understand afterwards.

It is a fork of Craft Agents — independently named, independently maintained, and
free to make different choices. This is its first release.

## A workspace, not a chat window

The unit of work is a durable session rather than a disposable conversation.
Sessions, projects, labels, statuses, boards, calendars, and background tasks
survive restarts and remain available while you work on something else. Several
can run at once, and a long-running job does not need the window in front of you
to keep going.

Work is organized the way work actually accumulates: an inbox with real states,
grouped into projects, with the sessions that produced a result still attached to
it. Nothing depends on remembering which conversation it was.

Execution is durable by design. A workspace-local runtime records what has
already happened, so an interrupted run resumes from where it stopped, and
ambiguous effects are held for an explicit decision instead of being quietly
replayed or reported as finished.

## Runs that explain themselves

A run is not a stream of prose. Each session keeps an execution record: what was
asked, which tools ran, what they returned, how long each step took, how context
grew, what it cost, and where anything failed or recovered.

Four views answer four different questions — what happened at a glance, the
execution ledger turn by turn, how each model request was assembled, and how
related sessions and branches connect — and the record is navigable back to the
conversation, file, or review it refers to.

The point is trust. You should be able to check the work rather than take it on
faith, and to see the difference between a step that succeeded and one that was
never confirmed.

## One agent runtime, many providers

Every provider runs on the same agent kernel: one event contract, one tool
registry, one permission model, one session lifecycle. The runtime runs in an
isolated subprocess, so a provider or agent failure cannot become a second,
subtly different execution path inside the desktop app.

Hosted model providers, OAuth-backed subscription plans, cloud platforms,
OpenAI- and Anthropic-compatible endpoints, and local models all connect through
that same path. Model capabilities and reasoning levels are resolved from the
provider rather than hard-coded per vendor.

| Layer | Baseline |
| --- | --- |
| Agent kernel | Pi SDK 0.85.1 |
| Desktop | Electron 44.2, React 19.2 |
| Runtime and tooling | Bun 1.4.2, TypeScript 7, Vite 8.2 |
| Integrations | MCP SDK 1.29+, native REST, local, and browser tools |

## Appearance with real range

Themes are the user's, not the product's. A theme is a file you own, and it
controls far more than an accent color: surfaces, depth, borders, shape,
typography, icon weight, and component density. Themes apply at the app level
with per-workspace overrides, so a work context and a personal one can look and
feel different without either being a compromise.

The built-in default is deliberately restrained and immutable. Everything past
it is yours, and a theme can be partial — override what you care about and
inherit the rest.

## Local by default

Your workspace is yours. Nothing about a conversation is published to a hosted
service, the documentation ships inside the application rather than on a website,
and crash reporting stays off unless you turn it on. Connecting a model account
does not quietly notify anyone else.

Personal profile and activity stay on the machine and are kept separate from your
configuration: user-authored preferences are not mixed with observed usage, and
the profile is a local surface rather than an account.

## Getting it

Phaneris builds from source; published installers and self-update are not part of
this release. Setup is documented in the application itself, from the help menu.

If you are arriving from Craft Agents, Phaneris is a separate application with
its own data directory and its own identity, and the two can be installed side by
side without sharing state. Credentials are re-authorized once on the new
installation — a consequence of how the operating system protects stored secrets
per application, not an oversight.
