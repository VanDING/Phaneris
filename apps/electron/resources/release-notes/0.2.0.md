# Phaneris 0.2.0

This release adds installable plugin bundles, a clearer welcome for new sessions, and
questions that let an agent continue a run after asking for your input.

## Highlights

### Plugin bundles

A plugin packages skills, sources, and a standing instruction using the Agent Plugins
1.0.0 format.

- Installing adds its skills and sources as ordinary workspace resources you can edit or
  disable. Reinstalling preserves the plugin's data directory.
- Start a plugin from the slash menu or by name. Its sources and instruction become
  active for the session; skills are listed for the agent to open when useful. One
  plugin is active at a time. The active plugin appears beside the permission mode.
- Plugin resources overwrite matching workspace resources rather than merging. Before
  writing files, installation lists conflicts and shows the exact command for any
  bundled server. Failed plugins remain visible with an error. Uninstall removes
  resources used only by that plugin and keeps shared resources.
- The Plugins sidebar lists installed bundles and opens each bundle's manifest, skills,
  sources, and uninstall action.

### New-session screen and Graphite theme

An empty session now opens on a welcome surface with the Phaneris mark and composer as
its primary action. The new Graphite theme offers a quiet, colorless look and is
editable like other themes.

### Questions during a run

When the agent needs your decision, it can ask in the conversation and wait without
ending the run. Work resumes after you answer.

## Improvements and fixes

- **Consistent Phaneris identity.** The system prompt and bundled guides now name
  Phaneris. The environment marker moved to the end of the prompt to keep version
  changes from invalidating its cached prefix.
- **Page compatibility.** New pages use the phaneris-pages/v1 bridge. The host continues
  to accept and emit craft-pages/v1 so pages created before the rename keep working.
- **Windows packaging.** Windows builds now identify Phaneris as the publisher instead
  of the upstream project.
- **DeepSeek model selection.** deepseek-flash now resolves to the canonical model ID
  recognized by the pinned Pi SDK.
