# Phaneris 0.2.0

Phaneris is a local-first agent workspace for work that lasts. Sessions, tools,
files, and results live on your machine, keep running across restarts, and leave
a record detailed enough to understand afterwards.

0.1.0 was the first release under this name. This one adds the biggest missing
piece: a way to install a whole capability set at once instead of assembling it
by hand.

## Plugin bundles

A **plugin** is a directory under `plugins/` that packages capabilities together
— skills, the sources they need, and a short standing instruction — following the
Agent Plugins 1.0.0 package format.

Installing one materializes its skills into `skills/` and its sources into
`sources/`. From that moment they are ordinary workspace resources: editable,
disable-able, and visible in the sections that have always owned them. A plugin
is a way to *arrive* at a working setup, not a new layer that owns your files.

Invoke one by typing `/` and picking it, or `/name`:

```
/investment-analyst value Tesla against its peers
```

The plugin becomes resident for the session. Its sources are switched on, its
standing instruction is added to the conversation, and the agent is told which
skills it brought. Only one is active at a time — invoking another replaces the
first — and a badge next to the permission mode shows which one is current.

**Skills are listed, not force-fed.** The agent is told a skill exists and where
to read it, and opens it when the task calls for it. That is what keeps a
plugin's cost per turn flat instead of growing with everything it contains.

**Installing is a conversation, not a form.** Ask the agent to install a plugin
and it shows you what will be replaced and the exact command any bundled server
will run, verbatim, before anything is written. Plugins overwrite rather than
merge, so the conflict list matters. A plugin that fails to load shows up as a
broken entry with its reason rather than quietly disappearing.

Uninstalling separates what only this plugin provided — deleted — from what
another installed plugin still references, kept. Reinstalling over a plugin
preserves its `data/` directory, so plugin state survives an upgrade.

The sidebar's Plugins section lists what is installed and what each bundle
contributes; selecting one opens its own page with the manifest, its skills and
sources, and the same uninstall confirmation.

## New-session hero, and a graphite theme

An empty session is no longer an empty panel. It opens on a brand surface built
around the mark, with the composer as the only primary action — the first screen
says what the workspace is for instead of showing a void.

A new **Graphite** theme ships alongside it: a deliberately colourless theme for
people who want the interface to recede. Its token choices and the density
decision behind them are documented, and it is a normal user-editable theme
rather than a special case.

## The agent can ask, mid-turn

An agent that hits a genuine fork — two reasonable interpretations, a
destructive step that needs a decision — can now ask you and **keep working**
while it waits, instead of ending the turn to get an answer. The question
surfaces in the conversation, and the run resumes with your answer.

## Improvements

- **The product names itself consistently as Phaneris.** The system prompt's
  environment marker is `<phaneris_environment …/>`, moved to the end of the
  assembled prompt so an app-version change no longer invalidates the cached
  prefix; the assistant introduces itself as running in the Phaneris desktop
  app; and the bundled agent guides no longer call the product "Craft". Menu,
  re-authentication, and backend labels keep their existing wording.
- **Page authoring uses the `phaneris-pages/v1` bridge envelope.** Pages built
  from the current scaffold emit the new name and accept both; the host still
  accepts and emits the legacy `craft-pages/v1` envelope, so pages built before
  the rename keep working.

## Bug fixes

- **Packaging no longer ships the upstream company as the app's `CompanyName`.**
  Windows builds identified the publisher as the project this codebase grew out
  of. Phaneris packages as itself.
- **`deepseek-flash` resolves to the canonical model on the pinned Pi SDK.** The
  model was offered under an id the pinned SDK does not recognise, so selecting
  it could fail to resolve.

## Getting it

Phaneris builds from source; published installers and self-update are still not
part of a release. Setup is documented in the application itself, from the help
menu — including a guide to installing and editing plugins.
