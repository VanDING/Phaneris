# Phaneris 0.3.0

This release brings the upstream 0.14.0 work, Pi SDK 1.0.2, and the dependency
upgrades together. Decisions now leave an outcome and a cost record, MCP tools can
be discovered as needed and composed under the workspace's permissions, and
Markdown Artifacts can be edited visually or as source. Messages sent during a
turn also show whether they were saved and whether the SDK received them.

## Decisions that stay attached to the work

The optional decision model now serves individual features: Guarded permissions,
risk badges, adaptive thinking, skill and source suggestions, large-result
previews, mid-turn delivery, turn outcomes, smart titles, automation conditions,
semantic labels, task verdicts, and targeted task repairs.

- **Each feature has its own switch.** New switches start off. Existing explicit
  verdicts, regex label rules, and manual edits keep their authority.
- **A judgement stays linked to its result.** Decision records can carry an outcome,
  follow-up, or cancellation, so a recommendation can be followed through the work
  it influenced.
- **The cost belongs to the session.** Decisions and image generation join the
  durable usage ledger. Run distinguishes estimated prices from unknown costs,
  and Task budgets include auxiliary tokens after a restart as well as during
  the original run. A local decision report summarizes the recorded usage.
- **Uncertainty follows the existing policy.** Low-confidence answers, failed
  providers, and malformed responses leave each feature's fallback in charge.
  A decision cannot grant a permission or override an explicit user choice.

Task definitions can also set a limit on consecutive turns without progress.
Unsupported execution nodes are rejected before a task starts.

## MCP tools, discovered when needed

MCP tools now retain their output schemas, annotations, structured results, and
content blocks through the agent path. Deferred discovery exposes the tools a
turn needs, and managed codemode lets the agent compose calls.

- **Every nested call passes through permissions.** Calls keep their source,
  parent, and execution identity in the durable record. Stopping a run cancels its
  managed work, and an interrupted effect remains unknown when completion cannot
  be confirmed.
- **Workspace rules can block a tool call before it runs.** These rules add
  restrictions; they cannot widen the permission mode.
- **Sources remain owned by the workspace.** Codemode's model access is disabled,
  and activating a source requires a fresh permission check.

The MCP HTTP server also gives each stateless request its own protocol instance.
Repeated and concurrent requests preserve their results and source ownership.

## Edit Markdown Artifacts without losing the source

The Artifact workbench now has a visual Markdown editor and a source editor, with
undo and the existing revision, lease, and conflict checks.

**Opening a document no longer rewrites it.** If the visual editor's initial
normalization would change the Markdown, the original draft is kept. Chinese
text, formulas, Mermaid diagrams, task lists, links, images, comments, and tables
are checked through saving, submitting, and accepting a revision.

**A conflict keeps your draft.** A rejected save leaves local work available, and
an edit made outside the workbench is captured when a new editing lease begins.
The rich editor loads when it is opened.

## Saved and received are separate states

Messages sent while a turn is running now show the host's saved state separately
from the SDK's reception state. Two identical messages keep two identities, and
a late reception receipt updates that message without restarting completed work.
Input whose delivery is unknown remains available for review and is not replayed
automatically.

## Models and images

- **Pi SDK 1.0.2 is the agent kernel.** The model catalogue supplies its native image
  limits, prompt-cache metadata, and cost tiers. The old injected DeepSeek
  catalogue entry is gone, and thinking levels use the SDK's sampling defaults.
- **OpenRouter image generation uses Pi's image API.** Generated files are checked
  before acceptance, cancellation is recorded, and usage joins the session's
  ledger. Existing OpenAI Images support remains available.
- **Image input follows the selected model's limits.** Request copies preserve the
  original files. Oversized image histories offer an explicit linked text-only
  recovery path.
- **Model observations describe the response.** Diagnostics distinguish the model
  requested from the model returned and leave unavailable reasoning information
  unknown.

## Fixes

- Explore checks cover MCP writes and shell write or execution flags. Always Allow
  remembers scoped commands, folders, endpoints, and hosts, and child sessions
  stay within their parent's permissions.
- Requests with no approval handler are denied. Source activation results that
  arrive after Stop are discarded.
- Source retries retain attachments and corrections without adding a second
  visible user message. Automation loops and notifications from untracked
  background tasks are prevented.
- Remote decision settings and credentials use the target server. Missing
  source-test credentials are refreshed before retrying.
- Completion listeners use a stable snapshot, new label identifiers are
  normalized, and unchanged pending plans avoid unnecessary writes.
- Unsupported legacy AgentEvent actions are shown as unsupported.
- Confirmation buttons retain their spacing on desktop.

## Improvements

- Concurrent icon reads are shared within a workspace, and resolved skill metadata
  avoids probing for icons that do not exist. Initial permission reconciliation
  applies its results together while retaining version checks.
- The renderer fits the existing initial JavaScript size budget. Production
  builds ship the Pi subprocess's launcher, worker, and WASM resources.
- Desktop, document, networking, and build dependencies are updated, with checks
  that keep the packaged Electron and Python runtimes aligned with their pins.
- RTK token optimization requires version 0.44.0 or newer and offers update
  guidance and a re-check for older installations.

## Remaining validation

The measured production workflow still exceeds the three-second target for its
first navigation. Full replacement of the host MCP, classifier, and automatic
routing paths remains conditional on compatibility, lifecycle, recovery, and
quality checks. The reproducible results and migration requirements are recorded
in the repository's capability and Pi SDK assessment documents.
