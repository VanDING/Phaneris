## Features

## Improvements

- **The agent knows which repository it is working in** — The system prompt now carries a `<developer_context>` block for the session's working directory: the git repository root and its parent, the selected path inside the repository, the `origin` remote (with any embedded credentials redacted) and the default branch, plus standing guidance about treating uncommitted changes as user work, keeping diffs minimal, creating worktrees as siblings of the repository root, and not switching branches, resetting, rebasing or force-pushing without being asked. The per-turn half — current branch or detached HEAD, upstream, ahead/behind, worktree cleanliness and counts, and a sample of up to 20 changed files — rides the volatile user-message tail, so the cached system prefix stays stable across turns. Every git call is bounded to 700 ms and fails soft: outside a repository, the block is simply absent. Project context files are now discovered relative to the git repository root, and a session in `packages/api` sees the root `AGENTS.md`/`CLAUDE.md` plus its own subtree instead of every sibling package's instructions.

- **Automation guidance is a first-class part of the prompt** — The system prompt now has an `## Automations` section that states what automations are, where to read the automation guide before creating or modifying one, that validation beats guessing schemas, that automation-created tasks stay reviewable, that script actions run workspace-local scripts rather than shell snippets, and that label/status changes can themselves trigger automations.

## Bug Fixes

- **The context indicator reports real occupancy, not a frozen number** — The badge previously derived its figure from the last assistant message, so after a compaction it kept showing the pre-compaction total until the next turn finished, and the Pi SDK's own occupancy metadata was discarded. The subprocess now reads the SDK's authoritative `contextUsage` (and its compaction settings) at each turn boundary and after every message, forwards it before the turn can complete, and the manual `/compact` RPC returns the post-compaction estimate. The host stores occupancy as its own field — separate from the cumulative billing counters — and no longer re-publishes an unchanged count at a compaction boundary. When the context has changed but no fresh count exists yet, the badge shows "Usage unknown" instead of a stale number or a percentage computed from one.

- **A plan approval can no longer be sent twice** — "Accept & Compact" persists the pending plan, compacts, and then sends the approval. Live completion and reload recovery used to be two separate paths — an event listener plus a mount-time check with a fixed delay — each able to send its own copy, and the persisted record was stamped rather than claimed, so a second window or a remount could dispatch again. Both paths now share one dispatcher: the record is loaded, an atomic host claim decides which caller owns the dispatch (refused while the session is busy, while compaction is still running, or if someone else already claimed it), and only the winner sends and clears. The fixed delay is gone, replaced by the session's idle transition as a second wakeup.

- **Steering messages are no longer delivered one turn at a time** — Sending several messages while a turn was running left the agent addressing them across separate model calls instead of all together: the Pi SDK's steering queue defaults to `one-at-a-time`, which releases a single queued message at each model boundary, and anything still queued when the turn ended could be discarded by a queue reset. The subprocess now pins `steeringMode: 'all'` (craft-agents-oss#1040), so every message pending at a tool boundary reaches the model in the same call, in order, and later arrivals wait for the next boundary. Pinned by an offline SDK-level regression test that fails on the previous setting.

- **A crafted file name or preference can no longer inject instructions into the prompt** — Working-directory paths, the discovered context-file list, and user preferences were interpolated into their `<working_directory>`, `<project_context_files>` and preferences blocks without escaping, so a directory from a cloned repository, a crafted file name, or a saved preference value could close its block and have the remainder read as instructions rather than as content. All prompt-injection escaping now lives in one shared module (`prompts/prompt-sanitize.ts`, replacing two private copies): control characters are stripped, closing tags are neutralized case- and whitespace-insensitively, values placed inside quoted attributes are escaped, repository URLs are relieved of embedded credentials, and the preferences block is wrapped in `<user_preferences>` with each line sanitized.
