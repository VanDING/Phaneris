# 消息平台

消息接入将外部聊天与 Phaneris 会话绑定。从聊天发送的请求进入同一会话，代理回复按平台支持的格式返回。

| 平台 | 接入特点 |
| --- | --- |
| Telegram | Bot Token；支持工作区超级群与论坛话题 |
| WhatsApp | 关联设备扫码，可使用“给自己发消息” |
| Lark / 飞书 | 分别选择部署区域，配置应用身份与事件连接 |
| 微信 | 扫码登录，依赖对应设备会话 |
| 企业微信 | 智能机器人长连接，配置 Bot ID 与 Secret |

具体可用性依赖实际平台账户、权限、网络和部署，不因源码包含适配器就等于已经完成所有真实账户验收。

## 配对

在应用会话中发起配对，取得短期有效的一次性代码，再在目标聊天发送 `/pair <code>`。错误尝试受速率限制；过期后应生成新代码。

| 指令 | 作用 |
| --- | --- |
| `/new [name]` | 新建并绑定会话 |
| `/bind` | 在支持的入口列出近期会话并按 id/序号绑定 |
| `/pair <code>` | 完成应用发起的配对 |
| `/unbind` | 解除绑定 |
| `/status` | 查看当前绑定 |
| `/stop` | 请求停止当前运行 |
| `/help` | 查看当前平台实际可用指令 |

## 谁可以使用

Telegram 和企业微信提供 `owner-only`/`open` 访问模式、所有者名单及待批准发送者。建议使用 owner-only；开放模式意味着能接触机器人的人可能发起机器上的代理工作。

WhatsApp、微信和 Lark/飞书在当前实现中没有同等的应用内 owner 名单。需要通过平台账户、可见范围、群成员与应用安装范围控制访问，不能假定其他平台的白名单自动生效。

## 话题与交互限制

Telegram 工作区超级群可以为不同工作流分配论坛话题，自动化可使用 `telegramTopic` 路由。

权限、凭据和计划审阅仍可能只在应用内提供。外部聊天不等于拥有完整桌面交互能力；处于询问模式的无人值守会话可能等待你回到应用。长文本、表格和附件会按平台能力转换，原始会话记录仍以应用为准。
