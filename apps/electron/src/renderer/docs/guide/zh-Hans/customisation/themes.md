# 主题

主题使用 JSON 定义界面语义令牌。内置主题为 `default`、`ink`、`geek`、`cyberpunk-2077`；这些稳定 id 优先于同名用户文件。用户主题位于 `~/.phaneris/themes/<id>.json`。

## 选择与继承

当前宿主的主题选择从临时预览、工作区选择到应用默认依次解析。未设置工作区主题时继承应用设置。具体项目或宿主的覆盖以其界面提供的范围为准。

自定义文件可以只覆盖部分字段，其余继承默认主题。读取失败会回退并显示诊断，不应被显示为健康应用的自定义版本。无效 CSS、透明的 `popoverSolid`、缺失的背景图片和未知 Shiki 名称都会影响主题校验。

Geek 与 Cyberpunk 强制深色。其他主题可按浅色、深色或跟随系统模式显示。阅读尺度和界面尺度是不同角色；根字体与 rem 行为不应被当作任意覆盖全部组件的快捷方式。

## 文件与设置

主题 id 来自文件名。更名后，仍指向旧 id 的选择可能回退，因此应通过可用设置入口维护引用。用户主题目录不会被应用当作临时缓存清空或重置。

旧的 `~/.phaneris/theme.json` 如存在，会一次性复制为 `themes/migrated-custom.json`，原文件保留但不再直接参与渲染。

应用设置中的 `themeMode`、`colorTheme`、`themeFont` 是持久选择。渲染缓存用于减少启动闪烁，不是第二个配置权威。修改设置后，文件及图片变化、断线重连应加载对应的当前主题版本。

## 编写与检查

从少量语义令牌开始，使用 `accent`、`success`、`destructive`、表面和文字层级表达用途。背景图片或渐变不要影响正文可读性。检查明暗模式、菜单、弹层、长文本及工作台，而不仅是主聊天区。

## 排查问题

文件必须是有效 JSON，扩展名正确。主题只有部分变化时，检查组件实际使用的语义令牌。启动短暂闪现错误主题时，可在外观设置中重新选择，核对持久配置与缓存。回退诊断指出的图片或语法问题需要修复，不能仅靠反复选择消除。
