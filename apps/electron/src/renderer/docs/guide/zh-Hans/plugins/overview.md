# 插件

插件把相关技能、来源声明与常驻说明组织为一个能力包。它属于当前工作区，不同工作区可以安装不同版本。

## 激活与可用性

输入 `/` 选择插件，或使用 `/名称`。每个会话同时只有一个激活插件，切换插件会替换当前常驻上下文。激活后加入 `PROMPT.md` 指令、声明原生技能名单，并按现有规则选择来源。

**激活不等于能力已经可用。** 插件详情区分未物化、需要配置、需要认证、缺少执行文件、已禁用和已配置。已配置也不能证明当前会话已经成功连接；连接要由会话实际核查。

取消激活会移除插件上下文，但已经选择的来源仍可驻留在会话中。需要关闭访问时，应在来源选择中移除；不会暗中改变你手动选择的其他来源。

## 包结构

```text
<工作区>/plugins/<name>/
  plugin.json            清单，名称须与目录一致
  skills/<slug>/         包内技能
  mcp.json               MCP 声明
  phaneris/sources.json   API/本地来源声明
  PROMPT.md              激活期间的常驻指令
  data/                  插件运行数据，重装时保留
```

## 安装确认

当前安装路径接受本地包目录。市场、自动更新、URL/归档对话导入不属于本轮已交付能力。

分析阶段列出将创建、替换或跳过的资源，以及本地服务器的完整命令和参数。正式写入前，你应审阅这些内容。确认计划绑定当前工作区、包的暂存快照和目标资源状态，短期有效且只能消费一次。确认后包或目标发生变化、换工作区、重复提交或计划过期，都需要重新分析和确认。

无效来源配置会在计划中显示跳过原因，不会先写技能再因已知配置错误半途失败。MCP 与扩展来源的重复 slug 会被拒绝。普通 header 不会被推断为 bearer 认证；只有声明 slug/type 而没有有效端点或目录的扩展来源，需要先通过原生来源流程配置。

## 编辑与重装

安装会把技能物化到工作区 `skills/`，来源物化到 `sources/`，之后由原生资源入口管理。激活名单读取这份原生技能的名称、描述和正文路径。修改包内副本需重新安装才物化；直接修改原生副本会反映在实际使用内容中。

`PROMPT.md` 的常驻指令保持即时更新语义，下一次消息会使用当前包内容。它与物化技能的更新语义不同。

重装按目录替换，不合并已删除文件，并保留已有 `data/`。将需要随版本分发的变更纳入安装包；不要假定任意本地改动在重装后都会保留。

## 卸载

侧栏菜单会先分析卸载影响：独占资源移除，共享资源保留。如果共享来源仍从待卸载包执行，必须先迁移实际 provider，系统会拒绝破坏它。卸载确认同样一次性绑定目标状态，变化后需要重新分析。

安装失败会尽力回滚；恢复不完整时保留恢复副本并报告，不能把错误当作已成功。插件包拒绝符号链接等不满足路径和备份约束的内容。
