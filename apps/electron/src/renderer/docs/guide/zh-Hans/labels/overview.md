# 标签

标签表示会话的主题，状态表示工作流阶段。新工作区通常没有用户标签，可以按客户、领域、优先级等实际筛选需要建立。

## 层级与类型化值

标签可以嵌套。按父标签筛选可包含其子项，例如 `client/acme` 和 `client/globex` 都归入客户分类。

标签还可附带 `string`、`number`、`date` 或 `link` 类型的值，例如 `ticket::PROJ-1183`。类型决定规范化和显示方式；需要按数值或日期整理时，应选择对应类型，而不是把所有内容都保存为普通字符串。

自动应用规则可从用户消息中的模式提取值并加标签，详见[自动应用规则](phaneris://docs/labels/auto-rules)。

## 配置

标签保存在 `<工作区>/labels/config.json`，可通过设置中的标签入口管理。会话引用稳定 id；改显示名称比重命名 id 更安全。直接改 id 不会自动修复所有已有引用。

保持分类含义一致，优先增加有意义的层级，避免不断增加近义的平面标签。只有确实用于筛选和整理的标签才需要保留。

## Task 保留标签

Task 编排器维护自己的任务标签族，用于把编排会话和子任务关联起来。不要手动重排、改名或删除应用管理的任务关联标识；业务上需要“任务”分类时，创建独立的用户标签。显示名称和内部任务编号格式不是对外稳定 API，不应靠它们替代 Task 的持久关联字段。
