# 文档工具

代理可通过应用资源中的文档脚本读取或制作 PDF、Word、PowerPoint、Excel、图片和日历文件。脚本在本地运行，通过显式参数调用；读取的内容若用于模型推理，仍可能发送到所选模型服务，应按模型连接的数据处理方式理解。

## 格式能力

| 格式 | 常见操作 |
| --- | --- |
| PDF | 提取文字、组装、拆分、合并；具体排版与扫描识别取决于使用工具 |
| DOCX | 读取和创建文字、表格、样式 |
| PPTX | 读取和制作幻灯片 |
| XLSX | 读取、生成与编辑工作表和单元格 |
| 图片 | 读取元数据、尺寸处理与格式转换 |
| ICS | 读取与生成日历事件 |
| 文档差异 | 比较受支持的文件内容 |

实际入口以本版本提供的工具参数和格式能力为准。文件能生成不等于已完成视觉或公式验收；宏、复杂版式、外部链接和嵌入对象可能需要额外检查。

## 运行时

脚本位于应用资源的 `scripts/` 下。打包运行时由仓库的 provisioning 机制准备 Bun、uv/Python、ripgrep 及所需依赖；源码运行应先按仓库运行时检查完成配置，不应假定任意系统 Python 都具备同样环境。

Windows 的部分底层文档库需要 Microsoft Visual C++ Redistributable。启动或工具诊断显示缺少依赖时，按实际系统提示安装并重启，再重试失败场景。

## 何时使用

交付物本身是 `.docx`、`.xlsx` 或 PDF 时，使用文件工具并产出可打开的 Artifact。只是聊天内对比几个值时，用表格更直接。阅读现有 PDF 时可先预览；需要抽取、比较、变换内容再调用对应脚本。

处理长文档时，将工作目录指向具体材料文件夹，并说明页码、章节或表格范围，减少无关检索。

## 草稿与接受

生成文件后先打开预览，检查文字、页面、图表、计算结果和附件。Artifact 的修订/checkout 用于保留草稿，提交后接受才更新正式交付路径。接受失败或检测到外部修改时，应保留草稿并处理冲突；不要靠重复提交猜测是否已经成功。
