# 页面

Page 是保存在工作区内的小应用，适合持续查看同一类资料，例如阅读清单、项目状态或定期整理结果。

```text
<工作区>/pages/<slug>/
  page.json          标题、刷新计划和授权
  index.html         页面内容
  data/
    store.sqlite     刷新脚本的私有状态
    snapshot.json    页面读取的数据快照
  thumbnail.jpg      预览缓存
```

页面通常读取快照，脚本维护私有状态后再发布新快照。这样刷新失败时可以保留上一份完整结果，避免直接展示半写入数据。

## 刷新

使用受支持的 cron 刷新计划运行工作区脚本，读取来源、处理数据并更新页面。`page.json` 最后写入，作为刷新完成通知。不要用高频调度代替没有限流设计的轮询；页面刷新和来源调用都需考虑预算、幂等与失败记录。

## 动作授权

页面默认不能直接取得来源凭据或任意宿主能力。超出读取快照的操作应经过 action grant：授权绑定当前内容，有有效期，并记录审计事实。内容变化会使旧批准失效，避免把“批准过一个版本”扩展成“批准以后所有脚本”。

脚本类授权还受发布限制。不要通过复制旧批准或绕过校验恢复失效授权；应重新审阅当前内容和动作。

## 发布边界

本构建未启用上游托管 Page 发布服务，没有可供分享的公共 Page URL。历史撤回入口的存在也不表示新页面可以发布。页面使用外部来源或你主动导出数据时，仍应按实际通信和分享行为理解数据流向。

## 保持实用

一个页面尽量回答一个明确问题。刷新脚本应可重复、输出一致，并让读取界面能看见数据新旧。长期不再查看的页面可归档或移除；过期快照不应被当成当前实时事实。
