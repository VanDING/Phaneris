# 看板

看板把工作按列组织。当前工作项由 Session 的规划字段投影，列、列表、日历和甘特图读取同一组会话事实，不维护另一份独立任务存储。

## 列与状态

项目可以配置自己的列名、颜色和落卡状态。列名是用户内容，按原样显示。列位置与会话状态是不同字段；只有列显式配置了 drop status，拖卡时才会同时更新状态。

因此，把卡片拖到名为“完成”的列，不一定等于其会话状态已经是 `done`，更不等于 Artifact 已被接受。需要联动时，应在项目看板设置中明确配置。

## 多种视图

| 视图 | 主要用途 |
| --- | --- |
| 看板 | 按列组织与移动工作 |
| 列表 | 扫描、筛选和编辑字段 |
| 日历 | 按日期和时间安排工作 |
| 甘特图 | 查看层级、跨度与依赖线，调整普通任务起止日 |

普通叶任务可以直接拖动甘特条或调整边缘改期，行内日期按钮提供键盘替代。截止日包含当天；已有时间值会在日期调整时保留其时分秒语义。派生汇总和里程碑不从此入口拖拽改期，依赖和进度仍由任务编辑器管理。

保存期间显示反馈并避免重复提交，失败后回到已知规划值。筛选隐藏、工作区切换或广播刷新不代表可以把未保存的变化当成正式数据。

## 会话与 Task

卡片可打开其会话与规划；由 Task 编排产生的子会话还有 Task、run 和 node 的持久关联。编排器负责 DAG 的执行，不应把看板列顺序理解为节点依赖。

保持每个项目的工作目标一致，及时设置列状态联动。需要保留背景和审阅记录时优先归档，删除前核对数据范围。
