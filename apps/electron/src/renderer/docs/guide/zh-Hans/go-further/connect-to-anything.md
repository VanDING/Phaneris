# 连接外部系统

根据实际访问方式选择接入，而不是为所有服务采用同一工具。

| 方式 | 适用情况 |
| --- | --- |
| MCP 来源 | 有受支持的结构化工具，操作定义由服务器维护 |
| API 来源 | 有稳定 HTTP 接口，需要配置认证和访问规则 |
| 本地文件夹 | 资料已在宿主文件系统中 |
| 浏览器 | 一次性或必须通过网页完成的操作 |

## 如何选择

先检查服务是否提供合适的官方接口，以及其权限、认证和部署要求。周期性工作通常值得配置来源；一次查询不一定需要长期接入。浏览器可以应对必须交互的网页，但布局、登录和脚本行为更易变化。

Page 适合将已授权的数据处理为持续可读的快照，不会自动解决不稳定 API 或缺少授权的问题。[自动化](phaneris://docs/automations/overview)负责触发工作，也不替代来源认证。

## 限定范围

优先使用能满足目标的最小服务端权限，工作与个人身份分开配置。本地资料只选择需要处理的目录；需要可靠只读时同时核查工具和系统权限。

来源配置可让地址与规则更容易审阅，但 guide 中写出的操作说明不是安全边界。浏览器拥有登录状态时，能够触达该账户的网页能力；两者都要根据实际工具和认证限定范围。

## 常见障碍

认证失败先检查 Token、scopes、回调 URI 和账户可见性。必须交互登录的服务可能更适合浏览器。达到速率限制时，应减少请求、利用快照并安排有界调度，而不是不加控制地重试。
