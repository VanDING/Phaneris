# MCP 服务器

MCP 来源连接提供结构化工具的服务。工具通常以 `mcp__<来源slug>__<工具名>` 命名，使不同来源的同名操作能够区分，也便于按来源应用权限规则。

## 远程与本地服务器

| 形式 | 配置与注意事项 |
| --- | --- |
| 远程 HTTP/SSE | 指定服务 URL、支持的传输方式与认证；确认网络和代理能够到达 |
| 本地 stdio | 指定启动命令、参数与环境变量，通过标准输入输出通信 |

本地服务器运行在宿主用户权限下。安装前应检查程序来源和完整命令；它并不因使用 MCP 就自动获得操作系统隔离。插件贡献的 stdio 命令必须使用插件内路径，不能依赖裸 `node`、`npx` 等 PATH 名称。

## 认证

- 公共或本地服务可能不需要认证。
- Token/API Key 通过安全输入保存，由来源在调用时使用。
- 支持的 OAuth 流程会打开授权页面，并在服务支持时刷新凭据。部分服务要求提前登记回调 URI，应使用实际配置流程给出的地址。

普通 HTTP header 只是请求元数据，不能据此推断为 bearer 认证。认证方式必须明确配置。不要把秘密写进插件包或共享配置。

## 工具发现

连接时读取服务器公开的工具列表。服务端新增工具后，重新连接来源再确认列表。工具可见不等于当前账户有权执行所有操作；工具调用时仍可能因授权范围或权限规则被拒绝。

## 排查问题

远程连接失败时检查 URL、TLS、代理和服务可达性。本地连接失败时检查可执行文件是否存在、参数是否正确、依赖是否齐备，必要时在同一环境运行命令查看标准错误。授权错误应在服务自己的账户或开发者控制台核对权限范围。

没有 MCP 服务时，可以使用[API 来源](phaneris://docs/sources/apis)，无需为了接入一个 HTTP 接口先自行开发 MCP 服务器。
