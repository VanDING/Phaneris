# API 接口

API 来源用于连接 HTTP 服务。配置基础 URL、认证和使用说明后，代理可通过来源工具访问服务。适合已有稳定接口、需要重复调用的业务系统。

## 配置内容

| 项目 | 示例或用途 |
| --- | --- |
| 基础 URL | `https://api.example.com/v1` |
| 认证 | bearer、指定 header/query、basic，或受支持的 OAuth |
| 使用说明 | 请求方法、路径、参数、响应与业务约束 |
| 访问策略 | 允许的端点、路径与工具限制 |

使用说明帮助代理正确调用接口，真正的阻断依赖已配置的策略。不能只在 `guide.md` 写“只读”就声称服务端权限或文件系统已经隔离。

## 认证

API Key 和 Token 通过安全输入保存。支持的 OAuth 来源通过浏览器授权；自动刷新是否可用取决于来源类型和服务实现。原生 API 配置还支持 `renewEndpoint`，用于按已配置的续期请求换取短期访问令牌。需要正确配置请求和响应字段，不能假定任意自定义续期协议都会自动工作。

认证与固定 header 分开处理。例如 `X-Client` 这样的标识头不表示 bearer token，也不应要求用户为它提供一个并不存在的认证凭据。

## 权限层

API 端点策略可限制请求地址和操作；MCP 工具策略约束对应工具。会话权限模式与显式限制规则继续生效。策略已拒绝的调用应先修正配置或方案，而不是反复申请一次性授权。

服务有维护良好的 MCP 工具时，可选择[MCP 来源](phaneris://docs/sources/mcp-servers)。只使用一次的网页操作，也可以通过浏览器完成；长期维护不稳定接口会增加配置成本。

## 常见错误

- **401/403**：凭据失效、账户权限不足，或请求的认证形式不正确。
- **404**：核对基础 URL 与路径是否重复拼接，例如 `/v1/v1`。
- **无提示被拒绝**：检查端点与工具限制、会话模式及来源配置。
- **插件的 API 声明没有生成来源**：仅有 slug/type 不足以组成有效 API 配置。先按原生来源流程配置端点，再分析和物化插件；安装计划会显示跳过原因。
