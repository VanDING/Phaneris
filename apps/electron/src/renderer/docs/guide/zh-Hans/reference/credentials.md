# 凭据

Provider Key、来源 Token、OAuth 和消息平台秘密通过加密凭据存储管理。配置目录中的 `credentials.enc` 是凭据密文；桌面宿主可另外保存 `credentials.key`，用于保留操作系统保护的随机密钥。

## 密钥由宿主提供

桌面使用 Electron `safeStorage` 提供的系统保护。具体后端随 Windows、macOS、Linux 和当前登录环境变化。已有受保护密钥无法解锁时，应用保留原文件并报告问题，不应直接删除它来尝试“修复”。

服务端可通过 `PHANERIS_CREDENTIAL_KEY` 指定高熵密钥，按当前实现接受 16–64 字节的 hex/base64 编码。没有安装此类 provider 的兼容环境可能使用 machine-id 派生；这与桌面系统保护的保证不同，部署时应明确选择并保护密钥。

## 移动与备份

只复制 `credentials.enc` 不保证能在另一台机器、另一账户或另一宿主身份下解密。应用更名、系统密钥链状态和实际保护后端都会影响恢复，不应一概声称“同账户一定能恢复”或“一定无法恢复”。

工作区备份不包含全局凭据与其解密环境。迁移前根据部署的密钥方案安排恢复或重新授权，不要把受保护密钥明文放进普通备份与日志。历史迁移工具的排除规则也不等于通用跨机器凭据导入能力。

## 使用与轮换

通过安全凭据请求输入秘密，避免普通聊天和 notes。来源通过凭据标识在调用时取得所需值；OAuth 仅在支持的流程中自动刷新。正常配置文件不应内嵌秘密，但手工填写的 header、URL 或环境字段仍可能泄漏，分享前需检查。

怀疑泄漏时，先在服务方撤销或轮换，再更新本地配置。删除本地凭据只影响本应用，不使已泄漏的值在服务方失效。

移除或替换资源时，凭据清理由相应事务与共享引用规则处理。发生错误应核对提交结果和诊断，不要直接清空整个凭据库。
