# 模型连接

模型连接定义应用如何访问 provider 或兼容端点。多个会话可以选用不同连接；会话中的连接选择与工作区默认值是不同设置。

## Provider 与协议

已知 provider 使用其受支持的认证和模型目录；自定义端点需要明确提供基础 URL、协议和模型 id。所有连接走当前采用的执行后端，不能把某个 provider 名称当成另一个执行引擎。

未知模型的图像、思考等级、上下文等能力不能仅凭 URL 或名称猜测。自定义服务显示中性标识，不表示它被认证为某个厂商的官方端点。

## 认证方式

根据 provider 支持情况，可使用 API Key、bearer、OAuth、IAM、服务账户、环境凭据或无认证本地服务。订阅登录和 API Key 的适用范围不同，不应把某个账户订阅自动理解为所有 API 的额度。

秘密通过凭据存储管理；`config.json` 主要保存连接形状、模型列表和默认项。复制配置后仍可能需要重新授权。

## 运行中追加消息

当前连接和会话策略决定追加消息是用于 steer 当前运行，还是排队成为下一轮。具体提供的模式以界面和执行后端能力为准；不要根据 provider 品牌套用已退役后端的固定规则。

## 模型列表与辅助调用

连接维护自己的模型列表与默认模型，可刷新目录或限制显示范围。工作区默认连接影响新会话，已有会话仍保留其选择。

标题、分类等小任务可能使用辅助模型或独立决策层设置。这些调用有自己的预算、可用性和费用证据，不应假定都由当前聊天模型承担或免费完成。

## 排查问题

连接失败时检查凭据、地址、协议和模型 id。列表缺项时刷新当前连接并核对限制设置。删除 provider/连接后，已有会话引用需要重新选择可用连接；不能只凭同名模型判断仍有正确认证路径。
