# 权限

权限模式控制会话在执行动作前如何处理授权。它是宿主的执行策略，不应视为操作系统级隔离。

| 模式 | 行为与用途 |
| --- | --- |
| 探索（`safe`） | 以只读调查为主；不允许的写操作直接失败。适合先理解材料、分析和准备计划 |
| 询问编辑（`ask`） | 需要授权的动作先发起权限请求。适合逐项审阅修改 |
| 守护（`guarded`） | 以执行模式运行，判断模型标记为风险的调用会转为询问；判断没有返回答案时仍按执行路径继续。它不是询问模式的保守替代，只在相应判断功能可用时提供 |
| 执行（`allow-all`） | 在当前执行策略允许范围内减少询问，适合目标和操作范围已经明确的工作 |

模式显示在输入工具栏，可以在会话中切换。新策略影响后续动作，不能撤回已经发出的外部请求。

## 模式与规则

权限规则按应用、工作区、来源等范围配置；精细限制可约束具体工具、路径和端点。另有显式限制性 `tool-call-rules.json`，执行模式和 codemode 入口不能绕过已生效的阻断规则。

应用自带默认权限资料会随版本维护。不要依赖修改每次启动可能被刷新的一份内置副本；应在相应用户或工作区配置范围维护自己的规则。

探索模式存在为产出计划、Page 自有数据等设计的例外。浏览器和某些外部系统的动作不能仅凭文字指令被可靠划分为只读或写入。处理真实网站、凭据和不可逆操作时仍需核查当前工具的实际限制，不能仅凭“探索”标签承诺所有外部系统都不会变化。

## 权限请求

请求应显示具体命令、文件或工具。批准一次动作不会自动形成跨会话、永久有效的授权。若界面提供本会话内的记忆选项，应按其显示范围理解；改变权限模式和批准单次动作不是同一件事。

拒绝后，代理应依据反馈调整方案。不要在聊天中直接粘贴密码或 API Key；使用[安全凭据输入](phaneris://docs/reference/credentials)。

## 无人值守 Task

每个节点必须在 `nodes.<id>.permissionMode` 或 `defaults.permissionMode` 中获得显式模式。节点值覆盖默认值。任何节点都没有可解析的显式模式时，整个任务在派发前被阻止；旧任务恢复也按此规则检查。

显式填写 `allow-all` 仍是有效选择，但缺省、迁移或恢复不能替你选择它。文件范围声明也不会扩大权限。

```yaml
defaults:
  permissionMode: safe
nodes:
  - id: inspect
    prompt: 检查资料并给出建议
  - id: write
    permissionMode: ask
    prompt: 按已确认的方案修改报告
    depends_on: [inspect]
```
