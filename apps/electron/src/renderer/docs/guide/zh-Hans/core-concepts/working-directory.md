# 工作目录

工作目录决定会话中命令从哪里运行、相对路径如何解释。它显示在输入区，可按工作需要调整。

## 影响范围

- Shell 命令在该目录的上下文中运行，例如 `git status` 针对所属仓库。
- 工具和指令中的相对路径以该上下文解析。
- 相对文件写入通常落在此目录；绝对路径可以指向其他位置。
- 代理会把此处的文件结构视为当前工作材料。

工作目录不是权限沙箱。执行模式下，满足权限规则的绝对路径访问仍可能超出目录。本地文件夹来源也是独立配置；增加来源不会自动改变工作目录。

## 默认值与继承

新会话可显式指定目录；未指定时按项目绑定、工作区默认值与会话运行环境解析。项目目录变更不会自动搬移已有会话的材料。没有内容目录时，执行器仍需要自身的会话运行目录，不应假定其一定是仓库根目录。

Task 子会话优先继承编排会话的已解析工作目录，其次采用 `task.yaml` 的 `cwd`、工作区默认内容目录，最后使用工作区根目录。Task 会冻结本次运行的范围与目录；修改后应开启新运行，不能借恢复旧运行改变范围。

## 选择目录

将会话指向要处理的资料，而不是整块磁盘。修改单个软件包时可直接指向包目录；写作和整理材料时可选择对应文档文件夹。涉及不同仓库或隔离要求时，拆成不同会话更容易审阅。

## Windows

检查当前执行器所需的 Shell、可执行文件和 PATH。某个命令不可用时，应根据运行时报告定位缺少的程序或路径，不要套用已退役执行后端的设置。路径包含空格时应正确引用；工作目录改变不等于自动获得写权限。
