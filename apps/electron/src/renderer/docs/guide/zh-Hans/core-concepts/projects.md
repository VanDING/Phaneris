# 项目

项目在一个[工作区](phaneris://docs/go-further/workspaces)中组织服务于同一目标的会话。工作区划分来源与配置，项目则帮助管理同一代码库、客户工作或研究主题。

```text
<工作区>/projects/<slug>/
  config.json     名称、说明、默认值和看板列
  assets/         项目附件
```

## 会影响工作方式的设置

| 字段 | 作用 |
| --- | --- |
| 工作目录 | 项目中新建会话的默认内容目录；会话可以显式覆盖 |
| 详细说明（details） | 为绑定会话提供项目上下文，后续轮次也会使用 |
| 强调色 | 帮助在列表中识别项目会话 |
| 主题 | 为项目工作界面选择视觉主题 |
| 看板列 | 定义此项目的列，并可配置落卡时应用的状态 |

## 写好项目说明

适合写入长期有效的约束、资料位置和读者要求，例如：

- “本周处于发布冻结期，不要修改版本号。”
- “API 位于 `services/api`，迁移记录位于 `db/migrations`。”
- “交付给非技术读者，摘要使用业务术语。”

保持精简。说明会占用模型上下文，也不会随着工作自动更新。冻结期结束后应及时删除过期约束。

## 什么时候需要项目

多个会话共享目标、材料或长期上下文时适合建项目。若只是临时分类，使用标签通常更轻。项目的工作目录指向内容，工作区根目录存放应用管理的数据，两者可以不同。

## 看板与任务

项目看板的列可以独立配置；卡片放置位置与会话状态是不同字段，只有配置了落卡状态的列才会联动。当前工作项由 Session 规划字段投影，不维护第二份独立任务事实仓。

普通叶任务可在甘特图拖拽改期，或通过行内日期按钮使用键盘调整。汇总和里程碑不能通过此入口改期。高级字段仍在任务编辑器中管理。

归档项目会隐藏其日常入口而保留资料和会话绑定；取消归档后可继续使用。
