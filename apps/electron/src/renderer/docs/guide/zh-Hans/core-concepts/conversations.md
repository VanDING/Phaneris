# 会话

会话（Session）是一段持续的工作记录。它有标题、状态、标签和持久化消息，可以离开后再打开，适合同时管理多项工作。

## 开始会话

使用 `Cmd/Ctrl+N` 或新建会话入口。新会话采用当前工作区的上下文及默认设置。第一条消息最好明确目标、交付物和约束，方便代理理解工作边界与生成标题。

## 组织工作

| 操作 | 含义 |
| --- | --- |
| 状态 | 待办、进行中、待审阅、完成等工作流阶段 |
| 标签 | 主题分类，可分层、筛选，也可附带类型化的值 |
| 标记 | 快速保留需要回看的会话 |
| 归档 | 从日常列表中隐藏，保留磁盘记录 |

相关设置见[状态](phaneris://docs/statuses/overview)和[标签](phaneris://docs/labels/overview)。项目用于聚合同一目标下的会话；工作区用于划分资源和配置。

## 消息记录与 Run

记录包含代理输出、工具调用、结果、命令输出及交互请求。长文和计划可以在阅读视图打开；生成的文件可以通过 Artifact 或文件工作台预览。

Run 工作台还可显示此会话保留的 Runtime 事实，包括终态数量、未决 T1、最老等待、任务 Token 预算及重复动作/错误信号。重复只是一项观察，不能单独证明代理陷入循环；正常轮询、SDK 重试和压缩另行分类。已完成、效果已核清和用户已接受是不同事实。没有记录的费用保留为未知。

## 并行与恢复

启动另一个会话通常不会中断前一个，列表会显示执行与待处理状态。多个会话操作同一文件仍可能冲突；Task 的范围声明可以协调其子会话，不能替代所有手动会话的文件隔离。

消息和执行事实持久化后可在重启时恢复查看。但进程在外部调用派发后、结果提交前中断时，不能确定动作是否已经发生。此类未知效果会停放等待核查，不能把“重新打开会话”理解为自动重放全部未完成操作。

## 继续、分支与转移

- **继续**：打开已有会话，结合保留上下文继续工作。
- **分支**：从选定消息尝试另一方向，保留原会话。
- **发送到其他工作区**：使用应用的转移入口；目标来源、权限、文件路径与凭据需要按目标环境重新核对。
- **连接消息平台**：绑定后可从外部聊天继续。权限和凭据请求仍可能需要回到应用处理，见[消息平台](phaneris://docs/messaging/overview)。

删除会移除会话记录和所属附件，应用内没有通用撤销。只是暂时不看时应使用归档。托管对话分享未在本构建提供可用服务。
