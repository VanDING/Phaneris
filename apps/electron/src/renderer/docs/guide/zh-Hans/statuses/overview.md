# 状态

状态表示会话在工作流中的位置；标签表示主题。每个状态属于 `open` 或 `closed` 类别，用于区分仍需处理与已经关闭的工作。

默认配置包含待整理、待办、待审阅、完成和取消等状态；实际名称及可用项以当前工作区设置为准。待审阅有助于区分“代理停止执行”和“用户检查过交付物”。标为完成也不自动构成 Artifact 接受或外部效果核验。

## 工作区配置

```text
<工作区>/statuses/
  config.json    状态列表
  icons/         可选本地图标
```

| 字段 | 含义 |
| --- | --- |
| `id` | 会话引用的稳定标识，使用小写连字符名称 |
| `label` | 界面显示名称，可按工作方式修改 |
| `color` | 语义颜色或明确颜色值 |
| `category` | `open` 或 `closed` |
| 固定/默认标记 | 决定内置项能否删除、哪些字段必须保留 |

`todo` 和 `done` 是工作流依赖的固定标识；其他内置项是否可移除，以设置界面的约束为准。关闭类别和归档操作是两个维度，不应把状态设为 closed 理解为已经删除或归档文件。

## 选择一组有用的状态

保持少量、含义互斥的阶段，避免每次都在多个近义状态中猜测。可设置一个明确的等待状态；优先级适合用标签表达，而不是混入工作流阶段。

自动化可以订阅某些状态事件；修改状态方案时，检查相关规则是否仍引用有效的稳定 id。
