# 自动化

自动化把时间或事件触发器与动作关联起来，例如定期整理资料、在状态变化时发起后续工作。配置按工作区保存在 `automations.json`。

## 规则结构

规则由触发器、匹配条件和动作组成。计划任务通过 cron 匹配内部调度节拍；事件规则则筛选指定事件和上下文。

应用事件包括标签增删、标签配置、权限模式、标记和会话状态变化。`SchedulerTick` 是内部调度事件，不是日常直接订阅的业务事件。

历史配置中还可能出现 `PreToolUse`、`PostToolUse`、`PreCompact` 等执行后端 hook 名称。字段能被读取不表示当前执行后端支持该语义：未支持的事件会保留明确的 unsupported 记录，而不会被当成已经可靠触发。尤其不能把普通自动化规则当作工具批准权威；工具阻断应使用现行权限和限制性工具规则。

## 动作

| 类型 | 作用 |
| --- | --- |
| `prompt` | 按提示词启动代理工作，使用正常会话记录和权限路径 |
| `webhook` | 向配置地址发送 HTTP 请求 |
| `script` | 直接运行工作区内脚本 |

脚本通过显式参数执行，不经 shell 拼接，路径必须满足工作区约束；环境按自动化实现限制。它仍以宿主用户权限运行，不是沙箱。Webhook 和脚本可产生外部效果，应按实际目标验证。

## 写可靠的规则

- 精确匹配所需状态、标签或项目，避免一条状态规则处理所有会话。
- 适合代理审阅的工作优先用 prompt；纯机械动作才考虑脚本。
- 设计幂等性，防止重复触发创建重复材料或重复发送。
- 启用前使用测试入口或受控样本验证，检查真实执行历史和跳过原因。

调度重叠或受限的触发可能被跳过并记录，不代表规则丢失。关闭规则可停止后续触发而保留配置和历史。工具、模型或外部服务在未知效果状态中断时，不应假定调度器会安全自动重试。

无人值守会话仍受所选权限模式约束，询问或凭据请求可能等待用户。Task 还要求显式权限声明，并使用其已有预算与范围调度规则。
